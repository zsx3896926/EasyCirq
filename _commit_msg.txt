fix(cli): an unknown command says which word and what to do, in the customer's language

The last English, guidance-free failure path: `easycirq frobnicate` printed
`unknown command "frobnicate" for "easycirq"`, and cobra's suggestion machinery
still answered in English.

Two things had to change:

- the parent-command patch now visits the ROOT itself; it used to start at the
  children, so a misspelled top-level command never reached it
- Args is set alongside RunE, because cobra validates positional args before RunE
  and its default is the English message

    easycirq frobnicate
    没有这个命令："frobnicate"（属于 "easycirq"）
    下一步：运行 `easycirq --help` 看有哪些命令；不知道从哪开始就运行 `easycirq setup`

The two Go tests that pinned the English phrase now pin the contract instead: the
output must name the word and give a next step. A Python test asserts the English
string cannot come back.

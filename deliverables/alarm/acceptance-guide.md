# 打样回来后怎么做（验收指引）

> 目标第四幕：客户拿到板子，回答三件事——焊好没有、通电没有、功能验没验。
> 这份指引给不碰 EDA 的人用。

## 三步

### 1. 填一份实测记录

把下面内容存成 `.easycirq/acceptance.json`（或任意路径，用 `--file` 指过去）。
**三行结果都必须带证据**，证据可以是照片文件名、万用表读数、现象描述。

```json
{
  "schema": "easycirq-acceptance/v1",
  "project": "KPI-S5-Verify",
  "board": "alarm-r1",
  "checks": [
    { "id": "solder",   "title": "焊接", "result": "pass",
      "evidence": "照片 IMG_0001.jpg：5 个器件无虚焊、无连锡",
      "by": "张三" },
    { "id": "power",    "title": "上电", "result": "pass",
      "evidence": "5V 输入实测 5.02V，3.3V 轨 3.29V",
      "by": "张三" },
    { "id": "function", "title": "功能", "result": "pass",
      "evidence": "加热到 58℃ 蜂鸣器响，降到 55℃ 停（回差 3℃）",
      "by": "张三" }
  ]
}
```

### 2. 跑一条命令

```bash
easycirq acceptance
```

### 3. 看卡

```
✅ 这块板可以交付使用

工程 KPI-S5-Verify  板号 alarm-r1

  ✓ 焊接       照片 IMG_0001.jpg：5 个器件无虚焊、无连锡
  ✓ 上电       5V 输入实测 5.02V，3.3V 轨 3.29V
  ✓ 功能       加热到 58℃ 蜂鸣器响，降到 55℃ 停（回差 3℃）

下一步：把这张卡和实测记录一起归档；有问题照上面的证据追溯
```

## 三种结果，不要混

| 你写的 | 卡会说什么 | 意思 |
|---|---|---|
| 三项 `pass` + 有证据 | ✅ 这块板可以交付使用 | 三项都测过且都有证据 |
| 写了 `pass` 但证据栏空的 | ⏳ 还差实测证据 | **写了通过但没有实测证据——不算通过** |
| 任一项 `fail` | ❌ 这块板还不能算可用 | 有实测失败项 |
| 少填某一项 | ⏳ 还差实测证据（点名缺哪项） | 缺项不算默认通过 |

**关键规则：`pass` 必须带证据。** 只写「通过」两个字，工具会判成"未知"，
不会给你绿灯——这是刻意的。

## 一个示例（假数据，仅为演示格式）

```bash
# 用示例数据跑一次，看卡长什么样
easycirq acceptance --file <示例文件>
```

示例记录在 `deliverables/alarm/acceptance.example.json`，里面的测量值**是编的**，
只用来演示格式。真实验收必须填你自己的读数。

## 常见问题

**问：我没有照片怎么办？**
答：证据不一定是照片。万用表读数、示波器截图、甚至"蜂鸣器在 58℃ 响"这样的
现象描述都算。关键是有具体内容，不是空白。

**问：功能测不出来怎么办？**
答：如实写 `fail` 或 `unknown`。写 `fail` 会让卡变红，但那比写个假的 `pass` 诚实——
假 `pass` 会让这块板带着未知缺陷交付。

**问：卡红了还能改吗？**
答：修好重新填记录再跑一次即可。每次运行都会重新判定。

## 这一环为什么必须由人做

焊接、上电、功能三件事**只有实物能回答**。工具能做的只有：验证记录完整、
把「有证据的通过」和「没证据的通过」分开、给出下一步。

它不能替你测。

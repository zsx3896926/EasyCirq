# 受控实验预注册与记录（Agent 填写，用户不填）

> 用途：在动手前把目标、护栏、基线、单因子、响应、停止、有效性与采用规则写死，防止事后改判据。
> 使用范围：K0 不建实验；K1 只做一个观察；K2 才启用完整预注册、基线冻结与采用决定。
> 纪律：没有 bench 不写 verified；没有分布/相关性不做蒙特卡洛；E3、SPICE、bench、batch 分开写。
## 1. 实验身份与目标

| 字段 | 值 |
|---|---|
| 实验 ID / 问题 | EXP-（项目）-（序号）；一句话说明要回答的工程问题 |
| 目标量 target | 可观察量 + 阈值 + 单位 + 条件；例：10 µs 内建立残差 ≤0.5 LSB |
| 护栏 guardrails | 不得越过的范围/安全/功能/采样率/温升条件；逐条写可观察判据 |
| 不回答什么 | 明确本实验不能证明的总精度、EMC、寿命、批量一致性 |
## 2. 基线与版本冻结（baseline）
| 字段 | 值 |
|---|---|
| 基线工件 | path；JSON/CSV/网表/固件/布局的准确路径 |
| 工件 ID / schema | 内容标识与版本；不接受“最新版” |
| 规范化与哈希 | 例：payload 取 `model` 与 `recompute_cases` 两键；`json.dumps(payload, sort_keys=True, separators=(',', ':'), ensure_ascii=False).encode('utf-8')` 后 SHA-256；写明 payload 范围，模型定义变更必须使基线失效 |
| 冻结日期与环境 | 日期、工具版本、参数集、温度、样机/板号 |
| 变更规则 | 基线任一字段变化即新基线 ID；旧结果标 stale，不得拼接 |
## 3. 单因子与水平
| 字段 | 值 |
|---|---|
| 唯一因子 factor | 只允许一个自变量；例：t_ACQ（µs） |
| 水平 levels | 至少 3 个，含边界与预期工作点；例：2/5/10/20/50 µs |
| 对照 controls | 同板、同通道、同输入阶跃、同温度、同基准、同固件、同探头接法 |
| 随机化/分块 | 重复顺序、通道顺序、预热/漂移处理；不能随机时写理由 |
## 4. 响应与测量
| 字段 | 值 |
|---|---|
| 主响应 response | 码值差/残差 LSB/时间/温升；写计算公式与采样点 |
| 次响应 | 重复性、超调、恢复时间、异常码；不得替代主响应 |
| 测量不确定度 | 源/表/探头/夹具的不确定度与负载效应；未知写待查 |
| 数据量 | 每水平重复次数、有效样本规则、剔除规则（预注册） |
## 5. 停止（stop）、有效性与排除
- 停止：超量程、过温、冒烟/异味、保护动作、探头负载改变电路、基线不一致；任一出现即停并记录现场。
- 有效性：源/表在校准有效期；温度稳定在声明窗口；对照未变；数据完整；排除规则在采数前已写。
- 排除：只按预注册规则剔除；不得因结果不符合预期而改判据、改水平或删点。
- 失败处理：保留失败数据与现场；区分“假设错”“模型错”“装配错”“测量错”，不把失败改写成通过。
## 6. 结论阶梯与采用决定
| 阶梯 | 允许结论 | 禁止写法 |
|---|---|---|
| E3 离线 | 模型/手算给出趋势与预测 | “已验证”“已满足” |
| SPICE | 指定模型/版本/激励下的仿真结果 | 当实测；无模型版本 |
| bench | 单板/单温度/单样品实测 | 批量保证、全温区保证 |
| batch | 多板/多批/温循/统计 | 用一块板外推批次 |
- 采用决定 adoption：adopt / adopt-with-conditions / retain-baseline / reject / cannot_conclude。
- adopt 必须同时满足 target、guardrails、validity，并写明适用版本、温度、样机数与剩余未知。
- 只有 statistical_pass 时标统计口径；没有分布/相关性不做蒙特卡洛；没有 bench 不写 verified。
## 7. 记录与签名
| 字段 | 值 |
|---|---|
| 原始数据 | path；不可覆盖；含时间戳、仪器、量程、探头 |
| 分析脚本/版本 | path + 版本；输入哈希；不做未记录的后处理 |
| 结论与限制 | 一句话结论 + 不能证明清单 |
| owner / 日期 | Agent 记录；用户只确认目标与采用偏好 |

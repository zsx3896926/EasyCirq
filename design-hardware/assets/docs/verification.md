# 实物验证记录（交付前 / G6）

> 模板：每个板版本、每轮测试各存一份。状态只用 `PASS / FAIL / NOT RUN / BLOCKED`；没执行就是 `NOT RUN`，缺仪器/环境/授权就是 `BLOCKED`，不能默认通过。这里的 `PASS/FAIL` 是单项测试结论，不替代 G0–G6 的 `PASS / PASS_WITH_WAIVER / BLOCKED / UNSUPPORTED`。制造包见 [manufacturing-package.md](manufacturing-package.md)，工艺档案见 [manufacturing-profile.md](../manufacturing-profile.md)，门禁定义见 [design-gates.md](../../references/design-gates.md)。

## 1. 记录头

| 字段 | 记录内容 |
|---|---|
| 板名/版本 | `<project> / <rev>`，与 BOM、Gerber、CPL 的 manifest 版本一致 |
| 工程与产物 | `.epro2` 路径 + sha256；Gerber/BOM/CPL 的 manifest 版本与哈希 |
| 装配方式 | SMT / 手焊 / 混装；本批板数与 DNP 行 |

| 环境 | 室温、湿度、气流；NTC 附近是否有热源 |

| 测试人/复核人 | 姓名与日期；复核人不能与测试人相同 |
| 证据目录 | 本轮照片、日志、测量 CSV 的相对路径 |

## 3. 上电检查（限流）

1. 断电测 `+5V`–`GND` 阻抗并记录；阻抗异常先查短路，不上电。
2. 限流电源设标称电压与保守限流（按设计填写，例如 5.0 V / 100 mA），**不要**首次就用 USB 直插。
3. 上电只看电流与温度；超限、发热、异味立即断电，保留现场并记录。
4. 电流稳定后测 `+5V`、`VREF`、`NODE`，记录到 V5。
5. 每次只改一个变量（电压、负载、温度），改完重测对应项。
6. 证据写文件路径与 sha256；口头“正常”不算证据。

## 4. 边界与失效

| 场景 | 期望行为（设计定义） | 本项目记录 | 状态 |
|---|---|---|---|
| NTC 开路 | 按设计：报警或进入安全态；必须能从输出区分 | 待实测 | `NOT RUN` |
| NTC 短路 | 已知限制：NTC 被短接后分压点不再随温度变化（固定电平），本项目**报警不触发、无故障指示**；“不报警”不能证明传感器正常 | 需人工测点或增加自检；交付说明必须写明 | `NOT RUN` |
| 电源反接 | 有 TVS/二极管时钳位且后级安全；无保护时明确告知用户 | 按实际器件与实测填写 | `NOT RUN` |
| 欠压/掉电 | 恢复后状态确定，无误报警/锁死 | 待实测 | `NOT RUN` |
| 重复插拔 | 连接器与供电稳定 | 待实测 | `NOT RUN` |
| 电位器调至两端 | 阈值不越界到不可恢复状态；报警行为仍可解释 | 待实测 | `NOT RUN` |
| 输出短路（LED/蜂鸣器侧） | 驱动器件不超额定、不损坏 | 待实测 | `NOT RUN` |

已知限制不是 `PASS`：它表示设计上接受的风险，必须进入交付说明和后续改版清单。上表该项仍要实测并记录现象，状态按实际结果填。

## 5. 已知限制（随交付说明）

按项目实际情况保留或删除，不能因为“模板里有”就照抄：

- NTC 短路不报警，也不产生可听/可见故障提示；只能靠人工测点或额外自检电路发现。
- 无显示：阈值只能靠外部温度计/万用表标定，用户无法现场读数。
- 电位器公差、机械振动与长期漂移会让阈值偏移；未做长期漂移测试。
- 纯模拟板无固件、无开机自检；上电即工作，无法软件确认传感器状态。
- 手焊件（如直插电位器、蜂鸣器）的焊接质量取决于工艺，未做批量一致性验证。
- 蜂鸣器声压未在标准声学环境测量；实际响度受外壳/开孔影响。
- 未做高低温循环、湿热、跌落与 EMC 测试；环境适应性结论只覆盖实测条件。

## 6. 变更后复测

任何变更都要先判断影响面，再决定复测项；不能只重跑 DRC 就交付。

| 变更 | 必复测 |
|---|---|
| 换 NTC、分压电阻、电位器或比较器 | V5、V6、V8、V9，并重核阈值计算 |
| 换蜂鸣器、LED 或驱动 MOS | V4、V7，并重核驱动电流/额定 |
| 换电源、TVS、连接器 | V3、V4、V10、V11、V12 |
| 改 PCB 布局（NTC 位置、热源、开槽） | V6、V13，并补热设计记录 |
| 换封装或替代料 | V2、V5、V6；更新 BOM/CPL 与制造包哈希 |
| 重导 Gerber/BOM/CPL | G6 全部重跑，更新 manifest 与 `.epro2` |
| 任何原理图变更 | G2 网表/DRC 重跑，再按影响面复测 V1–V13 |

## 7. 状态、证据与报告

- `PASS`：实测满足判定标准，有可追溯证据（路径 + sha256 + 时间）。
- `FAIL`：实测不满足；记录现场、影响与下一步，不带病交付。
- `NOT RUN`：未执行；交付说明必须列出。
- `BLOCKED`：缺仪器、环境、权限或安全条件，写清缺什么。
- 证据类型：照片/视频、万用表或电源读数、温度-状态记录、声级计读数、串口/日志（有固件时）。
- 报告同时写清：实际验证的板版本、装配方式、仪器与环境；未打样/未贴片/未实测项不得省略。

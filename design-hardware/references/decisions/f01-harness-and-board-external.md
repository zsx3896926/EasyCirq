# 整机线束、连接器与板外接口

> 一句话用途：把“每块板单独能工作”推进到“按真实线束装成整机仍能工作”，只补整机线束包、连接器受控字段、逐线记录与防误接矩阵；证据等级 E3，不能替代连接器原厂图纸、压接与拉脱实测、整机装配和 EMC。

## 目录

1 触发条件；2 输入；3 Agent 可独立完成的判断；4 必须停下的条件；5 决策规则与表；6 改变哪个工程决定；7 完整案例；8 证据与验证方式；9 与现有资产分工；10 来源、未知与重评触发

## 1. 触发条件

**触发：** 产品由两块及以上板、面板、传感器或执行器组成；需要线束、排线、端子台或板外连接器；整机要装壳、走线、维护或现场更换；同一块板要接不同外部件。

**不触发/跳过：** 单板、无板外连接、只做板级测试；接口只在同一 PCB 内；线束尚未定义且没有外部件清单。跳过要写理由与有效期，不能把“暂不做线束”写成“无需线束”。

**深度：** D0 只有一对板内排针且不可插错，登记连接器与版本即可；D1 单束、单连接器体系、无屏蔽/大电流，写包版本、连接器受控字段与逐线记录；D2 多板、多束、含电源/屏蔽/热插拔/现场维护，要求完整连接图、线束 BOM、防误接矩阵、装配说明与整机验证计划。

## 2. 输入

- **Agent 可自己读：** 原理图网表、板框与连接器位号、现有连接表、BOM、外壳开孔图、`manufacturing-routes.md` 的线束连接表字段与 `module-integration.md` 的连接器契约。
- **必须问用户：** 整机由哪些板/外部件组成、装配与维护方式、线束长度与走向、现场可插拔次数、谁做压接与测试、订单标识与追溯方式。
- **缺失即停：** 板端/线束端视角、连接器完整 MPN 或配对关系、线束包版本与板/壳版本、逐线测试判据中任一项缺失；缺一项只能写 `unknown`/`待查`，不得声称整机可装。

## 3. Agent 可独立完成的判断

- 包完整性：版本绑定、连接器受控字段、逐线记录、防误接矩阵四组是否都能逐项核对，而不是只有名字。
- 引用一致性：每条线的 `board`/`harness` 引用是否落在正确的一侧，配对关系是否互指，矩阵是否覆盖所有非配对连接器。
- 状态语言：`pass` 是否有证据、`NOT RUN`/`待查` 是否被误写成通过、连接器 `approved` 是否仍有额定字段待查。

## 4. 必须停下的条件

- 连接器额定电流/电压、线规范围、屏蔽方式、配对端子/壳体或压接工具任一待查，却要写 `approved`/`released`。
- 同一键位/同一针数的两个连接器没有防误接结论，或矩阵把 `distinct` 当万能理由。
- 逐线 `pass` 没有证据，或把脚本 `exit 0` 当成整机已通过。
- 线束包版本与板版本/外壳版本未绑定，或连接器图纸视角（板端、线束端、装配后）未注明。

## 5. 决策规则与表

本工作流只补现有表没有的层：`manufacturing-routes.md` 的线束连接表给网络/线规/长度/屏蔽，`module-integration.md` 的连接器契约给视角/脚序/接触面；本节补版本绑定、受控字段、逐线记录与防误接，不复制这两张表。

| 子项 | 规则 | 机器可检字段 | 不足时 |
|---|---|---|---|
| F1 整机连接图 | 每块板、每个板外件、每条线束各一个节点；连接器是图的边，不是注释 | `connectors[].side/mate`、`wires[].board/harness` | 缺节点即 `blocking` |
| F2 线束定义 | 每线一行：网络、两端脚号、线规、长度、屏蔽、测试与标签 | `wires[]` 的 12 个字段 | 缺字段即非法输入 |
| F3 连接器体系 | 板端与配对端同一记录集；MPN、配对壳体/端子、压接工具、额定、键位、锁扣成组 | `connectors[]` 的受控字段 | 待查记 `unknown`；批准态待查即 `blocking` |
| F4 线缆影响 | 线规按电流/压降选；屏蔽、双绞、弯曲半径进入记录，不只写在备注 | `gauge`、`shielding`、`bend_radius_mm` | 待查记 `unknown`，不填猜测值 |
| F5 防误接 | 非配对连接器两两有结论；同键位不能只靠丝印区分 | `misconnection_matrix[]` | 缺行或同键位未 blocked 即 `blocking` |
| F6 装配说明 | 插拔顺序、锁扣方向、应力释放、标签位置与维护入口写进装配图 | `lock`、`note`、逐线 `label` | 缺一项写 `NOT RUN` |

**规则：**

1. 包、板、外壳三个版本必须同时出现并在 `binding` 中互指；任一未定，整包只能是计划态。
2. 连接器受控字段按“原厂额定 + 降额 + 线规 + 屏蔽”成组记录；任一缺失只能 `unknown`，不能按同系列推值。
3. 逐线通断、拉脱、锁扣、标签、弯折半径分开记录；一个 `pass` 只覆盖它自己那一项。
4. 防误接矩阵必须覆盖所有非配对组合；配对关系互指，矩阵不替配对关系背锅。
5. 屏蔽/双绞的电气理由沿用接口文档（如 IF-S03 §4–§4.5，登记范围，本轮未重开），本工作流只记录是否落实。
6. 脚本输出 `exit 0` 只表示包结构自洽；不得据此写“线束已验证”或“整机可装配”。

## 6. 改变哪个工程决定

- 从“板级测试通过即可交付”改为“整机按真实线束、真实连接器、真实装配顺序再验一次”；会改变连接器选型、线束 BOM、装配工时、维护方式与整机测试计划。
- 连接器额定/降额未核时，选型决定保持 `draft`；不能先用低价连接器锁 BOM 再补额定。

## 7. 完整案例

`design-hardware/references/decisions/cases/r4-case-f01-multiboard-harness.md`（R4-P4，E3 / OFFLINE_PLANNING / hardware_execution NOT RUN）。

- 决定：三块板按一个整机线束包管理，接口行仍放 E 线，F 只补版本绑定、连接器受控字段、逐线记录与防误接矩阵。
- 代价：每个连接器要补原厂图纸/额定/配对端子/压接工具，线束 BOM 与整机 BOM 分开维护；交付前多一轮整机走线与装配检查。
- 下一个检查或待查：连接器 MPN、额定与降额、配对端子/壳体、压接工具、逐线通断/拉脱/锁扣/标签/弯折半径，均待查或 NOT RUN。

## 8. 证据与验证方式

- 本轮为离线规划：只读仓库内连接表、连接器契约与来源登记；未重开连接器原厂正文，未做压接、拉脱、通断、弯曲或整机装配。
- `harness_check.py` 检查版本绑定、连接器受控字段、逐线记录与防误接矩阵；所有输出固定 `board_verified:false`、`execution:OFFLINE_PLANNING`、`hardware_execution:NOT RUN`，并列出 `not_checked`。脚本通过不等于线束已制造或整机已验收。

- IF-S03：SLLA070D，登记查阅范围为第 1–2 页目录、第 3 页 §2、第 8 页 §2.1.8、第 9–12 页 §2.2 与 Table 2、第 12–13 页 §3、第 13–18 页 §4、第 18–20 页 §4.5、第 22–23 页 §6 与 Table 4；本轮未重开原厂正文。只用于“屏蔽/双绞/接地需要在线束层落实”的边界，不用于连接器额定或线规数值。

# 校准、参数存储与设备身份

> 用途：从产品记录和误差预算反推“是否需要校准、记录什么、何时失效”，把校准值当作带身份、版本、槽位和有效期的数据。证据等级 E3（离线方法整理；本轮未重开原厂正文、未校准、未实测）。不能替代校准源不确定度评定、存储耐久性测试、产线工装验证与整机实测。

## 目录
1 触发条件；2 输入；3 Agent 可独立完成的判断；4 必须停下的条件；5 决策规则与表；6 改变哪个工程决定；7 完整案例；8 证据与验证方式；9 与现有资产的分工；10 来源、未知与重评触发。

## 1. 触发条件
**触发：** 模拟测量/输出且验收依赖绝对精度；多通道、多量程或多变体；参数随板保存；现场可换板/换探头/返修；固件升级后要保留标定；需要设备身份或服务追溯。**不触发/跳过：** 纯数字或比较器/开关量；验收只要求重复性；一次性实验板且明确不迁移、不返修；跳过要写理由与有效期。**深度：** D0 无模拟参数/存储/身份，只在项目记录写“不适用”；D1 单通道单量程且仅工厂校准，写记录头、状态、单槽 CRC、安全态；D2 多通道/多量程、现场服务、安全相关、精度承诺或多板版，必须写完整 schema、身份、A/B 槽、状态机、分区与重校触发。

## 2. 输入
- **Agent 能自己读：** 项目验收表、误差预算、ADC 建立计算、固件参数表、变体表、`source-register.md` 登记范围；引用写 path:start-end。
- **必须问用户：** 使用温区与校准周期承诺；现场能否返厂或只换板；谁有权进入服务模式；序列号/批次编码规则；有无校准工装与标准源。
- **缺失即停：** 标准源/表不确定度未知；存储介质与掉电原子性未知；无效参数安全输出未定义；身份编码未定义；安全/贸易计量无外部合规要求。缺任一项只能停在 `uncalibrated` 或 `NOT RUN`。

## 3. Agent 可独立完成的判断
- **先判是否需要校准（H1/H2）。** 用未校准最坏误差对照验收项：能过就不建校准；不能过再定位主导项。校准只能消掉当前条件下可重复的常数，不能消温漂、噪声、建立、漏电、INL 与长期漂移；该边界不在本文重写，以 `design-hardware/references/engineering-deepdives/topics/c1-sensor-to-adc-error-chain.md:179-191` 与 `design-hardware/references/design-cards/analog/a05-vref.md:168-177` 为准。量程取 0/50/100% 点，温度取角点；顺序为零点→增益→线性/温度→重复性。标准源不确定度应小于残余预算的 1/3（E3 工程规则，具体值按校准规范核）。
- **定记录结构与有效性（H3/H4）。** magic、schema_version、length、身份、每通道 offset/gain/range/unit、A/B 槽、sequence、CRC32、status、valid；写清字节序、规范化方法和掉电切换顺序。无效时不得静默沿用旧值，必须给标称值/保持/禁用中的一种并置标志与告警。
- **定身份与分区（H5/H6）。** 序列号绑定板卡；工厂锁定区、现场配置区、服务校准模式分开；恢复出厂保留身份与 magic，不保留来路不明的现场参数。

## 4. 必须停下的条件
- 没有标准源/表不确定度、校准温度或校准点记录，却要写 `status=valid`；或没有序列号/批次编码规则，却要写“逐板校准/可追溯”。
- 存储耐久、掉电原子性或 A/B 槽切换未验证，却要声称“掉电不丢校准”。
- 参数无效可能导致输出超范围、联锁失效或安全边界被突破，而安全态未定义/未验证。
- 把模型一致、脚本通过或模板存在当成校准已执行；温度/现场校准缺设备时只能写 NOT RUN。

## 5. 决策规则与表
### 5.1 H1/H2：是否需要校准、校准点与参考源
| 误差结构（从记录反推） | 判定 | 记录最低要求 |
|---|---|---|
| 未校准最坏误差 ≤ 验收项且留有余量 | 不校准 | 写明计算依据与适用条件；不建空记录 |
| 静态 offset/gain 占主导 | 两点校准（零点+增益） | 4/12/20 mA 或 0/50/100% FS、源 ID、温度、残余项 |
| 温漂占主导且承诺全温区 | 多点温度校准或改器件 | −20/25/60 °C 点、插值/拟合、滞回与残差 |
| INL、噪声、建立、漏电占主导，或安全/贸易计量 | 先改电路或做外部合规校准；校准不能替代设计 | 指向建立/噪声计算；机构、证书、有效期；自校准不能替代 |

### 5.2 H2：校准流程
| 步骤 | 最低写法 | 不满足时 |
|---|---|---|
| 预热、夹具与参考源 | 稳定时间、接触电阻、通道切换；源/表型号、量程、不确定度、有效期、`source_id` | 无记录写 NOT RUN；不确定度未知不得判 valid |
| 采集与判定 | 每点原始码、offset/gain、残差、重复性；残差 ≤ 分配预算，重复性 ≤ 1/3 残差 | 超差回到电路/器件，不靠软件硬掰 |

### 5.3 H3：记录字段
| 字段 | 语义 | 约束 |
|---|---|---|
| `record_id` / `magic` / `schema_version` / `length` | 记录编号、记录标识、格式版本、payload 字节数 | payload 不含 record_id/length/slots/status/valid/valid_until/invalid_reason；record_id 用 `CAL-项目-序号`（R4-P3 示例为 `CAL-P3-001`）；固定 `CALREC`；版本或长度不符即 invalid |
| `model` / `hw_rev` / `variant` / `serial` | 设备身份 | 任一不匹配即 invalid；不得跨板复制 |
| `cal_date` / `cal_temp_c` / `source_id` | 校准日期、温度、标准源身份 | valid 时不得为“待查” |
| `channels[].offset/gain/range/unit` | 每通道偏移、增益、量程、单位 | 通道号唯一；单位与上位机一致 |
| `slots.A/B.sequence` / `crc32` | 提交序号与 payload CRC32 | 新序号递增；CRC 不匹配即 invalid |
| `status` / `valid` / `valid_until` | 状态机、快速判定与有效期 | 只允许四种状态；valid 必须为 true 才可信；valid/expired 的 valid_until 必须是真实 `YYYY-MM-DD`，缺失或非法不得判 valid |

### 5.4 H4：状态机与无效参数安全态
| 状态 | 含义 | 允许迁移 | 设备行为 |
|---|---|---|---|
| `uncalibrated` | 从未校准或参数被擦除 | → valid（校准+回读通过）；→ invalid | 用标称值并置未校准标志；禁止声称精度 |
| `valid` | 身份、CRC、槽位、有效期均通过 | → expired（到期）；→ invalid（校验/身份失败） | 使用记录值；周期自检 |
| `expired` | 数据完整但超过有效期 | → valid（重校）；→ invalid | 保持可用但置过期告警；按产品规则降级或禁用 |
| `invalid` | CRC/身份/槽位/范围任一失败 | → uncalibrated（擦除重校）；→ valid（服务重校） | 禁止使用旧值；回标称值/安全保持/禁用并告警 |

安全态必须逐产品定义：测量节点可“标称值+告警”，执行器节点应“输出禁用/安全保持”；不得把“继续用最后一次值”写成默认安全态。

### 5.5 H5/H6：身份、分区与恢复出厂
- **工厂锁定区：** magic、schema、model、hw_rev、variant、serial、校准来源；产线工装/一次性写，恢复出厂保留。**校准区：** 每通道 offset/gain/range/unit、cal_date、cal_temp、source_id、A/B 槽；仅服务校准模式可写，恢复出厂时保留或清除必须写明。
- **现场配置区与服务模式：** 地址、波特率、单位、显示偏好由用户清除并回默认；服务模式要有解锁、超时、审计、退出后 CRC/身份复核。**重校触发：** 到期；身份/板版不符；通道或前端维修；固件改变参数解释；CRC/槽位异常；自检超差；超出规定温湿度；客户精度投诉。恢复出厂不得清掉序列号、model、hw_rev。

## 6. 改变哪个工程决定
校准决定会改变存储介质与容量（内部 Flash/EEPROM/FRAM）、固件启动校验、产线工装与测试节拍、BOM（基准/分流/存储）、外壳标签与序列号、服务流程与备件策略。是否校准必须在选基准和分流之前回答。

## 7. 完整案例
[R4-CASE-H01：两路 4–20 mA 测量节点的校准记录](cases/r4-case-h01-measurement-node-calibration.md)（R4-P3，E3 / OFFLINE_PLANNING / hardware_execution NOT RUN）。
- 决定：保留两点 4/20 mA 方向，但示例记录 `record_id=CAL-P3-001`、`status=uncalibrated`；补齐身份、schema、A/B 槽、CRC、valid_until 与安全态后才允许升级为 valid。
- 代价：增加存储与产线工装、序列号和服务流程；校准点与温度数据未取得前不能承诺精度。
- 下一个检查或待查：标准源不确定度、恒温箱、存储耐久、无效参数安全态验证；offset/gain/range 全部待查。

## 8. 证据与验证方式
本轮为 E3 离线规划：未重开原厂正文、未运行 EDA、未校准、未实测。`scripts/decision_record_check.py calibration <record>` 只检查结构/状态/CRC 自洽，不证明参数正确或硬件已校准；valid/expired 的 valid_until 必须是真实 `YYYY-MM-DD`（`valid_without_valid_until` / `invalid_valid_until`）；输出固定 `board_verified:false`、`execution:OFFLINE_PLANNING`、`hardware_execution:NOT RUN`。

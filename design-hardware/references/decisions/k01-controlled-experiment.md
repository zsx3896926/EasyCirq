# 受控实验预注册、基线与采用决定
> 用途：在动手前冻结目标、护栏、基线、单因子、响应、停止、有效性与采用规则，防止事后改判据。证据等级 E3（离线方法整理；本轮未做 SPICE/台架/批量）。不能替代实际 ADC 手册、台架数据与批量统计。
## 目录
1 触发条件；2 输入；3 Agent 可独立完成的判断；4 必须停下的条件；5 决策规则与表；6 改变哪个工程决定；7 完整案例；8 证据与验证方式；9 与现有资产的分工；10 来源、未知与重评触发。
## 1. 触发条件
| 深度 | 使用条件 | 产物 |
|---|---|---|
| K0/D0 不建实验 | 判据可由既有保证值或标准算例直接回答；结论不改变设计 | 记录“不适用”及理由 |
| K1/D1 单次观察 | 一个响应、一个条件、无采用决定 | 观察记录 + 条件 + 限制 |
| K2/D2 受控实验 | 采用/淘汰取决于模型外推、器件未定型、温度/批次/通道差异 | 预注册 + 基线冻结 + 采用决定 |
- 触发：模型一致但无台架；两个候选网络/器件无法用纸面区分；需要最小 t_ACQ、最小 Cext、最佳校准点；结论会冻结 SCH/BOM/固件。
- 不触发/跳过：只做趋势观察；判据来自已核对的手册保证值；一次性实验且明确不采用。跳过要写理由与有效期。
- 深度不因“跑过脚本”升为 K2；没有目标、护栏、基线与有效性规则时只能停在 K0/K1。
## 2. 输入
- Agent 能自己读：验收表、P02:190-207、`design-hardware/assets/decisions/adc-settle.r4p3.recompute.json`、`design-hardware/assets/decisions/experiment-record.template.md`、`design-hardware/references/simulation-measurement.md:70-83`；引用写 path:start-end。
- 必须问用户：采用判据（保证/统计）、可接受的实验时间与样机数、温度点、是否允许改板、停线/安全边界。
- 缺失即停：目标量或阈值未定义；护栏与停止条件未定义；基线工件无版本/哈希；响应测量不确定度未知；没有 bench 却要 adopt。
## 3. Agent 可独立完成的判断
- 把工程问题写成 target（可观察量 + 阈值 + 条件）与 guardrails（不得越过的功能/安全/采样率/温升）。
- 冻结 baseline artifact：路径、ID、schema、规范化方法、SHA-256、日期、工具/参数/样机；变更即新基线。
- 只允许一个自变量；水平含边界与工作点；对照固定板、通道、输入、温度、基准、固件、探头；预注册 response、重复次数、剔除规则、停止条件与有效性。
- 按 E3/SPICE/bench/batch 阶梯给结论；没有 bench 不写 verified；没有分布/相关性不做蒙特卡洛。
## 4. 必须停下的条件
- 目标、护栏或停止条件在采数后才补；或看到结果后改水平/改判据/删点。
- 基线工件没有版本/哈希，或采数中途换板、换固件、换探头、换温度。
- 响应被平均/滤波掩盖了确定性残差（例如用 8 次平均掩盖建立不足）。
- 只有模型/E3 或 SPICE，却要 adopt；或单板 bench 外推批量/全温区。
- 安全边界（过压/过流/过温/冒烟）未定义却上电。
## 5. 决策规则与表
### 5.1 目标与护栏（K1）
| 字段 | 必填写法 | 不合格写法 |
|---|---|---|
| target | 量 + 阈值 + 单位 + 温度/输入/采样条件；例：10 µs 内残差 ≤0.5 LSB | “效果更好”“基本建立” |
| guardrails | 输入范围、采样率下限、温升、保护动作、不得改动的器件 | 只写“注意安全” |
| 不回答 | 总精度、INL/DNL、EMC、寿命、批量一致性 | 把建立判据当总精度 |
### 5.2 基线冻结（K3）
| 字段 | 要求 |
|---|---|
| artifact | 准确 path；JSON/CSV/网表/固件/布局；不接受“最新版” |
| identity | 工件 ID + schema_version + 参数集；与项目/板版/变体绑定 |
| hash | 规范化后 SHA-256；写明 payload 范围（例：`model` + `recompute_cases`，`sort_keys=True`、紧凑分隔符、`ensure_ascii=False`） |
| environment | 日期、工具版本、温度、样机/板号、探头/夹具 |
| change | 任一字段变化即新基线；旧结果标 stale，不拼接 |
### 5.3 单因子与水平（K2）
| 字段 | 要求 |
|---|---|
| factor | 只一个；例：t_ACQ（µs）；其他量全部锁定 |
| levels | 至少 3 个，含边界与预期工作点；例：2/5/10/20/50 µs |
| controls | 同板、同通道、同输入阶跃、同温度、同基准、同固件、同探头接法 |
| response | 主响应 + 次响应；写公式、采样点、重复次数与不确定度 |
| stop/validity | 超量程/过温/保护/基线不一致即停；源表校准、温度窗口、对照未变才有效 |
### 5.4 验证方式选择（K4）
| 方式 | 能回答 | 不能回答 | 采用门槛 |
|---|---|---|---|
| E3 离线 | 趋势、敏感性与最小水平预测 | 实际建立、串扰、噪声 | 只能 fail/conditional/cannot_conclude，不得 adopt |
| SPICE | 指定模型/版本/激励下的波形 | 电荷注入、PCB 寄生、批次 | 只能 fail/conditional，需 bench，不得 adopt |
| bench | 单板/单温度/单样品实际响应 | 批量、全温区、长期漂移 | 可 adopt-with-conditions |
| batch | 多板/多批/温循/统计 | 未覆盖的工况 | 可 adopt（限声明范围） |
### 5.5 采用决定（K6）
| 决定 | 条件 | 记录 |
|---|---|---|
| adopt | target、guardrails、validity 全满足，且有 bench/batch | 版本、温度、样机数、剩余未知 |
| adopt-with-conditions | 主判据满足但温区/批次/寿命未覆盖 | 条件、owner、到期日 |
| retain-baseline | 新水平未证明优于基线 | 保留原参数与理由 |
| reject | 任一护栏失败或 target 不满足 | 失败现场与复现步骤 |
| cannot_conclude | 只有 E3/SPICE 或缺主导项数据 | NOT RUN 清单与所需证据 |
### 5.6 报告与复评（K5）
权衡报告至少写：target 与实测/模型值、护栏是否守住、基线是否变化、主导不确定度、采用决定与代价。无分布/相关性不做蒙特卡洛；无 bench 不写 verified；单板结果不外推批量。
## 6. 改变哪个工程决定
实验结论会改变 ADC 采样时间/采样率、Cext 与缓冲器、MUX 序列、校准点与工装、固件平均次数、BOM 与测试计划。采用决定必须在冻结 SCH/固件前完成；不能用“平均后看起来稳定”替代建立或串扰结论。
## 7. 完整案例
[R4-CASE-K01：采集时间 t_ACQ 的单变量受控实验预注册](cases/r4-case-k01-acquisition-single-variable.md)（R4-P3，E3 / OFFLINE_PLANNING / hardware_execution NOT RUN）。
- 决定：冻结 `adc-settle.r4p3.recompute.json` 为基线；只变 t_ACQ，水平 2/5/10/20/50 µs；采用最短满足 0.5 LSB 且护栏全过的水平。
- 代价：需要台架、阶跃源、重复测量与温度记录；bench 前只能 cannot_conclude。
- 下一个检查或待查：实际 ADC Csh/Rsw、MUX 串扰、电荷注入、探头负载；全部待查。
## 8. 证据与验证方式
- 本文为 E3：只整理预注册、基线与采用规则；案例的数值来自 P02 既有假设与 `adc-settle.r4p3.recompute.json` 的离线重算，未重开原厂正文、未做 SPICE/台架/批量。
- 验证方式：检查 target/guardrails 是否可观察、基线哈希是否一致、单因子是否唯一、停止/有效性是否预注册、采用决定是否匹配证据阶梯。
- 不能证明：实际建立、串扰、噪声、INL/DNL、基准动态负载、批量一致性；模板存在或脚本通过不等于硬件已验证。

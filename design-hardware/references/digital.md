# 数字系统与接口

## MCU / SoC / FPGA
核对每个电源脚与域、参考/模拟电源、去耦、上电顺序、复位阈值/时序、启动配置、时钟、看门狗、下载与调试。
引脚表同时记录物理脚、复用功能、电平域、方向、上电默认/高阻/strap、外部上下拉。FPGA检查bank供电、I/O标准、专用脚和配置电压；与工具pin约束比对。
检查启动时外围驱动/LED/强上下拉对strap脚的影响；复位或下载状态下输出应处于合理安全状态。
裸芯片与模组的晶振/Flash/天线/稳压可能集成不同，不能将另一型号最小系统照搬。

## 时钟与逻辑电平
晶体按所选器件的负载、ESR、驱动等级、负阻裕量及layout指南配置；近似CL=C1·C2/(C1+C2)+Cstray只作初选，不能忽略寄生/实际启动。
按驱动器VOH/VOL保证值、接收端VIH/VIL和实际负载算噪声余量；“3.3V对3.3V”不自动兼容。
检查掉电容忍、Ioff/注入电流、模拟输入范围、输入钳位、反灌和方向。电阻分压不能替代所有双向/高速电平转换。

## I2C / SPI / UART
I2C考虑总电容、边沿时间、最弱灌电流、已有并联上拉、电压域、时钟拉伸和地址冲突。用各器件保证值和实际总线条件，不固定“4.7k通用”。
SPI考虑模式/片选、上电状态、MISO三态、扇出、走线/连接器和时序预算；UART核对TX/RX角色、流控、实际电平与对端定义。
任何总线都检查关机/部分上电、线缆插拔和连接器镜像。保留板端、线缆端、对端视角，不能靠丝印名猜脚序。

## USB / 以太网 / CAN / RS485
先明确协议版本、角色、速率、PHY/收发器、连接器、拓扑、线缆与供电方式，再读取当前协议/厂商指南。
USB-C分别核对连接器、CC/角色、电源路径和所需PD能力；Type-C接口不自动意味着PD或高速协议。
以太网检查磁性器件/集成接口匹配、电源中心抽头、屏蔽、PHY strap/时钟/参考layout；PoE另核对供电与隔离架构。
CAN/RS485按实际总线拓扑端接，核查共模范围、failsafe、偏置、隔离地与保护；不能每个节点都加同样端接。
时间预算包含器件传播、时钟偏斜、setup/hold、线缆/走线延迟、抖动与容差。信号完整性判断看边沿与传播关系，不只看时钟频率。

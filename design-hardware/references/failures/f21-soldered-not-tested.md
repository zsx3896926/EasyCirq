# F21 焊接完成但未烧录/未功能测试

> **证据等级：** B 官方 SMT 下单说明与验收分层文档支持“贴片完成不等于烧录/功能通过”；本次没有具体订单的交付记录。
> **适用边界：** 只适用于所列拓扑、器件、板版和工况；不得推广成通用规则。
> **关联：** [以原始用途验收](../product-acceptance.md)、[嘉立创业务衔接](../jlc-handoff.md)、[故障定位](../troubleshooting.md)；检查 MF25、MF26、MF27、MF28、MF30；任务场景 S33。

## 现象

收到“已焊好”的板后出现下列一种或多种情况：

- 上电无反应、无启动日志、无法枚举/连接；用户以为硬件坏，实际没有烧录固件。
- 板上有程序但版本/板版不对，外设不工作；或程序能跑但目标功能未测。
- 工厂报告只有 AOI/飞针/电测，没有烧录记录和功能测试记录；用户把“电测通过”当成“功能通过”。
- 同一批板有的能跑、有的不能，差异来自装配变体/DNP/ boot 配置/固件版本。
- 首板“亮灯”被当成整机验收，实际传感器/通信/负载未验证。

## 工况

- 订单：PCB+SMT 还是仅 PCB；SMT 是否包含烧录/测试（按当前服务确认，不能假设）。
- 板版：PCB 版本、装配变体、DNP、器件替代。
- 固件：版本/提交、目标板版、配置、boot 模式、烧录接口/治具。
- 测试：工厂电测/AOI/飞针范围；用户功能测试条件、仪器、负载。
- 交付：板数、包装、标签、测试报告。

## 原因假设

- **H1 未烧录。** SMT 流程默认不包含固件烧录；板子只有空片/出厂程序。成立时烧录接口可识别、烧录后正常。
- **H2 固件/板版不匹配。** 烧了旧版/错板版/错配置的固件；外设引脚/时序/功能不对。成立时读回版本/配置与目标不符。
- **H3 Boot/下载状态错。** BOOT strap、复位、调试口状态不对，芯片不进下载/启动模式；或程序启动即被看门狗复位。成立时测 boot 脚/复位波形可区分。
- **H4 装配变体/DNP 不一致。** 装配变体与固件/测试假设不符；DNP 器件导致功能缺失。成立时对照 BOM/位号/装配图可发现。
- **H5 硬件缺陷未被工厂检查覆盖。** 虚焊/连锡/错料/极性错；AOI/飞针只覆盖部分。成立时目检/通断/电源轨可发现。
- **H6 测试条件错。** 电源限流不足、负载/线缆/夹具不对、测试步骤缺失；板子本身正常。成立时换已知良品/改条件可复现。

## 区分假设的检查

按“先安全、再无损、再侵入”的顺序：

1. **核对订单范围（无损）。** 查当前 SMT 服务是否包含烧录/功能测试；SMT 下单三要素是 BOM、坐标、PCB 选择，官方页面没有把烧录/功能测试列为默认包含项（MFG-S16）。不能凭“工厂说焊好了”推断已烧录。
2. **核对板版/变体（无损）。** 对照 PCB 版本、装配变体、DNP、BOM 位号；确认固件目标板版与实物一致。
3. **目检与电源（低风险）。** 查极性/连锡/错料/虚焊；限流上电测各电源轨、电流、复位；异常先停，不盲目加大限流（MF25、MF26）。
4. **读回固件/启动（无损/低风险）。** 用调试/烧录接口读芯片 ID、固件版本、配置；无响应时查 boot 脚、复位、时钟、供电。
5. **烧录已知良品固件（侵入）。** 用匹配板版的已知良品固件烧录，重跑启动；若恢复，支持 H1/H2；若仍失败，转 H3/H5。
6. **最小功能测试（侵入）。** 先测电源/复位/时钟/下载，再最小 GPIO/通信/传感，最后完整负载；分阶段定位（MF27、MF28）。
7. **原始场景验收（侵入）。** 按用户最初用途测端到端功能，不只“亮灯/串口有输出”；记录板版、固件、装配、测试条件（MF30）。

## 根因证据

- **官方 SMT 流程边界（B）。** 嘉立创《SMT下单流程》（MFG-S16）说明 SMT 需要 BOM、坐标文件、PCB 选择“三点缺一不可”，并给出缺 BOM/坐标时的替代路径；页面没有承诺默认包含固件烧录或功能测试。该页面只支持“SMT 是 PCB 订单上的贴装选项”，不能据此声称任何工厂都不烧录；具体服务范围必须按当前订单确认。
- **验收分层（B）。** 本项目 [product-acceptance.md](../product-acceptance.md) 明确区分：生产/装配检查只证明制造/焊接检查范围；烧录/启动证明指定设备已写入或看到启动证据；端到端功能实测才证明所测版本和条件下原始场景发生。工厂 AOI/飞针/电测不能代替功能测试。
- **业务衔接（B）。** [jlc-handoff.md](../jlc-handoff.md) 明确“制造后不默认结束完整设备任务”：“不从‘贴片完成’推断‘应用功能已通过’”；工厂的 AOI/飞针报告不能代替用户实际场景。
- **合理推断（C）。** 若烧录已知良品固件后功能恢复，则“未烧录/固件不匹配”是可解释根因；若烧录后仍失败，需继续查 boot/硬件/装配。仅凭“没有启动日志”不能判定是硬件坏。
- **仍待验证（D）。** 本案例没有本次作者经手的订单、烧录记录、测试报告或失效板；没有具体固件版本/板版，不能写“某批板一定未烧录”。

## 修复

- **流程/装配变更（主）。** 在制造/交付流程中增加明确的烧录与功能测试工位：烧录文件、目标板版、配置、治具、测试步骤、通过标准、记录表；把“已烧录/已测试”作为交付状态，而不是口头说明。
- **固件变更。** 固定与板版匹配的固件版本/配置；提供可追溯的版本标识；boot/复位/看门狗参数按实际硬件核对。
- **BOM/装配变体变更。** 若不同变体需要不同固件/测试项，用位号/标签/装配变体区分；避免同一批混装。
- **硬件变更。** 若定位到虚焊/错料/极性/电源问题，修 PCB/封装/装配或反馈工厂；不能用固件绕过硬件缺陷。
- **测试工装变更。** 增加测试点/夹具/治具，确保关键电源、复位、下载、通信可测；测试点不能被外壳/连接器遮挡（MF15）。
- **交付变更。** 交付时附板版、固件版本、装配变体、测试记录与未测项；不能只交“已焊好”。

## 复验

未执行。复验条件与通过标准如下：

- 工况：目标板版/装配变体、目标固件版本、额定电源与限流、实际负载/线缆/夹具；首板与小批量分别记录。
- 检查：烧录成功并可读回版本；启动日志/心跳；电源轨/复位/时钟；最小 IO/通信/传感；原始用户场景端到端。
- 通过标准：每块交付板有唯一板版/固件/变体标识；烧录/启动成功；最小功能与原始场景在约定条件下通过；未测项明确列出。
- 还需补：批次一致性、温度/电源边界、长时间运行、故障恢复；修复后重跑原失败板与必要回归。

## 适用边界

- 只适用于 PCB+SMT 交付与首板/小批量验收；纯手焊、开发板、模块成品流程不同。
- SMT 服务是否包含烧录/测试随服务类型、工厂、订单选项变化；不能把本案例当成“所有 SMT 都不烧录”的结论，必须按当前订单确认。
- AOI/飞针/电测只证明其覆盖的制造缺陷，不等于固件/功能/用户场景通过。
- “亮灯/串口有输出”只是启动证据，不等于整机功能、性能、可靠性或认证通过。
- 没有具体订单/固件/板版时，不得写“某批板未烧录”或给出具体测试数值。

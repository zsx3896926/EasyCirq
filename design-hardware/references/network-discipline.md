# 网络纪律与服务阻塞

通过受支持的 EDA 客户端/连接器工作；不猜测或直连私有后端接口，不使用页面 fetch、伪造 UA/TLS 指纹或更换出口绕过拦截。官方公开接口只有在其文档、授权及限流策略明确时才单独接入。

## 发现异常

- 418、明确拦截页或同时间段日志可作为服务受阻证据。空结果、lists undefined、超时本身不能证明限流，也不能证明型号不存在。
- 先读取本地日志与已有快照，不为了诊断再发请求。按时间记录服务、受影响操作和事实；对外分享先移除账号、客户码、出口 IP、工程标识和追踪凭证。
- 本次反馈事件的十分钟来自事件记录及客服转述；TLS 指纹、最初触发源和滚动延长封禁尚未独立确认，不作为通用平台事实。

## 停止与恢复

1. 停止受影响服务的请求；共享出口的所有 Agent 在同一工作记录中登记 `blocked: remote-access`、最后观察时间和负责人，仅一个负责人执行恢复验证。跨机器协作需人工/平台协调；本工具不具备全网感知或流量拦截能力。
2. 默认从最后观察到的相关拦截起保守冷却至少十分钟；可信 Retry-After 更长时遵循更长时间。冷却期不探测、不批量重试。
3. 转做离线计算、已有快照检查与文档。放置已有 UUID、保存和回读也可能联网，不能假设走客户端就安全；不依赖的工作才继续。
4. 到期不等于恢复。仅在授权范围内经受支持客户端做一次受控验证；失败继续退避。超时写入先核对实际状态，不重放整批。
5. 历史器件身份可用于复用，价格、库存、SMT 状态仍须注明查询时间；受阻时写待查，不伪造实时结果。

## 离线辅助审计

```text
python scripts/net_discipline_audit.py scan <project-dir> --json
python scripts/net_discipline_audit.py eda-log --log <local-log> --json
```

两种模式不发请求。扫描使用 Python 静态解析及其他脚本启发式，只提示候选，不是网络沙箱或完整数据流分析；动态 URL、别名、运行时下载和子进程仍可能漏检。`REVIEW` 需审阅，不算通过；无法读文件/日志返回 unknown / exit 2。exit 0 只说明本范围无发现或保守冷却已到期，不能证明联网安全、服务解封或电路正确。日志时间使用本机时区，其他出口请求及日志轮转不在观察范围。

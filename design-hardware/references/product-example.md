# 演练案例：花盆缺水时手机提醒

这是Agent组织工作的示例，不是已验证的电路、真实报价或可直接制造的模板。保留用户“能用”的目标，不固定芯片、阻容值、预算、天数、云服务或外壳尺寸。

## 1. 从一句话到可测目标

用户：“做个花盆缺水时手机提醒的小东西，我不会EDA。”

回复先复述目标并问会改变路线的1–2项：“放室内还是会淋雨？附近能插电，还是必须用电池？”已有答案不再问。手机只在家里查看、离家仍需通知与只亮灯的路线不同，按必要性再补。

| 用户目标 | Agent整理的可验收内容 | 注意 |
|---|---|---|
| 真缺水会提醒 | 实际土质/植株适用的干湿判定、提示延迟、手机收到且识别哪盆 | 拔出探头只测输入异常/阈值链，不代替真实土壤校准 |
| 不重复轰炸 | 持续干燥提醒策略、恢复阈值/滞回、浇水后重置 | 掉电/断网恢复与通知重试要避免重复或漏报 |
| 插电/电池使用 | 实际供电条件、续航目标、低电/断电表现 | 目标数值由用途提出或明确暂定，不当成已实现 |
| 放到花盆旁 | 安装、气候/水、接线、探头涂层与可更换性 | 防溅不等于IP认证，电容式探头也需长期验证 |

## 2. 推荐最短验证路线

需要先验证通知链时，可用适用的立创开发板与传感模块跑通；目标明确且已有可靠参考时可直接定制PCB。用户要定制板就保留该交付，原型只是中间验证。比较器件、固件和结构参考的真实版本/授权与已有材料。

先用可获得资料判断探头类型、供电、模拟输出范围/源阻抗、ADC与校准；需要时用适用AFE，不能只因“土壤湿度模块”就直接任意ADC。传感器断电后还需查信号线反灌和上电稳定时间。

## 3. 电源先证明能工作，再估续航

两节AA→LDO→3.3V不能作为一般有效稳压路线：输入低于输出加压差时LDO无法维持3.3V，电池放电后更不满足。根据整个电压曲线、电池内阻、低温与无线峰值选择合适的升压/升降压、不同电池组合或其他适配架构；不要只把usable_fraction调低掩盖供电失败。

若采用电池，分别建立测量/稳定、联网/发送/确认、重试、睡眠等互斥整板状态，先换算到电池输入侧再运行续航辅助。使用典型和不利条件，实际睡眠与发射状态测量后重算；完整续航仍待长期验证。

## 4. 设计与并行准备

建立主控/传感器/电源/调试与接口模块，查实际器件库/脚表，完成原理图并实际回读与看图。PCB安排电源回路、传感器/探头位置、天线、连接器、测试点与壳体；保持传感电极和禁铜/禁布的真实意图，不用通用大地铜覆盖电极。

同步维护物理脚↔GPIO/ADC↔网络↔固件配置；接口稳定后并行写最小驱动、阈值状态机、联网与配置。先在适用原型上验证能做的链路，迁移到定制板后仍重验。

## 5. 购料、制造和使用链

按实际数量与装配变体准备商城购料和SMT文件，实时渠道独立核对。缺报价不填0；更换候选须回写源工程并检查兼容性。板、电池/探头、外壳、线束、烧录/测试与装配分别列是否包含，不能把“焊好板”说成“收到即用”。

制造/结构服务按当前真实能力准备文件，订单/支付沿用户授权与宿主规则办理，不自行增加逐阶段确认。凭据在适用本地配置/配网流程输入，不提交公共仓库。

## 6. 实物失败时回到具体链路

先适用的目检、断电测量与受控供电，再关键电源/启动/烧录、逐模块及真实花盆→手机端到端验收。实际干湿试验之外覆盖探头开路、低电、断网、恢复、误报与重复通知；必要条件与仪器不足则保持待测。

例如“空气中会提醒、真实土里不准”回到探头/标定与需求；“串口说发送成功但手机没收到”查服务与送达；“联网时重启”查供电波形/日志和状态；“装壳后信号差”查实际天线环境。一次只改可定位的一部分，再复验受影响目标。

交付用三句话：真实完成了什么、怎样使用、还没验证什么。附可编辑工程、程序/构建、对应BOM/结构/制造版本、使用说明与证据。没有实物时只能交付准备成果和接续条件。

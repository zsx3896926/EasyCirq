# 一份项目记录，关联所有交付

沿用已有记录，小任务只记目标/变更/证据/遗留。复杂跨硬件、固件、结构、采购的项目可用结构化档案，Agent维护而非让新手填表；不强制使用`project.json`或相同版本号，不运行未合入的`project_check.py`。

## 需要关联什么

| 记录 | 最小关联 |
|---|---|
| 原始用途与范围 | 用户原话、必须/可选目标、场景、可观察通过标准；未决数值明确暂定 |
| 设计决定 | 选择与理由、来源/条件、受影响模块/接口；不要只列结论 |
| 当前工件 | SCH/PCB身份与保存版本、BOM变体、固件目标/源码/构建摘要、壳体与制造包版本 |
| 引脚表 | 稳定器件ID/位号、实际物理脚、GPIO/ADC/复用、网络、有效电平/默认态、对应固件配置 |
| 验证 | 方法、条件、对象/版本、期望、实际观测、证据来源、状态与日期；未执行为空/待确认 |
| 采购/制造 | 物料来源与时间、装配/采购数量、订单/报价对应版本、授权范围和真实状态 |

引脚表最好由真实读回与所选器件引脚表生成/核对，代码配置尽量从该权威表生成。只有“网络在MCU的任意脚上”还不够：必须核对它是否在固件指定的那只物理脚/GPIO上，能力、方向、电平和启动状态也一致。GPIO编号与封装焊盘号不能混用。

## 变更传播

| 改动 | 必须评估/更新的对象 |
|---|---|
| 同封装/同脚候选换料 | 额定/容差/行为差异、库身份、BOM与渠道成本；确认是真兼容再保留PCB |
| 改符号、封装或引脚 | SCH-PCB映射、布局布线、BOM/坐标、程序接口、机械及相应回读 |
| GPIO/有效电平/地址 | 原理图/PCB、权威引脚表、固件配置、测试和用户接线说明 |
| 板框、安装孔、接口位置 | PCB、壳体/面板/线束、工装、加工资料及装配检查 |
| 阈值/算法/联网路线 | 需求、固件/配置、功耗/续航、测试条件、费用/服务依赖和说明 |
| 已投板后的变更 | 保留生产快照与现有实物身份，新版另记；评估旧库存、飞线/返修及程序兼容性 |

各工件可以独立版本，但必须有明确匹配关系与适用板版。不要为统一字符串把已生产硬件改标成新版，也不要每改一个注释都要求全项目升版。

## 验收记录的纪律

测试`通过`必须有实际结果，写清Agent直接观测、用户反馈或制造方报告；日志存在、脚本退出0、版本号相同都不能替代内容验证。输入开路/拔出传感器只能测故障/阈值链的一部分，不证明真实土壤缺水检测效果。

每次修改评估受影响测试，保留失败证据和复验，不把旧版通过结果复制给新版本。长期寿命、耐候、EMC、安规/认证等没有完整测试时分别记录估算、局部实测或待确认，不用平均分冲掉必须目标失败。

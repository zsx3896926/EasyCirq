# 原理图排版基准集（8类）

这是一组**故意有缺陷的离线几何快照**，用于让Agent和检查器在同类任务上有一致的最低验收面。它不是8张可直接生产的原理图，也不是真实EDA工程的替代品。每个案例都有：问题、改善目标、连接关系、可执行几何、预期候选、实际导图检查方法。

运行：

```bash
python scripts/schematic_benchmark.py
python scripts/schematic_benchmark.py --case B1-MCU-MIN --output case.json
python scripts/sch_layout_check.py case.json
```

`提示`/`等价`是检查器候选，不是电气结论；`expected_codes`只表示该案例应复现这些候选。任何案例通过都不代表真实工程通过。

## 1. 八个案例

| ID | 类别 | 主要问题 | 需要改善的目标 | 真实导图还要看什么 |
|---|---|---|---|---|
| B1-MCU-MIN | MCU最小系统 | 位号文字压本体、SWD/复位交叉、说明文字不在模块成员内 | 位号/说明移出本体；交叉错开或改短引线+标签；模块成员完整 | 复位/下载/电源脚是否可跟读；位号与值是否遮挡；SWD与复位是否混淆 |
| B2-POWER | 电源转换 | 反馈线穿功率级本体并绕行；关键节点跨度过长 | 输入电容→开关→电感→输出电容短回路；反馈从输出采样点短引线回控 | 功率回路面积、输入/输出电容归属、反馈采样点、地回流；PCB另验 |
| B3-ANALOG | 模拟采集 | ADC标签贴错网络、VREF标签悬空、文字未归模块 | 标签落在真实端点且网名一致；基准/去耦节点明确 | 模拟输入/基准/地参考是否同域；标签是否只是“看起来连上” |
| B4-COMM | 工业通信 | A/B标签贴错网络、文字跨框、终端说明未归模块 | 差分对成对呈现、标签各随其线、框线不切文字 | A/B极性、终端位置、共模/隔离边界；不能凭对称声称PCB阻抗满足 |
| B5-BATTERY | 电池与保护 | 器件越页、保护框越页、说明未归模块 | 先把电池/保护/输出限制在图框内，再谈紧凑 | 电池/保护/负载网络、极性、安规/机械条件；几何脚本不判安规 |
| B6-MOTOR | 电机/感性负载 | 采样线悬空、同一电机端子被两条不同网络占用 | 明确测试点或删除悬空线；一端子一网络；驱动/续流/采样同块 | 续流路径、采样点、驱动供电与地回流；SOA/热另验 |
| B7-WIRELESS | 无线模块 | 天线净空框与主控框重叠、净空说明未归框 | 净空区独立，不被其他模块框/器件占用 | 天线净空、地平面、外壳与匹配；以模块手册和实际叠层为准 |
| B8-MULTI | 多模块组合页 | 长地线、文字/导线压标题栏、模块成员不全、UART标签错网 | 按电源→主控→接口阅读顺序分块；跨块短引线+标签；标题栏留空 | 阅读顺序、跨页网络作用域、标题栏/页边界、模块留白 |

## 2. 连接关系与案例边界

每个案例的 `connectivity` 只列“该案例想表达的网络归属”，不是完整器件手册脚表，也不是已核对网表。例如 B1 只表达 `U1: 3V3/GND/NRST/SWDIO`、`C1`、`R1`、`J1` 的网络关系，不证明U1真实脚号、复用功能或电气兼容。真实任务必须从适用手册/库回读物理脚，再按 [连接表契约](connectivity.md) 或实际网表核对。

坐标是“benchmark grid units”，只用于离线几何检查，不是毫米、mil或像素。不要把案例中的 `(300,400)` 之类坐标直接写进真实工程；真实页面宽高/引脚端点必须从 [EDA执行](eda-execution.md) 的 `read` 回读。

## 3. 检查器新增能力与边界

`sch_layout_check.py` 在原有“矩形重叠/线穿本体或文字/越页/长线/不同网导线交叉”之外，新增可选检查：

| 字段 | 检查 | 典型候选 |
|---|---|---|
| `title_block` | 图签矩形 | 器件/文字压图签、导线穿图签、图签越页 |
| `module_frames` | 模块框与 `contains` 成员 | 框越页/压图签/互相重叠、框线切器件、成员缺失或成员在框外 |
| `attachment_points` + `policy.connection_tolerance` | 端点是否落在声明的引脚/标记/端口点或其他导线上 | 悬空导线端点、同一连接点出现多个网络 |
| `label_anchors` + `policy.connection_tolerance` | 标签锚点是否落在导线/连接点，网名是否与所在导线一致 | 标签悬空、标签网名与导线不符、同点不同网标签 |

这些检查仍是**候选**：`attachment_points` 不完整会把正常端点报成悬空；模块框的 `contains` 只是声明，不是工具自动识别的电气归属；标签“在线上”也不证明全页网络正确。因此：

- 只有 `matched is True` 且有对象时才可能输出 `no_candidates`，否则 `incomplete`；
- `electrical_verified` 与 `visual_verified` 始终为 `false`；
- 修完候选后必须回读实际网络并导出实际图，整页+局部检查，不能只看脚本退出码。

## 4. 与真实EDA证据的关系

- 8个案例是离线几何基准，**没有**在真实EDA中逐个绘图/导图；不要写成“8类已真机验证”。
- 真实执行通道的证据在 [EDA执行证据](../../docs/evidence/eda-2026-10-21/README.md)：同版本客户端上读取工程、创建R901/LED901/网络标识/导线、保存、关闭重开、导出PNG与Protel网表，网表核对 `R901-1=5V`、`R901-2=LED901-1=LED_A`、`LED901-2=GND`。该证据只证明两器件串联演示页的闭环，不证明这8类都已真机绘制。
- 若要把某个基准升级为“真实EDA案例”，至少需要：真实工程副本、器件完整型号/库身份、引脚回读、实际导图、网表核对、保存/重开结果；缺一项就保持 `离线示意/未执行`。

## 5. 使用顺序

1. 读案例的 `problem/target/connectivity/inspection`，先理解要解决什么，不直接抄坐标。
2. `schematic_benchmark.py --case <ID> --output case.json` 导出几何，`sch_layout_check.py case.json` 看候选。
3. 对候选逐项判断：是真实碰撞/悬空/错网，还是快照不完整造成的误报。
4. 在真实工程中按 [原理图排版与看图验收](schematic-layout.md) 的流程做“连接基线→模块几何→页面组合→小批写入→回读→导图→修正”。
5. 修复前后比较连接关系；排版修改不得改变网络。最后显式保存并重开核对。

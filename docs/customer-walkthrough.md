# 客户视角走查（2026-11-01，1.3.34，隔离安装）

> 目的：验证终态判据——**一位不懂 EDA 的客户，在不看任何文档的情况下**，
> 只按输出里的提示就能走完四步。
>
> 做法：用 `easycirq_install.py` 把工具链装到一个临时目录（`%TEMP%\cust-walk`），
> 之后的每条命令要么用那个隔离安装的二进制，要么只用交付包里的文件。
> 不看 `SKILL.md`，不看我写过的任何文档。

## 第一步：一条命令装好

```
$ easycirq setup
EasyCirq 安装检查

  ✓ 运行时            easycirq 1.3.34
  ✓ 后台服务           运行中
  ✓ EasyEDA 插件     已连接（EasyEDA Pro 4.1.78）
  ✓ 技能包            已安装

一切就绪。下一步：说清你要做什么板子，或者运行 easycirq status 看当前状态。
```

退出码 **0**。四行中文，最后一行直接给了下一步。

## 第二步：一句话说出需求（以及"现在什么状态"）

刚装完还没画任何东西时：

```
$ easycirq status
【这块板还没有做过离线检查】
下一步：把你想做的板子说给 AI 听就行；画完并检查过之后，这里会告诉你还差什么
```

退出码 **2**。

**这是有意为之**：状态机把它判为 `incomplete`，退出码 2 表示"还不能下结论"，
而不是"出错了"。输出本身已经把下一步讲清楚了。

## 第三步：拿到一张写着「可以打样 / 还差什么」的卡

用这块板真实的检查结果：

```
$ easycirq card --kpi-report reports/alarm-r163/kpi-report.json \
                --pcb-drc reports/pcb-drc-r163.json
✅ 可以下单（原理图与板子都通过）

板子检查：通过（0 项）

检查结果：必查 14/14 通过 · 缺证据 0 · 不适用 3 · 提醒 1
下一步：导出制造文件；打样回来后做验收
```

退出码 **0**。

## 第四步：打样回来拿到验收卡

```
$ easycirq acceptance --file deliverables/alarm/acceptance.example.json
✅ 这块板可以交付使用

工程 KPI-S5-Verify  板号 alarm-r1

  ✓ 焊接       示例：照片 IMG_0001.jpg（5 个器件无虚焊）
  ✓ 上电       示例：5V 输入 5.02V，3.3V 轨 3.29V
  ✓ 功能       示例：58℃ 响，55℃ 停（回差 3℃）
```

退出码 **0**。

（这份 `acceptance.example.json` 里是**示例数据**，文件清单里也标了"里面是假数据"。
真实的验收卡需要打样之后用实测值填。）

## 结论

| 判据 | 结果 |
|---|---|
| 一条命令装好 | ✅ `setup` 四行全绿，退出 0 |
| 一句话说出需求 | ✅ `status` 在无数据时也给了明确下一步 |
| 拿到卡片 | ✅ `card` 14/14，退出 0 |
| 打样后验收卡 | ✅ `acceptance` 工具就绪，**但本步从未用真实数据跑过** |
| 全程无需解释工具概念 | ✅ 四条输出里唯一的工具词是命令名本身 |

## 仍然不是"目标达成"的部分

**第四步用的是示例数据。** 真正的验收卡要在打样、焊接、通电、测温之后才能生成。
在那之前，这一栏只能是「工具就绪」，不是「已经走通」。

## 一个测量教训（记下来免得重犯）

第一次跑这四条命令时我把退出码读成了 `2,2,2`，差点当成缺陷去查。
原因是 PowerShell 里 `& $exe ... | Select-Object -First 6; echo $LASTEXITCODE`
取的不是 exe 的退出码。

**干净重测**（不带管道、输出重定向到 `$null`）的结果才是对的：

```
setup=0  status=2  card=0  acceptance=0
```

`status` 的 2 是状态机对 `incomplete` 的既定码，不是故障。
这是**第二次**因为测量方式把结论搞错。

## 装出来的东西能自己干活吗（隔离安装实测，1.3.34）

之前的「隔离安装 healthy」只核对过**文件哈希对得上**。那证明包没坏，
但不证明装出来的脚本能跑。这一轮补上：

| 检查 | 结果 |
|---|---|
| 技能目录里的脚本数 | **86** 个 `.py` |
| `skill_selftest.py`（用隔离安装里的那份跑） | **6 PASS, 0 FAIL, 0 NOT RUN** |
| `sch_offline_pipeline.py` 跑真实报警板快照 | **PASS**，`kpis: 18`，`verdict: PASS` |
| 用隔离安装的二进制出卡片 | 「✅ 原理图可以打样（板子还没检查）」必查 **14/14** |

最后一行那个「板子还没检查」是对的——这次只给了原理图报告，没给 PCB 检查结果，
卡片如实收缩了结论，没有冒充整板通过。

### 为什么值得单独记

一个「文件都在、哈希都对」的包，仍然可能因为缺一个 import、少一个资源文件、
或者脚本间的路径假定而**跑不起来**。上面四行是跑出来的，不是比出来的。

## 验收卡能不能判红（1.3.34 实测）

指标 6 是「交付卡与实测证据一致率 100%」。它最容易被破坏的方式不是算错数，
而是**把没有证据的东西算成通过**——一块不响的板配上「✅ 可以交付使用」。

四种情况实测：

| 输入 | 输出 | 退出码 |
|---|---|---|
| 写 pass 但证据为空 | 「⏳ 还差实测证据」 | 1 |
| unction 填 ail（加热到 70℃ 不响） | 「❌ 这块板还不能算可用」 | 1 |
| 三项都是实测 pass 且带读数 | 「✅ 这块板可以交付使用」 | 0 |
| 记录文件不存在 | 「⏳ 还没有验收记录」 | 2 |

**第一条是关键**：写了 pass 但没读数，不会变成绿灯。

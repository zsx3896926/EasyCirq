### 第 7 项 · 报告可分发、能看出哪些没生效 ⭐

```powershell

```

| 通过标准 | |
|---|---|
| 生成 `kb.html` | |
| **断网**双击能打开，样式正常（没有任何外部引用） | |

### 第 8 项 · 两人同时维护不互相覆盖 ⭐

A 同学推一条规则，B 同学推另一条：

```powershell

easycirq enterprise promote --ledger B的人审记录.json
easycirq enterprise ls
```

| 通过标准 | |
|---|---|
| 两条规则**都在**库里 | |
| 第二次输出写明「本次推入 N 条 / 库中共有 M 条」 | |
| 若两条用同一 id 但内容不同 → **报冲突、退出码 2**，且库里保留原有那条 | |

> 共享目录上这是必然发生的场景。**不许"后保存的覆盖先保存的"**。

结果：□ 通过　□ 不通过　□ 不适用　　备注：______________

## 四、试点的成功与中止条件

### 成功的定义（满足全部 4 条）

- [ ] 客户至少 **3 条真实规范**进了库，且各自**至少拦住过一次真板**
- [ ] 第 4–8 项全部通过
- [ ] **2–3 名工程师连续用满 2 周**
- [ ] 没有被工程师抱怨"误报太多"而关掉的情况

### 中止的定义（出现任一条就停下来谈）

- [ ] 网表拿不到（客户端导不出、连接器也读不到）
- [ ] 现有规范不足以写成可执行规则（写出来全是 advisory，拦不住任何东西）
- [ ] 误报率高到工程师主动关掉检查
- [ ] 两个月内没有任何一次真实拦截

> **中止不是失败。** 它说明这套东西对这家客户现在还不适用，
> 早说比晚说省双方的钱。

# 企业版 LLM 网关设计（B 方案）

> 状态：**转发链路已实现并实测**（假上游验证）。
> **真实模型调用未验证** —— 需要客户的 C1/C2/C4 答复和内网 key。
> 未做的部分见文末，逐条写明卡在哪条门。

---

## 一、为什么走 B 不走 A

| | A 方案（服务端代调 LLM） | **B 方案（本项目）** |
|---|---|---|
| 谁跟 LLM 说话 | 服务器 | **工程师机器上的 Agent** |
| 服务器职责 | 重做整套方法论编排 | 发配置与密钥，转发请求 |
| 出错面 | 一个人 → **一个公司** | 一个人 |
| 已验证的架构 | 要重写 | **保持不动** |

A 要把握手、门禁、审计、重试、流控全搬进服务端。一旦某处编排错了，
全公司的板子都受影响。B 把这些留在工程师那一侧，服务器只做它必须做的事。

---

## 二、整条链路

```
┌─ 工程师机器 ────────────────────┐        ┌─ 公司服务器 ─────────────┐
│                                  │        │                          │
│  Agent                           │        │  easycirq gateway        │
│   base_url=http://127.0.0.1:23190│        │   /llm/v1/chat/...       │
│        │                         │        │        │                 │
│        ▼                         │        │        │ 换成真 key      │
│  easycirq llm-proxy   ───────────┼───────▶│        ▼                 │
│   （本机代理）                   │  token │   公司 LLM               │
│        │                         │        │                          │
│  ~/.easycirq/credentials.json    │        │  (key 只在这里)          │
│   只有 token，没有 key            │        │                          │
└──────────────────────────────────┘        └──────────────────────────┘
```

**三处凭据边界**：

| 位置 | 有什么 | 没有什么 |
|---|---|---|
| Agent 配置 | `http://127.0.0.1:23190/v1` 和一个占位 api_key | **任何真凭据** |
| 工程师机器凭据文件 | 服务器地址 + **短期 token** | **真 key** |
| 服务器环境变量 | **真 key** | — |

---

## 三、为什么需要本机代理（127.0.0.1:23190）

**不加这一层，token 就得写进 Agent 的配置文件。** 而这类文件：

- 经常被截图发群
- 会被提交进仓库
- 会在排查问题时被贴到工单

本机回环地址 `127.0.0.1:23190/v1` 里**没有任何凭据**。token 由代理在转发时补上，
读的是 `easycirq login` 存的凭据文件。

这就是 B 方案里那个 `127.0.0.1:23190` 存在的理由，不是多余的一跳。

---

## 四、路径与 base_url 映射

| Agent 请求 | 本机代理转成 | 服务器再转成 |
|---|---|---|
| `POST /v1/chat/completions` | `POST <server>/llm/v1/chat/completions` | `POST <上游>/v1/chat/completions` |
| `GET /v1/models` | `GET <server>/llm/v1/models` | `GET <上游>/v1/models` |

规则很简单：**`/llm` 之后的路径原样透传**。这样上游换了什么版本、加了什么端点，
都不需要改代码。

---

## 五、鉴权

| 环节 | 依据 | 失败时 |
|---|---|---|
| 本机代理 | 只接受回环来源 | 403，且**不转发** |
| 服务器 `/llm/*` | `Authorization: Bearer <工程师 token>` | 401，且**不打上游** |
| 服务器 → 上游 | 服务端真 key | 上游自己报错，原样返回 |

**没有 token 表的服务器一律拒绝**——否则它就是个开放代理，谁发现地址都能白用公司额度。

token 查找用常数时间比较、**不提前退出**，响应时间不泄露"命中了第几条"。

---

## 六、审计

每次转发记一行：

```
llm: 张工 POST /v1/chat/completions -> OK 1.23s
```

**记**：谁、方法、路径、状态码、耗时。
**不记**：请求体、响应体、真 key、工程师 token。

图纸和提示词可能涉密。**日志就是磁盘上的一份副本**，落盘即泄露。

---

## 七、真 key 不落地的边界

| 断言 | 验证方式 |
|---|---|
| key 从环境变量读，不从命令行 | 参数名是 `--llm-key-env`（变量**名**），不是 key 本身；命令行参数会进 `ps` 和 shell 历史 |
| 工程师的 token 不到上游 | 测试断言上游收到的 `Authorization` 里不含工程师 token |
| 工程师机器上没有 key | 端到端读凭据文件，断言不含 key 字符串 |
| 上游状态码原样返回 | 429 被改写成 200 会让调用方以为自己没问题 |

**实测输出**（假上游）：

```
上游收到 Authorization: Bearer sk-real-company-secret
工程师凭据文件含真 key: False
工程师凭据文件含 eng-token: True
```

## 八、还没做的

| 项 | 卡在哪 | 说明 |
|---|---|---|
| **真实模型调用** | **C1 / C2 / C4** | C1 网关形态；C2 是否 OpenAI 兼容（不兼容要协议转换）；C4 图纸能否出公司（不能则只能内网模型） |
| 非 OpenAI 协议的转换 | **C2** | 现在只原样透传 OpenAI 兼容路径 |
| 按人配额与限流 | **C5** | 谁承担额度、要不要按人计量 |
| 超时重试 | 无 | 现在单次超时（默认 120s），**不重试**——重试一个已经开始的补全可能双计费 |
| 流式响应的帧级处理 | 无 | 现在原样透传字节流，不解析 SSE |

最后两项是刻意的：**不做比做错好**。重试和流解析都要先知道 C1/C2 的答复。

## 九、给客户的一句话

这个网关**不替你选模型、不替你调参、不替你计费**。
它只做一件事：让你的工程师用上公司配的模型，而**密钥不离开你的服务器**。

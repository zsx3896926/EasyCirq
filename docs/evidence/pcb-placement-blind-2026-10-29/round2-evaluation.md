## 1. 方法与口径

- 3 名隔离 Agent（R1/R2/R3）试答 v2 题面（只读仓库外题目副本，禁止读仓库/答案/联网/运行命令；各自自报只读过该副本）。
- 2 名独立评审按同一口径逐题打分：结论类型 / 机制 / 证据 / 行动 / 未知，`✓ / △ / ✗`；X05、X11 为专项，同时判断**答案本身是否站得住**。
- 每位评审输出 60 个评分单元（20 题 × 3 人）。两评分数用脚本逐单元比对算一致率；冲突单元由 Lead 逐条裁决（见 §5）。

## 4. 两评审共同判断与专项

### 4.1 X05（终端跨隔离侧）

- 两评审一致：**答案 ②-only（案例只声明一个连接器贴边硬检查）站得住**，且答案没有把 `connector_off_edge` 扩写成“隔离已验证”。
- 但两评审都指出：答案的**证据句与案例 JSON 不一致**——`P4-COMM.checks` 里只有 `ck-decoup`（且通过），`connector_off_edge` 来自 `board.connectors` 声明 + `rubric.connector_edge_tol_mm`，不是 `checks[]` 里的项。原句“案例数据只声明了这一个硬检查”应写成“只声明了连接器贴边这一个硬检查（来自 board.connectors + 容差），没有为隔离边界单设检查项”。
- 两评审都指出：`可确认` 只覆盖 `connector_off_edge`；若把“隔离是否合规”当成被问结论，主标记应为 `待补`/`条件`。答案需要写死适用范围。
- 作答侧：R1 主标记对但机制自相矛盾；R2/R3 主标记 `条件` 且偏向“压进代理”（①）——说明“二选一”在题面里仍不够硬。

### 4.2 X11（反馈取样点）

- 三人一致标 `可确认`（“离线区分不了两个取样点”），无人再标 `待补`——**v2 修订目标达成**。
- 两评审都认为：**答案的 `条件` 主标记与题面要求不完全一致**。题面 v2 明确“结论类型必须落在被问的那件事上（离线判分能否区分取样点）”，回答“不能区分”是判分规则的确定事实 → 应为 `可确认`；把“两个取样点是否等价/哪个正确”放进条件副注并标 `NOT RUN`。
- 结论：**改答案（X11 主标记 → `可确认` + 条件副注）**，不是改题面。

### 4.3 X01 / X02 / X06（三人全 △）

两评审一致：这三题是**题面诱导 + 答案未给“主标记落层”示例**。答案标 `可确认`（判分器 verdict 可确认），三人全写 `条件`（想着真实板性能）。→ 在答案侧补“主标记落层”规则，`题面 v3` 加一句全局提示。

## 5. 裁决（评审后修订，v2 评分不追溯）

> 本轮分数按**修订前**的 v2 `answers.md` 计算，保持不变；以下修订（称 v3 口径）用于下一轮，**不回改本轮分数**。

| 项 | 修订 | 依据 |
|---|---|---|
| 标记口径 | 新增「主标记落层」规则：主标记问的是**判分器在题给数据下能判到什么程度**；真实工程条件（层叠/屏蔽/热/3D/手册）一律进 `未知` + `NOT RUN`，不改变主标记；只有题目直接问“能否上量产/能布通/能插拔”时，才按该问答案（多为 `待补`/`条件`） | 两评审对 X01/X02/X06 的一致归因；解决“复合标记”冲突 |
| X05 | 修正证据事实（`connector_off_edge` 来自 `board.connectors` + rubric 容差；`checks[]` 只有 `ck-decoup` 且通过）；补“主标记只覆盖 `connector_off_edge`，隔离本身是 `待补`” | 两评审一致指出 |
| X10 | 主标记由 `条件（偏待补）` 改为 `待补（偏条件）`：题面直接问“能插拔/能不能上量产”，答案就是“不能，缺 3D” | 「主标记落层」规则；B 评审与三人作答一致 |
| X11 | 主标记由 `条件` 改为 `可确认`（判分器不能区分 = 确定事实），保留“两取样点是否等价 = 条件”副注 + `NOT RUN` | 两评审一致建议（选项 2） |
| 题面 | v3 加一句全局提示：主标记落在判分器判定层；真实工程条件写未知。X05 的“二选一”加粗并注明“只能选后者” | A 评审建议 1–2 |
| X13 | 不改答案；本轮 R2/R3 未识别“成对翻转”属**作答问题**（内容错误），保留为训练点 | 两评审均判该题为内容失分 |

## 6. 发现（合并两评审）

1. **结论类型仍是唯一主要失分维度**（✓ 60%–61.7%），且 20–24 个失分单元里绝大多数是标记位移；机制/证据/行动/未知都在 90% 以上。说明题面已能支撑工程推理，问题在**标记口径**。
2. **X01/X02/X11 三人全 △** 是最大可修复项，且两评审给出的修复方向一致（答案加“主标记落层” + X11 改主标记）。
3. **X13 两人 ✗** 是唯一的内容错误（成对案例“只改一个条件 → 结论翻转”没识别），属于要在示例/答案里加强讲解的点。
4. **X05 的答案事实错误**（`checks[]` vs `board.connectors`）说明“答案也要能被案例数据核对”，不只是看结论对不对。
5. **跨评审一致率 92.7%，结论/未知维只有 86.7%**：说明 5 维口径本身需要更硬的定义，否则“双评审”只是把不确定性写在纸上。
6. **无三人全 ✗、零“过度修改/臆造 code/补默认坐标”**：与第一轮一致，纪律项稳定。

## 7. 限制（不可越过）

- 3 名试答者、2 名评审、单轮；**约束式隔离**（同一文件系统，靠指令约束），非容器/权限强隔离；三份作答同源同构，不排除对训练语料记忆。
- 本轮与第一轮**题面版本、评审人数、作答者均不同**，分数不可直接比较；v2 与即将使用的 v3 题面/答案也不可直接比较。
- 评审 A 与 B 的 22 处冲突说明“结论类型”评分仍有主观空间；本报告保留两人原始分数，不做平均掩盖。
- **不能证明模型能力**，不能作为认证或对外能力声明；不代表真实工程判断力。

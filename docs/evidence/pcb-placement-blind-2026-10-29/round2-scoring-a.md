## 1. 方法与口径

按 `answers.md` 的「标记口径（评分用）」逐题比对，五维各给 `✓` / `△` / `✗`：

- **结论类型**：以 `answers.md` 的答案标记为准；同时看 ① 有没有把软检查 `review` 说成 `blocking`/`fail`，② 有没有把数据缺口说成可确认，③ 有没有漏 `NOT RUN`，④ 是否守「单主标记、条件必须两段、结论落在被问的事上」。主标记对、但关键 verdict 明确错（如把成对 `acceptable` 说成 `review`，或把 `review` 说成 `acceptable`）记 `✗`；仅主标记位移、verdict 与边界基本对，记 `△`。`X10` 的答案本身写「`条件`（偏 `待补`）」，故 `待补` 不按位移扣分。
- **机制**：能否说出电流回路/回流、耦合路径、热路径、机械干涉，而不是只重复 code 名。
- **证据**：能否指到案例 id、finding code、检查 id、PL 条目或规则描述。题面未给 code 名时，写 check_id/规则描述算 `✓`；写一个不存在或明显反向的 code 占位名算 `△`。
- **行动**：修复动作是否与结论匹配；`blocking` 先硬约束、`review` 先主导项，不过度整板重排。
- **未知**：是否列出离线判分答不了的项并写 `NOT RUN`；`待补`/`未覆盖`/`未验证` 视为等价状态。

**评分边界**：本报告评的是「仅凭题面可判」的作答质量，不是工程能力认证。`△` 多数是标记/口径问题，不等于作答者不懂机制；`✗` 只给明确与答案相反的关键 verdict。`X05`、`X11` 的「答案是否站得住」单列在 §4、§5，不因答案争议而改评分口径。

## 4. X05 专项：终端跨隔离侧为何表现为贴边/朝向硬检查

### 4.1 答案要点（`answers.md`）

1. 结论 `可确认`（限案例数据）；verdict `blocking`，codes 只有 `connector_off_edge`。
2. 二选一只能选 **②**：案例数据只声明了这一个硬检查，隔离边界（爬电、电气间隙、耐压）不在 v1 判分范围内。选 ①（「判分器把隔离缺陷压进/证明成贴边问题」）是过度归因。
3. 可确认的是 `connector_off_edge`；**不能**写成「隔离边界已被验证」或「隔离已违反」。隔离本身是 `待补`（需要层叠、隔离耐压、安规）。
4. 行动：机械侧把连接器贴边；电气侧把终端留在隔离侧内，并按器件/安规核隔离间隙。
5. 未知：爬电/电气间隙、隔离耐压、3D 插拔空间，`NOT RUN`。

`benchmarks.json` 的 `P4-COMM.reference.rationale` 直接支持第 2 点：「『终端跨隔离侧』在 v1 里没有对应几何检查，只写进 problem/inspection 作为人工复核点」。因此答案的 ②-only 判断是有案例数据依据的，不是作者臆断。

### 4.3 我的判定

- **R1：结论 ✓；专项对照的 verdict 表述 △，其余 ✓。** 五维结论类型按主标记（`可确认`）与硬检查逻辑判 ✓；但专项逐条看，verdict 用「fail」而没有写 `blocking`，属表述不完整，记 △。两者不矛盾：五维看类型，专项看逐条覆盖。
- **R2：结论 △，机制 △，证据 △。** 主标记 `条件` 与答案 `可确认` 相反；更关键的是没有回答「这是压进代理，还是案例只声明一个硬检查」这一问，读者会以为判分器「懂」隔离。行动和未知对。
- **R3：结论 △，机制 △，证据 ✓。** 内容最接近答案：依据明确写了「案例只声明一个贴边/朝向硬检查」，但主标记用 `条件` 且句内又写「可确认」，违反「单主标记」；机制「被压成几何投影」是答案明确判为过度归因的 ① 表述。

### 4.4 答案是否站得住

**基本站得住，但 `可确认` 的适用范围需要写得更死。** ②-only 有 `P4-COMM` 的 rationale 直接支持；答案也没有把 `connector_off_edge` 扩写成「隔离已验证」，反而明确说隔离是 `待补`。问题在于：题面问的是「为什么表现为贴边/朝向硬检查」，答案的 `可确认` 只覆盖「`connector_off_edge` 这个硬检查可确认」，而「隔离边界是否合规」本身是 `待补`。一个两段式 `条件` 答案（`connector_off_edge` 可确认 + 隔离 `待补`）在内容上与答案等价，只是主标记不同。

**建议（不改答案实质）**：在 `answers.md` X05 的结论后加一句——「本题主标记只覆盖 `connector_off_edge`；若把『隔离是否合规』作为被问结论，主标记应为 `待补`/`条件`。」这样既保留 ②-only 的判断，又消除 `可确认` 被读成「隔离已确认」的风险。评分上，`条件` 仍按主标记位移记 △，但不应判为内容错误。

## 5. X11 专项：反馈取样点在离线判分里的盲区

### 5.1 答案要点（`answers.md`）

1. 主标记 `条件`。必须拆两段：
   - **可确认（图纸/配置事实）**：反馈件位置在阈值内，判分器不会针对「取样点」报失败——这是可以直接看出的几何/配置事实。
   - **条件（需题外条件）**：「两个不同取样点是否等价、哪一个是正确的调节点」离线判不出来；取决于实际取样点的电气拓扑、走线是否避开功率脉动地、输出电容/负载侧位置。
2. 为什么不是 `待补`：数据并不缺到无法判断；缺的是「两个取样点是否等价」这个条件。
3. 结论要落在被问的事上：本题问「离线能不能判取样点等价」，答案就是「不能判（条件）」，而不是只答「反馈件在阈值内」。
4. 机制：取样点决定调节点；v1 只用网络/坐标/`loop_span` 代理，同网络、几何相近的两个取样点可能得到相同分数。
5. 行动：按 PL12 从规定点取样；离线层可加「取样点到指定输出电容焊盘」的 `max_distance` 显式检查，或做成对案例只改取样点并加显式 `checks`。
6. 未知：输出纹波/负载瞬态、补偿、实际取样点寄生、走线是否跨功率区，`NOT RUN`。

### 5.3 我的判定

- **R1/R2/R3 全部结论 △。** 三人都把「离线区分不了」写成 `可确认`，而答案的主标记是 `条件`；同时三人都没有严格拆成「可确认事实 + 尚缺条件」两段（R1 有几何事实但没有条件段，R2 只提「缺取哪段铜」，R3 只提「缺拓扑」）。机制、证据、行动、未知基本对。
- 从「被问的事」看，三人的落点其实是对的：都回答了「离线不能区分两个取样点」。他们与答案的差异是**主标记**，不是内容。这也是为什么这一题三人全 △ 最值得单独讨论。

### 5.4 答案是否站得住

**部分站得住，主标记有争议。** 两段式拆分、机制、行动、未知都站得住；争议在 `条件` 这个主标记：

- 题面最后一句明确要求「结论类型必须落在被问的那件事上（『离线判分能否区分取样点』）」。对「能否区分」的回答是「不能」——这是判分器输入/规则的**确定事实**，不是题外条件。
- 答案把「两个取样点是否等价、哪个是正确调节点」作为被问结论，因而标 `条件`。这其实比题面问的**多走了一步**：题面问的是「能否区分」，不是「两个点是否等价」。
- 按答案自己的规则 3（「结论必须落在被问的事上」），`可确认（不能区分）` 也讲得通；按答案现在的正文，`条件` 也讲得通。两种读法都能自洽，说明答案在这一点上**内部不完全一致**。

**建议（二选一，不要两头都占）**：

1. 保留 `条件`：把题面最后一句改成「本题问的是两个取样点是否等价/哪个是正确调节点；离线只能确认『不报失败』，等价性是条件」。
2. 改成 `可确认`：主标记写 `可确认（不能区分两个取样点）`，再把「两取样点是否等价/哪个正确」放进条件说明与 `NOT RUN`。

在答案未改之前，本报告严格按 `answers.md` 的 `条件` 评分，故三人的 `可确认` 记 △；但这是**标记口径争议**，不是三人内容错误。若跨评审要算「内容正确率」，X11 应单独标注，不宜与真正的 `review→blocking` 错误混在一起。

## 6. 发现

1. **结论类型仍是五维中最低的一项，且失分几乎全是「可确认 ↔ 条件」位移。** 60 份作答中结论 ✓ 37（61.7%）、△ 20、✗ 3；机制 96.7%、证据 95.0%、行动 100%、未知 93.3%。对照 `README.md` 记录的一轮结论 43/60 = 71.7%，只能作方向性对照——README 明确说 v1/v2 分数**不可直接比较**（题面与答案口径已变），本报告不据此下「退步」结论；可说的是结论类型仍是五维中最低，失分集中在标记位移而非知识错误。**归因：题面/答案口径问题为主，作答问题为辅。** 建议在 v3 题面加一句判别规则：「主标记只落在判分器 verdict 能被题给数据确定的程度；真实板/层叠/3D 条件写进未知，不改变主标记。」

2. **X01/X02 三人 6/6 全 △，X06 2/3 △（仅 R3 ✓），合计 8/9 △，是最大的可修复项。** 三题答案都标 `可确认（限案例数据）`；R1/R2 在 X06 也写 `条件`，只有 R3 写对。题面同时问「判分器应给什么 verdict」和「哪些结论必须等真实板」，作答把后者当成了主标记。**归因：题面诱导 + 答案未给「主标记落哪一层」的示例。** 建议在题面 X01/X02/X06 各加半句：「本题主标记问的是判分器 verdict，不是真实板性能；真实板条件写未知。」

3. **X11 三人全 △，但答案本身有争议，不应算三人内容错误。** 题面要求「落在被问的事（能否区分取样点）」，而「不能区分」是判分器的确定事实；答案却用 `条件`，因为把「两取样点是否等价」当成了被问结论。**归因：答案内部口径张力。** 建议按 §5.4 二选一改题面或改主标记；跨评审统计时应把 X11 单列，避免把标记争议算成能力失分。

4. **X05 的 `可确认` 也有适用范围风险；R2/R3 的 `条件` 内容接近正确。** `P4-COMM` 的 rationale 支持答案的 ②-only；但答案的 `可确认` 只覆盖 `connector_off_edge`，隔离本身是 `待补`。R3 的依据已经写到「案例只声明一个硬检查」，只是主标记写 `条件` 且句内又写「可确认」；R2 则真的滑向了 ①「压进代理」。**归因：答案主标记范围 + 作答机制表述。** 建议答案加一句适用范围；评分时对「两段式 `条件`」只扣标记、不扣内容。

5. **成对案例的「翻转」是唯一出现 ✗ 的地方：X13 R2/R3、X07 R3。** X13 两人把两份 verdict 说成「相同」/都 `acceptable`；X07 R3 把 `P3b` 说成 `review`。这不是标记问题，是没有把「只改一个条件」映射到「哪个 check 消失/翻转」。**归因：作答问题。** 建议训练时强制写三件套：「改前 verdict / 改后 verdict / 主导 check」，并特别练 `P3→P3b`（distance_far 消失）与 `P8→P8b`（两条硬检查通过）。

6. **`NOT RUN`/未知清单在「条件」类题上被弱化。** 未知维度 56/60；R1 的 X04/X15/X20 没有 `NOT RUN` 或未知清单，R2 的 X10 把未知栏用来回答「补 3D 后离线分数变不变」，而不是列缺项。**归因：作答格式纪律，不是知识错误。** 建议作答模板固定「未知：…（`NOT RUN`）」一行；`待补` 只用于数据缺口，不拿来代替 `NOT RUN`。

7. **code 占位名仍有反向错误。** R2 X20 写 `placement_missing`，答案的 code 是 `missing_placement`；题面未给名，按规则应写 check_id/规则描述，不应造近似 code。其余人用「placement 完整性」/「placement missing」描述，符合要求。**归因：作答细节 + 题面缺正例。** 建议在 `blind-prompts.md` 的试答要求里给一个「描述性 check_id」的正例，并说明「不要写看起来像 code 的占位名」。

8. **证据维度整体强（95.0%），但「题给事实 → 评分依据」的桥接不稳定。** X05 R2 缺「案例只声明一个硬检查」，X13 R2 缺「HPWL 全局阈值」，X20 R2 的 code 占位名反向。**归因：作答问题（没有把题给事实转成评分依据）。** 建议评分卡逐题列「必须引用的题给事实」：X05 的「只声明一个硬检查」、X13 的「HPWL 是全局软阈值」、X20 的「非固定器件缺 placement」。

## 7. 限制

- **单评审、只看文本。** 没有第二评分人交叉校验；`△`/`✗` 的边界（尤其 X05/X11 的主标记、X20 的 verdict 口径）有主观性。跨评审一致率需要等另一份评分报告出来后才能算。
- **未复跑判分器。** 只按题面给定事实与 `answers.md` 评分，没有重跑 `pcb_placement_benchmark.py`，也没有逐坐标核对作答里的数值（如「超阈」「16–19 mm」）。若作答数值与 `benchmarks.json` 有出入，本报告不另判。
- **3 个样本、同构度高。** 不能据此推断模型能力，也不作为认证或对外能力声明；隔离是约束式（禁读仓库/答案/联网/运行命令），不能排除训练语料记忆。
- **独立性。** 未读第一轮 `evaluation.md` 与另一份 `round2-scoring-b.md`；因此本报告不引用、不对比它们的逐题判断。`README.md` 的一轮汇总数字仅作上下文，不作为评分依据。
- **X05/X11 的「答案争议」不改变评分口径。** 本报告按 `answers.md` 现有标记打分；争议单列在 §4.4、§5.4，供作者决定是否改答案/题面。

# 第二轮盲测试答评分（评审 B）

> 对象：v2 题面（[blind-prompts.md](../../../easycirq/references/engineering-deepdives/exercises-pcb/blind-prompts.md)）下 3 名隔离 Agent（R1/R2/R3）对 X01–X20 的作答（[round2-responses.md](round2-responses.md)）。
> 对照物：[answers.md](../../../easycirq/references/engineering-deepdives/exercises-pcb/answers.md)（含 X05/X11 更新口径与「标记口径（评分用）」）、[README.md](../../../easycirq/references/engineering-deepdives/exercises-pcb/README.md)（五维 + 题目↔案例矩阵）、`easycirq/assets/pcb-placement-benchmarks/benchmarks.json`（各案例 `expected.verdict`/`codes`/`checks`，只读核对）。
> 独立声明：未读 `evaluation.md`，未读任何其他评分的 `round2-scoring-*.md`；未与 R1/R2/R3 或其他评审交流。

## 1 方法与口径

按「仅凭题面可判」评分：先取 `answers.md` 每题的**主标记**与该案例 `expected.verdict`/`codes`（用 `benchmarks.json` 核过：P1-MCU-MIN=review/distance_far、P2-BUCK=review/loop_large、P3-ANALOG=review/distance_far、P4-COMM=blocking/connector_off_edge、P5-BATTERY=review/distance_far、P6-MOTOR=review/loop_large、P7-WIRELESS=blocking/keepout_violation、P8-MULTI=blocking/connector_off_edge+body_overlap，四条 `*-PAIR` 均 acceptable），再查四条口径：①软检查 `review` 有没有被说成 `blocking`/fail；②数据缺口有没有被说成可确认；③该 `NOT RUN` 的有没有漏；④有没有遵守新「标记口径」（单主标记、`条件` 必须两段、结论落在被问的事上）。五维各给 `✓`（正确完整）/`△`（方向对但缺关键项、标记位移或表述混淆）/`✗`（明确错误）。题面未给 code 名时，写 check_id / 规则描述记 `✓`，臆造不存在的 code 记 `△`（本轮无人臆造 code）。`△` 的判定重点：结论类型维度看主标记与 verdict 是否同时对上；`未知` 维度要求列出该题关键缺项（有 `NOT RUN` 更佳；整段缺失或只列 1 项记 `△`）；`行动` 维度要求与结论匹配，且 X01/X08 的「过度例」（X08 另加「改对但分数不变例」）为必答项。

每格记 5 字，顺序固定为 **结论 / 机制 / 证据 / 行动 / 未知**（`C M E A U`）。

## 4 X05、X11 专项

### 4.1 X05（终端跨隔离侧为何表现为贴边/朝向硬检查）

期望（`answers.md` 更新口径）：主标记 `可确认`（限案例数据）；verdict `blocking`、codes **只有** `connector_off_edge`；对题面给的两种解释**只能选 ②**（案例数据只声明这一个硬检查、隔离边界不在 v1 判分范围），选 ① 属过度归因；隔离本身 `待补`；真实工程分别核「机械贴边/插拔」与「电气隔离间隙/终端位置」两件事，都不能用离线分数代替；不得写成「隔离已验证/已违反」。

| 条目 | 期望 | R1 | R2 | R3 |
|---|---|---|---|---|
| 主标记 | 可确认 | 可确认 | 条件 | 条件 |
| verdict | blocking | 「按贴边/朝向硬检查报 fail」（=blocking） | blocking | 「该硬检查报 blocking 可确认」 |
| codes | 只有 `connector_off_edge`（题面未给名，写描述算 ✓） | 描述「贴边/朝向硬检查」，隔离无独立项 | 同 | 同 |
| ①还是② | **只能 ②** | 结论段「非判分器懂隔离」（≈②），机制段「几何上表现为朝向/贴边偏移」（≈①）→ 自相矛盾 | 「表达受限」→ 偏向 ① | 「被压成几何投影」→ 偏向 ① |
| 隔离本身 | 待补 | 「隔离 `NOT RUN`」 | 层叠/间距/材料组/污染等级 `NOT RUN` | 隔离电压/间距规则 `NOT RUN` |
| 两件事 | 机械贴边 + 电气隔离间隙/终端 | 隔离间隙 + 终端拓扑（缺机械侧） | 隔离间隙 + 终端拓扑（缺机械侧） | 隔离间隙 + 连接器朝向/插拔 ✓ |
| 离线不可替代 | 必须写 | ✓ | ✓ | ✓ |

我的判定：R1 `✓△✓△✓`；R2 `△△✓△✓`；R3 `△△✓✓✓`。

- **答案是否站得住：方向站得住**——隔离边界确不在 v1 判分范围，`connector_off_edge` 只证明「没贴声明边」，不能扩写成隔离结论；选 ① 确属过度归因。但有两点需要修：
  1. **证据句与 JSON 不符**。`answers.md` 写「案例数据只声明了这一个硬检查」，而 `P4-COMM` 的 `checks` 里**只有 `ck-decoup`**（去耦焊盘距离，且该检查通过）；`connector_off_edge` 是 rubric 级的隐式硬规则（由 `board.connectors` + 容差产生），并不在 `checks` 数组里。字面上「只声明一个硬检查」容易被读成「checks 里有 connector 检查」。建议改成「本案例 verdict 只由一个硬几何规则产生，`checks` 中无隔离项（也未声明车辆/爬电检查）」。
  2. **复合结论的主标记口径不一致**。X05 是「贴边可确认 + 隔离待补」的复合结构，答案给 `可确认`；X18 同样是「指南合理可确认 + 铜/过孔不可证」的复合结构，答案给「`条件` + `NOT RUN` 混合」。同一结构两种主标记，R1 与 R2/R3 的分歧正是这个不一致的投影（1 人可确认、2 人条件）。建议在「标记口径」里加一条复合结论规则（例如：代理项可确认、真实项待补时，主标记按**决定行动的那一层**取，并在题面要求两段写）。

### 4.2 X11（反馈取样点在离线判分里的盲区）

期望：主标记 `条件`，且必须两段（可确认的几何/配置事实 + 尚缺的条件）；结论落在「离线能否判两个取样点等价」；不得笼统标 `待补`；机制缺「取样点相对输出电容/负载的电气位置」语义；行动给显式检查或只改取样点的成对案例；未知列纹波/瞬态/补偿/寄生/跨功率区并 `NOT RUN`。

| 条目 | 期望 | R1 | R2 | R3 |
|---|---|---|---|---|
| 主标记 | 条件（两段） | 可确认 | 可确认 | 可确认 |
| 落在被问的事 | 「不能判等价」=条件 | 「离线不能区分两个取样点」 | 同 | 同 |
| 两段结构 | 必须有 | 单段 | 单段 | 单段 |
| 机制 | 缺「取样点电气位置/拓扑」语义 | 缺「相对输出电容/负载的电气位置」✓ | 缺「取哪段铜」✓ | 缺网络内拓扑/电流路径 ✓ |
| 补充检查 | 显式距离检查 或 只改取样点的成对案例 | 成对案例 + 几何近似 ✓ | 增取样点+网络/铜皮检查，或成对 ✓ | 「取样点在输出电容焊盘之后」+ 成对 ✓ |
| 未知 | 纹波/瞬态/补偿/寄生/跨功率区 `NOT RUN` | 只 1 项（铜阻抗） | 2 项（输出电容位置、开尔文待补） | 1 项（铜流 `NOT RUN`） |

我的判定：R1 `△✓✓✓△`；R2 `△✓✓✓△`；R3 `△✓✓✓△`。

- **答案是否站得住：内容站得住，主标记有争议**。三段内容（几何事实可确认 / 等价性需条件 / 不得标 `待补`）都对，v2 的修订目标（防「待补」误标）**达成**：三人无一标 `待补`。但「主标记=条件」**不能从题面唯一推出**：题面问的是「离线判分为什么区分不了、缺什么」，直接回答「区分不了」是关于**判分器能力边界**的确定否定命题，按「`可确认` = 仅凭题给数据/几何就能判是/否」应属 `可确认`；`answers.md` 的规则 3 把「不能判=条件」写死，与同一张表里「`可确认` 仅凭题给数据就能判」存在张力。三人一致选 `可确认` 就是这种张力的投影，不是三人同时犯了同一个低级错。建议：v3 题面把标记落点写成「若你判断的是**判分器能否区分**→`可确认`；若判断的是**两个取样点是否等价**→`条件`」，或答案并列接受两读并把评分改为只查「是否落在被问的事上 + 是否两段」。**我不因这条改答案口径**：本轮仍按 `answers.md` 记 `△`。

## 5 发现（现象 → 归因 → 建议）

1. **结论类型 60% 是所有维度的洼地，24 格失分里 23 格是标记位移，内容几乎全对。** → 主要是**题面/答案口径问题**：X01/X02/X06 的答案主标记是「限案例数据的可确认」，但这三题的题干同时追问「哪些必须等真实板」，按「标记口径」规则 2 读就会写成 `条件`；X10 答案自身写「条件（偏待补）」，三人统一写 `待补`。 → 建议 v3 在「试答要求」里加一句：「主标记按 **v1 判分器在本案例数据下的结论**取，不按真实板性能取」；答案对 X01/X02/X06 各加一行「若按真实板性能取，则为 `条件`」，对 X10 明确 `待补` 可接受。

2. **X05 的「①还是②」三人都没有正面回答。** → 作答问题为主（题面已把两种解释并列，但没要求「请选一个」），叠加题面问题（判据只在答案里）。R1 甚至在结论段选了 ②、机制段又写成 ①。 → 建议题面直接要求「请明确选①或②，并给出可核验依据」；答案为选择补一条可核验事实（`checks` 里无隔离项）。

3. **X05 答案的证据句与案例 JSON 不一致。** → 答案问题：`P4-COMM` 的 `checks` 只有 `ck-decoup`（通过），`connector_off_edge` 是 rubric 隐式规则，不是「声明的检查」。 → 建议改写该句；否则「只声明一个硬检查」这种口径无法被作答者核验，也让「证据」维在该题失去区分力。

4. **X11 的标记口径不可从题面唯一推出，三人一致被判 `△`。** → 题面/答案问题（见 §4.2）。 → 建议按「能力边界 vs 等价性」二分写清，或答案并列接受两读；否则该题在跨评审一致率里会稳定贡献 3 个 `△`，噪声大于信号。

5. **成对案例的 verdict 逐份给分仍是薄弱点（X07 R3、X13 R2/R3）。** → 作答问题：题干已说「只改一个条件」，但作答只给一个统一 verdict，没写「原案例 review / 成对案例 acceptable」。 → 建议题面把 X07/X13 的问法改成「A 布局判什么？B 布局判什么？」并在答案里并列两份 verdict，避免只写「条件」就得分。

6. **v2 的两项修订确实生效：** 60 份作答**零臆造 code**（题面未给 code 名时都写 check_id / 规则描述）、X01/X08 的「过度例」**三人齐备**、X11 **无人误标 `待补`**。 → 题面问题已修，属正面结论。 → 建议保留这三条约束，并在 v3 沿用；同时把「X20 的 verdict 与结论标记要分开写」补进要求（见下条）。

7. **X20 的「结论标记」与「判分器 verdict」被混写（R1「verdict 待补」、R3「应为无法评估」）。** → 作答问题 + 答案问题：`answers.md` 该题结论是 `待补` 而 verdict 是 `blocking`，题面问「什么 code、什么 verdict」时没有区分这两个字段。 → 建议题面要求「分别写：结论标记 / 判分器 verdict / codes」三栏，答案也按三栏给。

8. **`未知` 维 90%：失分集中在「整段缺失」与「只列 1 项」（R1 的 X04/X06/X14/X15 无未知段；X11 三人各只列 1–2 项）。** → 作答问题（格式），但题面只在试答要求 4 说「不确定就写待补/NOT RUN」，未要求每题必有未知段。 → 建议二选一：要么格式要求里写明「每题必须有『未知/NOT RUN』一段」，要么评分时对无未知段不再扣分——现状是格式噪声混进了判别力。

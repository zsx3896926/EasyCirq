### 1.2 五维与档位

维度沿用 [exercises-pcb/README.md](../../../easycirq/references/engineering-deepdives/exercises-pcb/README.md) 与读法文档 §4：结论类型 / 机制 / 证据 / 行动 / 未知。

- **结论类型**：看**单一主标记**是否等于 answers v3 主标记，且关键判定子问是否答对（verdict、codes、是否翻转、假通过/误报方向、规则 0 落层）。
  - `✓`：主标记一致（允许一句附加说明），且该题要求的判定层结论齐全正确。
  - `△`：主标记**位移一级**（`可确认`↔`条件`）但判定层事实正确且（对 `条件`）写了两段；或主标记正确但**关键子问缺失/判断错**（如漏答判据改写后果、判分器 verdict 写错）。
  - `✗`：`verdict`/翻转方向判错，或主标记位移两级（如应 `可确认` 写 `待补`），或违反规则 0 把真实工程条件抬成主标记。
- **机制**：是否说出电流回路/回流、耦合路径、热路径、机械干涉等物理机制，而不是重复 code。
- **证据**：是否指向可核对锚点（案例/成对 id、finding code、`check_id`、代理指标、PL 条目、指南条款）。**题面未给 code 名时写 `check_id`/规则描述记 `✓`；臆造不存在的 code 记 `△`。** 只复述几何事实、或把“依据”写成缺项清单记 `△`。
- **行动**：修复动作与结论匹配（`blocking` 先改硬约束、`review` 先改主导项、不过度整板重排）；X01/X08 的“过度例”为必答项，缺答记 `✗`。
- **未知**：是否列出离线判不了项并写 `NOT RUN`（或等价的“待补/待验证”状态）；只列项不标状态记 `△`，整题缺未知字段记 `✗`。

### 1.3 口径上的两处张力（先声明，§4/§5 展开）

1. answers v3 规则 0 说“主标记落在**判分器判定层**”，但 X12–X17 主标记仍写 `条件`；而 X12–X15 的题面问句恰是判定层的“两份布局 verdict 会不同吗”。本评审**以 answers.md 主标记为准**计分，因此三人在这几题上的 `可确认` 一律记位移（`△`/`✗`），并在发现 §5-2 说明这更像口径冲突而非能力差。
2. answers v3 内部不一致：X12/X14/X15 标 `条件`，但「成对案例参考答案」表里同一对案例 PC02/PC04/PC01 标 `可确认`。三人作答正好落在“成对表口径”一侧。

| T1 | **未识别** | “两份 verdict 相同（均不触发软失败）” | **✗** |
| T2 | **未识别** | “两 verdict 不会不同（软检查通过、HPWL 软阈值内）” | **✗** |
| T3 | **未识别** | “通常两份 verdict 相同（都通过）” | **✗** |

三人**都答对了**“HPWL 变差 ≠ 布局变差”“分区/回流优先于线长观感”“HPWL 超阈才降为 review”，且都在 X07 对同一对案例写出“原布局 review → 成对 acceptable”。也就是说：**成对结论本身在 X07 答对、在 X13 反向答错**，属题面“两份布局”指代不明造成的自相矛盾，不是机制缺失。按专项要求记 **3/3 ✗**（结论维同记 ✗）；建议 v4 在 X13/X12/X14/X15 显式写“改动前（原案例）与改动后（PAIR 变体）的两份布局”。

## 5. 发现

1. **规则 0 精准生效，且只在该生效处生效。** X01/X02/X06 共 9 个结论单元 8 ✓ / 1 △（唯一的 △ 是 X01-T1 漏答中心距子问，不是主标记问题；第二轮这三题按 README 记载是“三人全 △”），X10 主标记 3/3 `待补`、X11 主标记 3/3 `可确认`。题面一句“主标记落在判分器判定层”把“真实板条件当主标记”的诱导清掉了，说明这三题原先的失分确实来自题面而非知识。
2. **但结论维总分反而下降（53.3% < 第二轮 61.7%/60.0%），失分整体迁移到“有意取舍”簇。** 结论维按期望主标记拆分：`条件` 题（X07/X08/X09/X12–X18）30 单元里仅 7 个 ✓ = **23.3%**；其余 `可确认`/`待补` 题（X01–X06/X10/X11/X19/X20）30 单元里 25 个 ✓ = **83.3%**。X12–X15 + X18 的 15 个单元**无一 ✓**（10 个标记位移 △ + 5 个 ✗），原因单一：三人一律按判定层标 `可确认`，而 answers v3 仍把这四题标 `条件`。更关键的是**答案自身不一致**——X12/X14/X15 标 `条件`，而「成对案例参考答案」表的 PC02/PC04/PC01 对同一对案例标 `可确认`。这是 v4 必须收敛的口径冲突，不应记在试答者头上。
3. **X13 是三人一致的单点失败，且与各自 X07 自相矛盾。** 三人都答对 HPWL 语义却都否认翻转；`benchmarks.json` 的 P3b rationale 明确写“verdict 从 review 翻转为 acceptable”。根因是 X13 题面“两份布局”没有明说指成对 before/after，而 X12/X14 同类问句又确实存在“同一版本两次判分”的读法。
4. **机制维已饱和（60/60 = 100%）。** 20 题 × 3 人全部说出回路/耦合/热/机械机制，包括 X12 的“SW 铜面积/散热/测试点/反馈通道被挤”和 X15 的“过孔共用/参考层开槽”。五维里机制不再是区分项，剩余噪声集中在标记与格式。
5. **证据/行动/未知的 6 个失分单元全部是“字段完整性”，不是“不知道”。** 分别是：X07-T1 依据写成缺项清单、T3 X08 无依据字段、T3 X20 把 `missing_placement` 记成 `placement_missing`（唯一臆造 code 的样本）、T1 X05 行动漏机械侧贴边、T2 X08 无未知字段、T2 X10 未标 `NOT RUN`。→ 题面“每题五栏”的要求对格式的约束力弱于内容，建议作答模板固定五栏占位（缺项也必须写 `NOT RUN`）。
6. **X05 的 ①/② 归因仍是薄弱点，但比第二轮好。** T1/T2 明确选②并把主标记限定在 `connector_off_edge`（T2 甚至写了“非判分器故意合并”）；T3 却混述“多类缺陷压进一个代理”；T1 行动漏机械侧“贴边”。题面 v3 只给到“该案例的判定只声明了一个与连接器贴边/朝向有关的硬检查”这一层，而 code 的真实来源（`board.connectors` + `rubric.connector_edge_tol_mm`，`checks[]` 只有通过的 `ck-decoup`）在答案里——**题给的这句已足以支撑单选②**，但三人中仍有一人读成①。
7. **三名试答者高度同构，同错同对。** 5 题 25 单元全满、X13 三人同错、X14/X15/X18 三人同位移、X08 三人同位移；只有 5 题出现个体分化（X01/X05/X16/X17/X20）。这与第二轮“三份作答高度同构”一致：样本只能用来发现口径噪声，不能推断能力差异。

## 6. 限制

- **单评审、无双人交叉**：60 个评分单元全部由本评审独立判定；第二轮双评审一致率 92.7%（README）提示“结论维位移 vs 缺失”的边界每轮可有 1–3 单元/人的分歧。本报告的 △/✗ 边界已在 §1.2 写明，便于 B 评审对齐或反驳。
- **未复跑判分器**：案例期望取自 `benchmarks.json` 的 `expected`（P1/P1b/P2/P2b/P3/P3b/P4/P5/P6/P7/P8/P8b 均已逐条核对）与 `rationale`（P3b 的 22.8→12.7 mm 已核对），但未执行 `scripts/pcb_placement_benchmark.py` 验证输出。
- **按要求未读第二轮评分与评估文件**，因此不与第二轮逐单元对齐；“第二轮 61.7%/60.0%”仅引自 README，两轮题面不同、不可直接比较。
- **隔离是约束式而非容器**（仅有“只读题目副本、禁读仓库/答案/联网/运行命令”的自述与“读过文件”一行），无法排除训练语料记忆或同族模型的共同先验；三人结论高度同构时，本报告只能记为“口径噪声”，不能作为能力结论。
- **X12–X18 的记分依赖 answers 主标记**：若改按规则 0 的简短表述重判，结论维会上升约 10–15 单元（X12-T1、X14×3、X15×3、X18×3，以及 X08/X09 部分单元），这属于口径选择而非评审分歧，已在 §5-2 单列。
- 本报告只评“是否与当前答案一致”，不评答案本身在真实工程中是否正确；所有真实检查一律 `NOT RUN`。

## 1. 方法与口径

### 1.1 独立性

- 只按 v3 题面 + 当前 `answers.md` 评分，不参考第二轮分数与评审 A 的口径。
- 用 `benchmarks.json` 的 `expected.verdict`/`expected.codes`、`checks[].id`、`board.connectors`、`rubric` 核对事实（如 P4-COMM 的 `connector_off_edge` 来自 `board.connectors` + `rubric.connector_edge_tol_mm`，不是 `checks[]` 项）。
- 题面未给 code 名时，作答写 check_id、规则描述或「按契约枚举」均按 `✓`；臆造不存在的 code 记 `△`。本组作答未发现臆造 code。

### 1.2 五维与符号

`✓` 达标；`△` 部分达标/有实质缺口；`✗` 未达标或方向错误。

| 维度 | 本轮判定口径 |
|---|---|
| 结论类型 | 主标记必须与当前 `answers.md` 逐题段一致，且只有一个主标记、落在被问结论上；再核对被问主结论（verdict、是否翻转、能否判）。**主标记错记 `✗`；主标记对但主结论/必需结构缺失记 `△`。** |
| 机制 | 说出电流回路/回流、耦合路径、热路径、机械干涉等因果链，而不是复述 code。 |
| 证据 | 指到案例事实、check_id、规则描述、code 或缺失项；只写空泛判断记 `△`，与案例数据冲突记 `✗`。 |
| 行动 | 修复动作与结论匹配；`blocking` 先改硬约束、`review` 先改主导项；X01/X08 的过度例为必答。 |
| 未知 | 列出离线答不了的项并标 `NOT RUN`；漏项较多记 `△`，完全未列记 `✗`。 |

### 1.3 v3 规则 0 的落地

- 主标记问「判分器在题给数据下能判到什么程度」；真实层叠/屏蔽/热/3D/手册写进「未知」并 `NOT RUN`，不改变主标记。
- 例外：题目直接问「能不能插拔/能不能上量产/能不能布通」时按该问取（X10 → `待补`，X19 → `待补`）。
- X11 按 v3 口径：主标记 `可确认`（离线区分不了两个取样点）+ **条件副注**（两点是否等价/哪一个是正确调节点取决于拓扑）。只写前半段记 `△`。
- X13 另按任务要求专项核对成对结论：`P3-ANALOG`（review）→ `P3b-ANALOG-PAIR`（acceptable），HPWL 变差但 verdict 翻转。

### 1.4 特殊处理

- **verdict 用词**：T3 在 X03/X04 把判定写成 `fail`，语义等同硬检查失败（blocking），不单独扣分；X20 把 `verdict` 写成 `待补` 则扣分（契约 verdict 应为 `blocking`，`待补` 是结论类型）。
- **X12/X14/X15 的答案内部冲突**：逐题段给 `条件`，同文件「成对案例参考答案」表给 `可确认`（PC02/PC04/PC01）。本轮按「逐题段为准」应记 `✗`；考虑同文件自相矛盾、作答三人都落在 `可确认`，折中记 `△`，并在 §5 单列。若严格按逐题段，三人的结论 `✓` 数不变（仍各 10/20），但 `✗` 会增至 T1 6、T2 7、T3 9。
- **X08 的规则 0 张力**：`answers.md` 逐题段为 `条件`；三人写 `可确认（代理层）` 且都说明「代理只证几何跨度、不证误触发」。按当前答案记 `✗`，但这是标准侧边界未写清的高风险点，见 §5。

## 5. 发现

1. **规则 0 在目标题上生效。** X01/X02/X06 共 9 个主标记全部 `可确认`（X01 T1 仅子问缺失），X10 3/3 `待补`，X11 3/3 `可确认`。第二轮「X01/X02/X06 三人全 △」的题面诱导已被 v3 消除；这三题不再需要靠「真实板条件」争标记。
2. **X08/X18 成为新的 0/3。** 三人均把「判分器能判的局部」（loop_span 代理超阈 / 器件包围盒净空）当成整题主标记，写 `可确认`；标准为 `条件`。X08 的规则 0 张力最明显：题目问「是否真的误触发/振铃」，三人却把代理层结论当主标记；X18 问「全层铜/过孔/固定件状态」，三人把 NOT RUN 写在未知里但主标记仍 `可确认`。建议 v4 给「真实工程结论题」补一条规则 0 反例，或复核 X08/X18 的答案是否应改 `可确认`。
3. **成对翻转题是结论维度最大失分区。** X13 0/3、X12 1/3（仅 T1）、X14 3/3、X15 3/3。规律是：硬检查对（X14，blocking→acceptable）三人都会；软检查对（X12 `loop_span`、X13 `distance_far`）因题面未给基线失败而漏翻转。X12/X13 的题面应显式给「原布局软检查失败」或「基线 verdict」。
4. **`answers.md` 内部口径冲突（X12/X14/X15）。** 逐题段为 `条件`，成对案例表 PC02/PC04/PC01 为 `可确认`；同文件两处对同一对案例给出不同主标记。本轮折中记 `△` 并在 §1.4 给出严格口径的替代统计（结论 ✓ 不变，✗ 增至 6/7/9）。这是标准侧缺陷，不是作答者缺陷，v4 应统一并说明「翻转层」与「工程结论层」的区别。
5. **X13 题面信息不足导致三人同错。** 见 §4.4；这是本轮最明确的「题面而非能力」问题，建议优先修。
6. **X05 的 ①/② 仍被混写。** T2「案例数据只声明一个……缺陷被压进代理」、T3「案例只声明一条……多类缺陷压进一个代理」都把两种解释揉在一起；只有 T1 落到「案例只声明一个贴边/朝向硬检查」。题面的「是 A 还是 B」问法容易被答成「两者都有」，建议改成「只能选一个，并说明另一个为什么错」。
7. **内容层仍近饱和，标记层是主要噪声。** 机制 98.3%、证据 98.3%、行动 93.3%、未知 95.0%，而结论只有 50.0%；16 个 `✗` 中 15 个在结论维度。这与 README 记录的第二轮判断（「内容层接近饱和，标记口径是主要噪声源」）一致。本轮 B 的结论 50.0% 低于 README 记录的第二轮 B 60.0%，但 v3 题面、评审严格度与折中口径都不同，**不可直接比较**。
8. **X20 仍把 verdict 与结论类型混在一起。** T1 写「verdict 待补」、T2 写「verdict=待补/insufficient，不判 blocking」；标准是 `missing_placement`（硬检查）→ `blocking`，`待补` 只是结论类型。T3 的「按契约取 blocking/不可判」最接近。建议在答案/题面固定 verdict 枚举，并加一句「verdict=blocking 与结论类型=待补 不矛盾」。

## 6. 限制

1. **单评审、单遍评分。** 300 个单元由 B 一人判定，`△/✗` 边界（尤其 X05、X08、X11、X20）带主观性；无评审 A 对照，一致率无法计算。
2. **标准侧不一致会传导到分数。** X12/X14/X15 的逐题段与成对表冲突、X08 的规则 0 边界未写清；本轮用 `△` 折中，严格口径下结论 `✗` 会增加。若 A 采用严格口径，X08/X12/X13/X14/X15 会出现系统性分歧。
3. **3 个样本、高度同构。** 不能据此推断模型能力，也不作为认证或对外声明；隔离是约束式（禁读仓库/答案/联网/运行命令），无法排除训练语料记忆。
4. **只读指定材料。** 未读第二轮评分/评估与评审 A；未运行 `pcb_placement_benchmark.py`，verdict/code 以 `benchmarks.json` 的 `expected` 为准；`blocking` 与 `review` 的判定没有实际执行验证。
5. **术语处理。** T3 的 `fail` 视为 `blocking` 语义，不扣分；`NOT RUN` 与 `待补` 未完全等同（X04 T2 因此只记子项提示，未扣结论分）。
6. **CSV 为 B 的单方评分**，与正文表一致；与 A 的差异应在汇总时逐题对齐，而不是直接平均。

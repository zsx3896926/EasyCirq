## 1. 方法 / 口径

### 4.3 残留争议单列（标准侧，不算作答错）

以下 5 条是我判断“当前 `answers.md`/题面仍未自洽”的点。**未改答案**，仅说明理由与建议。

**(a) X05 主标记：答案 `可确认`，规则 0 字面应为 `条件`（高）**
X05 第一问句是“**为什么**‘终端跨隔离侧’会表现为贴边/朝向类硬检查？”，属规则 0 第二档“机制与决定量 → `条件`”！答案却给 `可确认`（并自注“限案例数据 / 只覆盖 connector_off_edge”），且规则 0 的示例清单里列了 X08/X09/X17/X18 这类机制题给 `条件`，独独没有 X05。答案正文还写“如果把‘隔离是否合规’当作被问结论，主标记应为 `待补`”，说明该题被问对象本身有歧义。三人一致答 `条件`、内容（选②、只一个硬检查、两件事不能用离线分数替代）都对，却各丢 1 格结论分。**建议二选一**：把 X05 第一问句改成“判分器应给什么 verdict 与 codes？为什么只有这一个 code？”（判分层，`可确认` 成立），或把答案键改为 `条件`（工程层）+ verdict 副注。

**(b) X20 主标记：答案 `待补`，规则 0 字面应为 `可确认`（高）**
X20 第一问句是“判分器应报什么 code、什么 verdict？”，是典型判分层问题，按规则 0 应为 `可确认`；而且答案自身给出的是确定结论（`missing_placement` 硬检查 → `blocking`，补默认值=假通过），并非“信息不足无法形成判断”（`待补` 的定义）。但同时答案第 4 子问“缺失类 finding 与几何越界类的结论类型有什么不同”又要求“缺失类=`待补`”——**答案内部就是两难**。三人一致写 `可确认`（U2 还写对了 blocking；U3 写“关键器件 blocking、其余 review”；U1 写“不可判/失败”），各丢 1 格。**建议**：把第一问句改成“缺 placement 的候选布局还能不能判？缺失类 finding 的结论类型是什么？”（数据缺口层先行，`待补` 成立），并在答案里把“判分器应报 blocking”明确写成**副注而非结论类型**；否则应改键为 `可确认`。

**(c) X10 第一问句层级（低；未造成失分）**
X10 第一句“离线判分不报错能说明什么、不能说明什么？”是判分层问题，按规则 0 字面应 `可确认`；答案按第三句“应标 `条件` 还是 `待补` / 能不能插拔”取 `待补`。三人均按题面后半段答 `待补`，未失分。**建议**把“能不能插拔/能不能上量产”提前为第一问句，消除读法竞争。

**(d) X11 第一问句是“为什么…”但与 `可确认` 并存（低；已被题面自身化解）**
X11 第一问句“为什么离线判分可能区分不了这两个取样点？”形式上是机制题（规则 0 应 `条件`），但题面在该题末尾有显式指令“结论类型必须落在被问的那件事上（离线判分能否区分取样点）”，答案也专设“为什么主标记是可确认”一段。三人均答 `可确认`，未失分。**建议**在规则 0 补一句“题面另有显式标记指令时以题面为准”，避免规则文本与题面互斥。

**(e) X13 数值口径不一致（极低）**

## 5. 发现

1. **结论维 53/60 = 88.3%，为四轮最高**；且失分 7 格中 6 格（X05×3、X20×3）全落在两个“标准侧争议题”，剔除后 **53/54 = 98.1%**。真正的作答内容失分只剩 1 格（U3-X12 把 review→acceptable 读成“verdict 相同”）。继续修订的收益已不在题面诱导，而在**答案键与规则 0 的对齐**。
2. **规则 0 在四个原本最易位移的题上完全生效**：X01/X02/X06/X07/X12/X13/X14/X15/X16 九题判分层全部落 `可确认`，X08/X09/X17/X18 四题工程层全部落 `条件`，X10 全 `待补`，X11 全 `可确认`——v3 的“条件簇口径冲突”在本轮无一处复发。
3. **X13 专项 3/3**：题面补基线（v4 修订②）确实消除了第三轮 0/3 的根因；三人均同时答出“翻转项是 ck-analog 距离软检查”、“HPWL 变差不降级”、“HPWL 超阈值才降级”三个要点，说明该题的检验目标已达成。
4. **X05/X20 的三人同错是口径损失而非能力损失**：两题的机制、证据、行动、未知四维 30 格中 28 格 ✓（仅 U1-X05 行动、U2-X05 机制各 1 △），结论维却 6/6 全错——这正是“同一题两种读法”的残迹，且都可用改第一问句一键修复。

## 6. 限制

- **单评审、无交叉校验**：本轮按要求未与其他评审交流，△/✗ 的边界（尤其“漏一个子问算 △ 还是 ✓”）带主观性，若换 B 评审，行动维可能有 ±2 格漂移。
- **3 个样本**：三份作答结构同构，无法区分“模型能力”与“题面诱导”；本文所有比例只描述这 60 个单元，不作能力声明。
- **只做纸面核对，未运行 `pcb_placement_benchmark.py`**：代码级事实（verdict/codes/距离）取自 `answers.md` 与 `benchmarks.json` 的 `expected`/`rationale`，未独立复算几何。
- **争议题的双计**：正文同时给出“按答案键”的 88.3% 与“剔除 X05/X20”的 98.1%，后者是口径判断而非评分结果；对外引用时应注明口径。
- 隔离是**约束式**（禁读仓库/答案/联网/运行命令），无法排除对训练语料的记忆；`读过文件：` 行三人都只有题目副本路径，符合约束。
- 本文未修改 `answers.md`、题面或任何案例数据；争议条目仅为建议。

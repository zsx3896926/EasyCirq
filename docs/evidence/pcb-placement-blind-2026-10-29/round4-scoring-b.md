## 1. 方法 / 口径

**1.1 评分基准。** 结论类型一律以当前 `answers.md`（v4）每题的主标记为准；主标记之外另查三件事：

1. **规则 0（取第一问句所在层）**：把每题的**第一个问句**抽出，按规则 0 三层（判分层→`可确认`；工程后果/机制→`条件`；量产/布通/插拔→`待补`）复核答案键自身；
2. **单主标记**：是否只写一个主标记（复合写法不计主标记，副注另计）；
3. **`条件` 两段**：标 `条件` 的单元是否写成"可确认的几何/配置事实 + 尚缺条件（NOT RUN）"两段。

**1.2 五维判定细则（本轮固定，便于复算）。**

| 维度 | ✓ | △ | ✗ |
|---|---|---|---|
| 结论类型 | 主标记与 v4 答案一致，且被问 verdict 的陈述正确 | 主标记对、但被问 verdict 陈述错 | 主标记错（含把 review 说成 acceptable 之类位移） |
| 机制 | 说出正确物理机制（回路/回流、耦合路径、热路径、机械干涉、判分语义边界） | 只复述 code、只说结论、或机制方向对但缺该题核心机制 | 机制错 |
| 证据 | 出现案例 id、finding code、check_id、容差/阈值、规则描述（题面要求 3：未给 code 名时写 check_id/规则描述即可） | 仅泛称"案例/题面"，无可核对细节 | 指错案例/规则 |

**1.3 争议单元处理。** 若答案键与规则 0 / 题面自相不一致，该单元在表中标 `*`，五维仍按答案键严格记（CSV 亦记严格值），但在统计里**另给"扣除争议"口径**，且**不计作作答错**——争议清单见 §4.3，不改答案。

### 4.3 残留争议（标准侧，单列，不算作答错，不改答案）

**S1（硬冲突）X05 主标记 `可确认` vs 规则 0 → 应为 `条件`。**
X05 第一问句是「**为什么**"终端跨隔离侧"会表现为贴边/朝向类硬检查？」——按规则 0 的枚举，先问"机制/为什么"落工程层为 `条件`（X08「机制+决定量」、X18「为什么全层净空可能合理」都据此记 `条件`）。答案键却记 `可确认`，并在正文用"主标记只覆盖 `connector_off_edge`"解释；该解释对"判分器只声明一个硬检查"这一**事实**成立，但与规则 0 的字面分层冲突。三人 3/3 答 `条件`，U3 还专门写了"这不是把多种缺陷压进一个代理，而是案例数据只声明了一个硬检查；两者必须分开说"（正是答案要件）；U1/U2 也都点出②读法。**建议**（二选一，不改本轮分数）：① X05 主标记改 `条件`，`connector_off_edge` 事实写副注；② 规则 0 增例外"问的是判分器为何这样判/检查清单事实 → `可确认`"，并把 X11 的相似说明并入同一例外。

**S2（硬冲突）X20 主标记 `待补` vs 规则 0 → 应为 `可确认`。**
X20 第一问句是「判分器应报什么 code、什么 verdict？」——判分层，按规则 0 与同族题（X01/X03/X04 均"判分器应给什么 verdict"→`可确认`）应为 `可确认`；答案键记 `待补`（理由：`missing_placement` 是数据缺口）。三人 3/3 答 `可确认`，且三人都把 `missing_placement`→`blocking`、补默认值=假通过、缺失类与越界类结论类型不同写全了；答案键正文本身也同时写了"`待补`（数据缺口）"与"判分器应报 `missing_placement`（硬检查）→ `blocking`"，自洽但主标记与规则 0 相反。**建议**：① 规则 0 增"缺失类 finding / 数据缺口 → `待补`"例外（推荐，可同时修 X19 边界）；或 ② X20 改 `可确认`，把"数据缺口"写副注。

**S3（次，张力）X10。** 第一问句「离线判分不报错能说明什么、不能说明什么？」字面属判分能力层（类比 X11 应为 `可确认`）；答案键取 `待补`，理由是"题面直接问能不能插拔/上量产"。本轮三人 3/3 均答 `待补`，未产生分歧，但题面最好把"能不能插拔"明确为主问，否则下一轮换人可能再翻。

**S4（次，文本细节）答案键内部瑕疵。**
① X06 标注「`可确认`（工程判断层）」——主标记符合规则 0（第一问句问硬/软检查归属），但"工程判断层"与「`可确认` = 仅凭题给数据可判」的定义、以及规则 0 的"判分层"表述有张力，建议删去该括注；② X13 正文写 `22.76 mm`，而题面与 `benchmarks.json` 的 rationale 均写 `22.8 mm`（应为精确值与四舍五入之差），建议统一有效位，避免下一轮评审按数字对错扣分（本轮三人用 22.8 均正确）。

**S5（口径提示，非题面矛盾）证据维宽/严。** 题面要求 3 允许"写 check_id、规则描述"替代 code 名，答案键的评价表却写"能指出案例 id、finding code、检查 id 或 PL 条目"，未说是否**必须**有案例 id。U3 全篇多用"案例/成对案例/规则描述"而少写 id：按宽口径（本轮采用）证据维 19/20；若收紧为"必须出现案例 id 或 code/check_id"，U3 只有约 4–6 题达标（X01 的 check_id、X02/X08 的 `loop_span`、X13 的 `ck-analog` 及 X03/X04 的规则边界），证据维会降到 5±1/20，统计随之显著变化。跨轮比较证据维前应把这条口径写进答案键。

## 5. 发现

1. **v4 的 X13 基线修订完全生效**：成对翻转识别从第三轮 0/3 变为 3/3，四人四项（22.8→12.7、review→acceptable、翻转项=`ck-analog`、HPWL 变差不降级且超阈值才降级）齐全。这是本轮可直接归因到题面（而非答案或评审）的改善，建议保留并作为"题面泄题程度"的对照点。
2. **X01/X02/X10/X11 主标记 12/12 一致**：v2 的"条件簇诱导"与 v3 的"判分层口径"两轮修补后，这四类题的标记位移在本轮未复现；配套证据是 X02 三人都不再把软代理说成"已证实失效"。

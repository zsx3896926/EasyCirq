## 1. 方法与口径

### 1.1 判分基准
- **结论类型以当前 `answers.md` v5 为准**：主标记取该题「结论」行的单一标记（X05 = `条件`、X20 = `可确认`、X10/X19 = `待补`、X08/X09/X17/X18 = `条件`、其余 = `可确认`），并核对规则 0「第一问句所在层」。
- **单主标记**：每题只认一个标记；复合写法按主标记计，附加说明另计（本轮 60 份均为单标记，无违规）。
- **`条件` 两段**：必须同时写出「可确认的几何/配置事实」+「尚缺的条件」，只写一段记 △。
- **code 名**：题面未给 finding code 名（v4 已删 PL 编号与 code 提示），写 check_id、规则描述或「题面未给名、需按契约枚举」即算证据合规（规则 3）；本轮无人臆造英文 code。
- **判层细节（verdict 层级）不计入结论维**：结论维只判三类标记的区分、规则 0 落层、单标记、`条件` 两段，以及「review↔acceptable 反转/翻转识别错误」这类实质性结论错误（沿用读法文档 §4「不合格表现」的两种情形）。X14 的 `blocking` 层级、X20 的 `blocking` 层级属「判层细节」，单列 §4.5；若强行计入，结论维为 56/60（见 §4.5）。

### 1.2 五维判据（✓ / △ / ✗）
| 维度 | ✓ | △ | ✗ |
|---|---|---|---|
| 结论类型 | 主标记与 v5 一致；单标记；`条件` 题两段齐全；无 verdict 反转或翻转误判 | 主标记对但结构缺项（两段缺一、标记复合、层级自相矛盾） | 主标记与 v5 不同，或把 review 读成 acceptable / 漏掉成对翻转 |
| 机制 | 说出电流回路/回流、耦合路径、热路径、机械干涉或「代理只测几何」的物理机制 | 机制方向对但混入被答案明确否定的归因（如 X05 选①）、或只重复判定现象 | 只重复 code/verdict，无机制 |
| 证据 | 能指到案例 id、check_id/code，或与该案例唯一对应的检查语义（`loop_span`、`ck-analog`、bbox 相交、贴边容差、缺失规则） | 只写「题面说…/题面未给…」，无案例、无检查标识，无法回查 | 无任何引用，或臆造/错引 code |

| 未知 | 列出离线答不了的项并标 `NOT RUN`（DRC/布线/阻抗/热/装配等） | 列了缺口但不标 `NOT RUN`，或只列 1 项且无标记 | 用离线分数推断「能布通/能打样」，或不列任何缺口 |

### 1.3 特殊核对（本轮重点）
- 规则 0 落层：先问 verdict/「各判什么」/「会不会翻转」/「是不是缺陷」→ `可确认`；先问机制/实际后果/可不可接受 → `条件`；先问能布通/能插拔/上量产 → `待补`。
- X05 主标记应为 `条件`；X20 应为 `可确认`；X13 应识别 `ck-analog` 22.8 mm > 14 mm 失败 → 12.7 mm ≤ 14 mm 通过、`review` → `acceptable`、HPWL 变差不降级。

## 4. 重点专项

### 4.1 X05：主标记 3/3 归零，标准侧仍有一句残留；真正残余在机制层
- **三人一致**：V1/V2/V3 均 `条件`，与 v5 答案一致（第四轮此处是答案 `可确认`、三人 `条件` 的 3 个冲突单元）。**X05 主标记已归零。**
- **判层事实**：只有 V1 提到「该案失败判 blocking 属判分层」；V2/V3 未复述 `blocking` 与「codes 只有 `connector_off_edge`」。三人均未写出该 code 的名称（题面未给名，不算法错）。
- **机制维该题 0/3 通过**：答案对「压进一个代理 / 只声明一个硬检查」要求**二选一、只能选后者**，选①属过度归因（`connector_off_edge` 只证明连接器未贴声明边，不证明隔离好坏）。三份文本都保留了①：
  - V1：「是案例数据只声明一条贴边/朝向硬检查，**多种缺陷压进同一代理**」——两者并列断言，等于接受①；
  - V2：「没有隔离边界检查项，**因此跨隔离侧的问题被压进这个代理**」——②的事实 + ①的框架；
  - V3：「主因是……只声明了这一条……**代理压缩次之**」——②为主，但仍给①留了位置。
  三人都没有写成「隔离已违反/隔离已验证」，所以只是 △，不是 ✗；但这说明 v4/v5 只修了标记，没有把「只能选②」变成可评分差异。**建议**：答案 §X05 把「①/②」改成显式判分点（写①即机制维不通过），或在题面 2b 里加一句「代理能证明的范围不得扩写」。
- **标准侧冲突（答案-vs-规则 0）**：`answers.md` §X05 结论行已改为 `条件`，v5 头注也写 `条件`，但同节「**主标记的适用范围：**」仍留 v4 的句子「主标记 `可确认` 只覆盖 `connector_off_edge`」。同一节内 `条件` 与 `可确认` 并存，评分者若只读该段会把三人的 `条件` 判错。**建议删除或改写该句**（本轮按结论行与头注计，三人不受影响）。

### 4.2 X20：主标记 3/3 归零，但「判层 = blocking」仍 0/3
- **三人一致**：均 `可确认`，与 v5 一致（第四轮答案 `待补`、三人 `可确认` 的 3 个冲突单元已消除）。**X20 主标记已归零。**
- **判层事实未达**：答案「`missing_placement`（硬检查）→ `blocking`，不能给 `acceptable`」；契约 §3 硬检查表也确认 `missing_placement` 属「任一命中 → blocking」。三份作答实际给的是：
  - V1：「verdict 取 `review`/数据不完整，不判几何失败」；
  - V2：「verdict 不得通过：按完整性 `review`，若契约为硬检查则 `blocking`」（提到正确分支但主口径是 review）；
  - V3：「verdict 不可判通过（待补），不能算 pass」。
  三人都答对了实质（缺失≠几何越界、补默认坐标是假通过、缺失类落待补），但**没有人把缺失项按硬检查落到 `blocking`**。
- **归因**：题面没有交代「`missing_placement` 是硬检查 / 缺失项按硬检查处理」，v1 契约的硬检查表也不在试答可见范围内，所以这是**题面信息缺口**，不是纯作答错。若把它计入结论维，X20 三人均为 △（见 §4.5）。建议在题面补一句「缺失类 finding 按硬检查处理」，或在答案把 `blocking` 标为「按契约硬检查；若按数据完整性判则 review」。
- **标准侧**：X20 的「结论行 = 可确认」与 v5 头注、规则 0（先问判分器 code/verdict → 可确认）一致；**无新的答案-vs-规则 0 冲突**。

## 5. 发现

1. **v5 两处修订完全生效，且更像「答案追作答」而非作答变强**：X05（`条件`）+ X20（`可确认`）共 6 个单元从第四轮的冲突变为 6/6 一致；结论维从 53/60 升到 60/60。按 README 记录的「三人 3/3 同向」+ v4→v5 改的是答案，可推断第四轮三人给的就是 `条件`/`可确认`，本轮答案改成了他们的答案（此推断未用 round4 作答原文核对，见 §6）。因此本轮**不能**作为「模型结论类型能力提升」的证据。
2. **结论维已零区分度**：20 题 × 3 人主标记完全相同且全对，`条件` 两段、单标记、规则 0 均无违规。五轮之后该维度在本题集上饱和，继续加轮只会在非结论维和标准侧细节上打转。
3. **X20 的「判层=blocking」是本轮最大的实质缺口（0/3）**，且缺口来自题面未交代硬/软层级，而不是判断错误：三人都答对「缺失≠越界、不能补默认坐标、不能给 acceptable」，只是没落到 `blocking`。题面补一句即可闭环；否则下一轮仍是 0/3。
4. **X05 的「① 压进一个代理」仍 3/3 存在**（V1/V2 直接断言、V3 列为次要）：v5 只改了主标记，机制维该题 0/3 ✓，说明「代理能证明什么、不能证明什么」这条判分点还没有落到可评分的位置。
5. **证据维（93.3%）是三人最大差异源，但属引用密度而非内容错**：V3 每题给案例 id/check_id/实测数值；V1/V2 有 4 处只写「题面说…/题面未给…」（X07/V2、X15/V1、X17/V1、X17/V2），无法回查到案例或检查。若沿用更宽口径（提「题面规则」即算），三人证据维均近满分——**建议下一版在 README 写明证据维是否要求案例 id/check_id，否则不同评委会给出 10 个百分点的差异**。
6. **未知维的失分全是格式执行**：V1 在 X04/X05/X08/X17 未写 `NOT RUN`（其中 X05/X08/X17 完全没写未知项），V2/V3 20/20。这与判断力无关，属输出模板执行问题。
7. **判层细节有 4 个单元偏移**（X20×3、X14/V1），另有 X16/V3 一处口径细节（共用过孔写 `review`，答案作 `条件` 副注）：都不改变主标记，但会让「blocking 先改硬约束」的处置顺序失真（X14/V1 把两条硬检查的案例写成 `review`，会误导「先改主导软项」）。建议把「verdict 层级」也写进结论维的合格表现，或单列一个「判层」子维，避免它长期悬空。
8. **标准侧仍未清零**：`answers.md` §X05 残留的「主标记 `可确认`」一句必须删掉，否则任何只读该段的评分者都会把本轮 3 个正确的 `条件` 判错；另一处读法文档 §3 的 `review → 条件` 表与规则 0 相反，是本轮 60/60 之外最容易被下一轮评审踩到的坑。

## 6. 限制

- 每轮只有 **3 个样本**，三份作答高度同构（结论行逐字相同），**不能**据此推断模型能力，也不构成对外能力声明；本评分只说明「在这 3 份文本 + v5 答案口径下」的差异。
- 隔离是**约束式**的（禁读仓库/答案/联网/运行命令），非容器/权限强隔离，无法排除对训练语料或前几轮题面的记忆；本轮题面与第四轮同 SHA-256，作答者若见过第四轮讨论会被污染。
- 我按要求**未读** round2/3/4 的 scoring/evaluation，因此无法校验 A/B 一致率，也无法判断我的「证据维宽严」是否与上一轮口径相同；§5 第 5 条已把这一风险写明。
- 五维判分含主观边界（尤其「证据」与「未知」的宽严），我已把每条 △ 的理由写进 §2 备注，便于复核者逐条推翻。
- 本轮只用 `benchmarks.json` 核对 `expected.verdict/codes`（`missing_placement` 的硬检查语义另用读法文档 §3 核对），未运行判分器、未改任何案例数据；真实工程项一律 `NOT RUN`。

### 1.2 五维判分规则（本评审实际执行的判据）

| 维 | ✓ | △ | ✗ |
|---|---|---|---|
| 结论 | 单一主标记与基准一致，且其判分层/工程层表述不互相拆台 | 主标记对但并列第二个主标记、或把另一层写成主结论导致层位混淆 | 主标记错（如 `条件`→`待补`、`可确认`→`条件`），或把 `review` 说成 `acceptable` / 软代理超阈值说成"已证实失效" |
| 机制 | 说出回路/回流、耦合路径、热路径、机械干涉或判分器能力边界中的对应机制，且与该题缺陷方向一致 | 机制方向对但混入答案明确否定的解释（如 X05 的"压进即证明"式过度归因），或只重复 code/只列缺项 | 无机制、机制反向 |
| 证据 | 给出案例 id、check_id / finding code，或题面未给 code 名时给出规则描述（依试答要求 3） | 只有泛化引用（"布局指南""题给数据"），无案例 id/规则描述 | 臆造 code、或证据与结论不匹配 |
| 行动 | 修复与结论层位匹配（blocking 先硬约束、review 先主导项），必答项齐（X01/X08 过度例；X02 三项含 NOT RUN；X19 ≥5 缺项），不升级为整板重排 | 动作大方向对但含一处事实相反的判分含义（本轮 X13/W2） | 行动与结论矛盾、用默认坐标/删约束"修" |
| 未知 | 至少一处标 `NOT RUN`（或"未验证"）覆盖真实离线不可判项，不猜型号、不补默认值 | 列了缺项但全行无 `NOT RUN`，或只写"待补"而无具体缺口 | 断言已做/给出无数据支持的数值 |

补充口径：

- **R1 单主标记**：复合写法（如"可确认+待补"）不算主标记；另一层写进副注/未知不扣分。本轮三人均未出现复合主标记。
- **R2 `条件` 两段**（标记口径规则 2）：须有"可确认的几何/配置事实 + 尚缺条件"两段。X05/X08/X09/X17/X18 三人**两段全部齐备**，未触发扣分。
- **R3 code 名**：题面未给 code 名的题（X03–X08、X10–X12、X14–X20 多数），写案例 id + 规则描述或 check_id 即证据 ✓，**不要求**写出 `keepout_violation` / `missing_placement` / `body_overlap` 等答案 code。这是本轮证据维 60/60 的主要口径原因。
- **R4 标准侧隔离**：先判"答案 vs 规则 0/题面"是否自洽；若作答与答案一致而答案本身存疑，**按答案计 ✓**，冲突单列 §4.5，不计入作答错。
- **R5 未知维 substance-over-tag**：W2 的 X03/X04/X05/X06/X10/X14/X16 把 `NOT RUN` 写在「行动」而非单独「未知」栏，按实质计 ✓（缺项与 NOT RUN 都在同一行内）。
- 未给分的：书写风格、条目数、是否复述题面。

## 5 发现

1. **X20 的题面前提修复完全生效（本轮核心结论）。** 主标记 `可确认` 3/3、verdict `blocking` 3/3、code 一律按规则描述/check_id 写、假通过机制 3/3、无人给坐标；第五轮"三人因题面未声明硬/软属性而在 verdict 层写 review/待补"的失分模式归零（主标记层第五轮已 6/6 `可确认`，本轮只是维持）。这是"只在题面补一个属性、不改问句结构"就能消除标准侧前提缺口的干净案例。
2. **结论维 60/60，且三人同题全同。** 20 题主标记零分歧、零复合标记、`条件` 题两段全齐（X05/X08/X09/X17/X18 共 15 个单元）。连续第二轮满分（第五轮评审 A 100% → 本轮 100%，据 README 记录），说明规则 0 + 试答要求 2b 在当前题面下已可被稳定执行；继续靠加轮次提升结论维的收益为零（见限制）。
3. **失分整体下移到「未知」维（55/60，91.7%），且是书写纪律问题而非知识问题。** W2 的 X12/X15/X17/X20 与 W3 的 X20，缺项都在判定/机制里出现过，只是没落 `NOT RUN`；同一题 W1 写了 `NOT RUN` 就全 ✓。这与第五轮"未知 93.3/91.7"同一形态，两轮未见改善，说明"未知栏必须点名 + NOT RUN"是当前最值得固化的格式约束。
4. **W2 是本轮唯一有两处实质偏差的试答者：X05 机制过度归因、X13 行动答反。** 前者正是答案点名警告的"用贴边检查证明隔离缺陷"（① vs ②），后者是"HPWL 超阈值不降级"——题面已给"只有软检查失败才降级"，属可判定的明确错误，不是题面缺口。两处都不影响主标记，说明"主标记对"与"子问题对"已可分离计量，评分不宜只用结论维。
5. **X13 的翻转识别已进入稳定期（第五、六轮均 3/3）**：数值（22.8/12.7/14）、翻转项（`ck-analog` 而非 HPWL）、verdict 两端（`review`→`acceptable`）三要素三人全对。残留的只是"HPWL 超阈值"这一末问的边界理解，v4 补基线的收益已被完全吸收。
6. **X05 在 `条件` 口径下连续第二轮 3/3，但"解释 ②"与"解释 ①"的区分仍不稳定。** 三人都在判定里写了"案例只声明一个硬检查"（②），但 W2 在机制里又用 ① 的因果表述收尾——答案把这一区分列为 X05 的核心考点，实际作答里它更接近"一句话的措辞习惯"，v6 若想保留该考点，建议在题面明示"两选一"并要求写明"为什么不选另一个"。
7. **W1 与 W3 的作答几乎同构**（同样的五段式、同样的行动清单、同样的"规则描述代 code"），W2 也只在 6 处偏离。三份作答高度同构 + 结论维饱和 + 0 个 ✗，**不能**用于推断模型能力，只说明这套题面在当前口径下已接近上限（见限制）。
8. **证据维 60/60 是高口径红利。** 本轮题面多数题不给 code 名，按试答要求 3"写规则描述/check_id 即可"计 ✓，因此"未写 `keepout_violation`/`body_overlap`/`missing_placement`"一律不扣。若未来想考 code 名，必须在题面给出或在评分口径中显式要求，否则证据维会长期贴在 100%。

## 6 限制

- **样本量 3**，且三份作答高度同构（结构、行动清单、code 处理方式近似一致），分数不可外推为模型能力或对外能力声明。
- **隔离是约束式**（只读题面副本、禁读仓库/答案/联网/运行命令，靠自报"读过文件"），不是容器/权限强隔离，无法排除对训练语料的记忆或对上一轮答案的间接记忆。
- **单评审**：本文件为评审 A，未与 B 交叉核对；300 单元一致率需 `round6-evaluation.md` 汇总后才能给出。已知分歧风险点集中在 §4.5 (a)(b) 的口径选择与「未知」维的 tag/substance 判定（W2 有 7 个单元把 `NOT RUN` 写在行动栏）。
- **评分口径自建**：五维 ✓/△/✗ 的边界（尤其"未知"要求落 `NOT RUN`、"结论"要求单一主标记）为本评审显式约定，不是既有冻结口径；跨轮次比较需先对齐该口径。
- **只读离线材料**：判分事实键取自 `benchmarks.json` 的 `expected` 与契约硬/软检查表，未运行 `pcb_placement_benchmark.py`、未做 DRC/布线/阻抗/热/机械验证；本文件不对任何真实板结论背书。
- 只覆盖 20 题面；`answers.md` 的「成对案例参考答案」表与 D1–D3 派生案例未纳入本轮评分单元。

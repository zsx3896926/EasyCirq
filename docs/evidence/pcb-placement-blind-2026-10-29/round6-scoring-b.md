### 1.2 五维判定树（本轮实际使用）

| 维度 | ✓ | △ | ✗ |
|---|---|---|---|
| 结论类型 | 单主标记与 v5 答案键一致（`可确认`/`条件`/`待补`），且落在被问的那件事上；`条件` 写满两段（可确认事实 + 尚缺条件） | 主标记对，但该题**另一处被问的标记判断**答错/答反（如把 review 档说成"降级/不降级"把 `待补` 说成 `blocking`） | 主标记错、或把软代理超阈值写成"已证实失效" |
| 机制 | 给出回路/回流、耦合路径、热路径、机械干涉等物理链，能解释"为什么" | 方向对但把缺陷压进代理（过度归因） | 只重复 code/结论 |
| 证据 | 指到案例 id / 检查 id / finding code / 规则描述 / PL / 契约条目；题面未给 code 名时写 check_id 或规则描述**算 ✓** | 指向对但关键事实错 | 编造 code 名、指到错误案例 |
| 行动 | 修复/验证动作落在主导项，先硬约束后主导项，不过度 | 只覆盖部分主导项（如只修两条缺陷中的一条），或把"改判分实现"当作布局修复 | 动作与结论相反，或必答的过度例缺失（X01/X08） |
| 未知 | 列出离线答不了的项并写 `NOT RUN`（内容写在"行动"栏也计） | 列了缺口但无 `NOT RUN`，或漏掉核心缺项 | 完全没有边界声明 |

补充：结论维的基准是**主标记**（复合写法按主标记），故 20 题主标记 60/60 全对（§5 F7）；但对同一题**另一个被问到的标记/verdict 判断**答反仍记 △（X13 W2 的 HPWL、X04 W3 的"未声明连接器"）。相反，`条件` 第二段的**取值缺失**（X05 W1 未写 `blocking`）不记 △——规则 2 的两段可由"配置事实 + 缺失条件"满足，该缺口只写进发现（§5 F2）。

- 全部 300 个评分单元由我一人按上表逐条判；同一格只在"口径歧义"（见 §6 限制）时给出替代计分。

## 5. 发现（5–8 条）

1. **X20 前提缺口已归零，且归因清晰。** 3/3 主标记 `可确认`、3/3 verdict `blocking`、3/3 都写"缺布局项=硬检查"、3/3 都把"补默认坐标"判为契约 §7 假通过、3/3 都不给坐标、不臆造 code 名。第四/五轮 3/3 写 `review`/`待补` 的现象本轮**完全消失**——说明那是题面前提缺口，不是判断能力缺口。这是 v5 修订唯一改动点，验证通过。
2. **X05 主标记 3/3 `条件`，但"条件两段"的第二段仍是薄弱点。** W1 用"受该单一硬检查支配"代替 `blocking` 的字面取值；W2 则在机制上过度归因（"机械上即朝向冲突"）。也就是说：标记层的冲突没了，**证据层的归因方向**（"只是没声明该检查" vs "代理证明了缺陷"）仍有 1/3 走偏，这与 X05 的题目设计（两种解释二选一）直接相关。
3. **X13 的翻转识别已稳（3/3），但"翻转的边界条件"开始露头。** W2 在"HPWL 超阈值"上答反并与自己的依据矛盾。v4 补基线解决了"看不出哪项翻转"，v5 之后下一个风险点是**追问式小前提**（超阈值会怎样、成对案例的代价何时失效），建议成对类题目（X12–X15）各带一句"若代价项本身超阈值会怎样"的追问，把这类误差提前暴露。
4. **`行动`（93.3%）与 `未知`（91.7%）是仅有的两个低于 95% 的维度，且 4 个行动 △ 全是"漏第二段"。** X01 W2/W3 用"改判据"替代"移电容"（口径歧义，见 §6），X06 W2/W3 只修 NTC 不修 `ck-prot`。共同点是**题目有多条并列缺陷/多个动作层时，只答第一条**。建议答案键的「行动」对多缺陷题显式列出"第二条"，评分时按条数计。
5. **未知维 91.7%，失分形态单一：内容对但没写 `NOT RUN`。** 5 个 △ 全在 W2/W3，且这些题的 `NOT RUN` 都恰好被"折进行动句末"或被省略；W1 则 20/20 每题都带 `NOT RUN`。这说明该维现在考的是**格式纪律**而非知识，评分应明确"`NOT RUN` 必须出现在未知栏或行动栏的显式位置"。
6. **W1 拿到 100/100，需警惕"完整性偏好"。** W1 的作答在每题的"未知 + `NOT RUN` + 过度例"上最齐，且几乎逐条覆盖答案键；但它仍有 X05 未给 verdict 字面值（`blocking`）、X20 未答"缺失类 vs 越界类"两处未扣分缺口。若交叉评审 A 按"逐子问计分"，W1 会掉到 98。**W1 的满分是本表口径上限的体现，不是无瑕疵。**
7. **结论维主标记已饱和（60/60 = 100% 主标记正确，58/60 格 ✓），剩余误差都在"同一题的第二/第三问句"。** 两处结论 △（X13 的 HPWL、X04 的未声明连接器）都不是主标记错。规则 0 解决了"标记落层"，但**没有解决"一道题含多个标记判断时怎么计"**——这是当前答案键与评分表之间的最后一处结构性缝隙。
8. **三份作答高度同构，分数差异来自栏位完整度而非机制理解。** 三人的机制/证据几乎同构（证据 60/60），差异集中在"是否写 `NOT RUN`""是否修第二条缺陷""是否答最后一问"。因此本轮 288/300 只应读作**答案键覆盖度**，不能读作三名 Agent 的能力排序（与 README「三份作答高度同构，不能推断模型能力」一致）。

## 6. 限制

- **样本 3 个**，300 单元由单评审一人判定；同题同维的边界格（尤其 X01 行动、X06 行动、X20 未知）存在 ±1 单元的合理分歧。与评审 A 的差异应逐格对账，而不是比总分。
- **两处口径歧义已显式标注，未反复调整计分**：
  - X01"改动时先动哪一处"：若读成"改判分实现"（W2/W3 的读法），两格行动应记 ✓，则行动 58/60（96.7%）、W2 94、W3 98、总 290（96.7%）。本表按答案键（布局动作）记 △。
  - X06"行动"是否必须覆盖 `ck-prot`：本表按"两条失败项各需一条修复"记 △；若只要求主导项（NTC），两格应记 ✓，单独适用时 W2 94、W3 98。两项歧义若同时放宽，则行动 60/60（100%）、总 292（97.3%）、W2 96、W3 100。
- **只看文本，不看过程**：无法判断三人是否"记住"了训练语料；隔离是约束式（禁读仓库/答案/联网/命令），不是容器强隔离。
- **`benchmarks.json` 仅用于核对答案键的案例事实**（verdict/codes/checks/rubric），不作为评分依据，也不用于反推作答。
- 所有真实工程检查（DRC、布线/可布通、阻抗、EMC、热、机械/装配、打样）在本题面下均为 `NOT RUN`；本报告不对任何真实板结论背书。

> 对照标准：`answers.md` 当前 v6（规则 0 + 数据缺失两级）、`blind-prompts.md` v6、`README.md` 五维、`benchmarks.json` 的 `expected`。

## 1. 方法与口径

### 1.1 输入与边界

- **作答**：`docs/evidence/pcb-placement-blind-2026-10-29/round7-responses.md`（原文照录，含每人 `读过文件` 行）。
- **题面**：`easycirq/references/engineering-deepdives/exercises-pcb/blind-prompts.md` v6。
- **答案**：同目录 `answers.md` v6（当前标准答案，规则 0 含“能力/盲区例外”，规则 5 分“布局输入缺失/契约未声明对象”两级）。
- **维度**：同目录 `README.md` 的五维定义。
- **案例期望**：`easycirq/assets/pcb-placement-benchmarks/benchmarks.json` 的 `expected.verdict` / `expected.codes`（P1 `review/distance_far`、P2 `review/loop_large`、P3 `review/distance_far`、P4 `blocking/connector_off_edge`、P5 `review/distance_far`、P6 `review/loop_large`、P7 `blocking/keepout_violation`、P8 `blocking/connector_off_edge+body_overlap`，成对案例均 `acceptable`）。
- **不做**：不跑判分器、不做 DRC/布线/阻抗/热/3D；所有“真实工程”结论只按作答是否标 `NOT RUN` 评。

### 1.2 五维与 ✓/△/✗

| 维度 | 通过（✓） | 部分（△） | 不通过（✗） |
|---|---|---|---|
| 结论类型 | 主标记与 v6 答案一致；关键 verdict/codes/分级正确 | 主标记正确，但某个必答子结论缺失、含混或分层不完整（含 `条件` 只写一段、规则 5 两级混用） | 主标记错、verdict 反向、把 review 说成 acceptable 或把软代理说成已证实失效 |
| 机制 | 给出回路/回流、耦合、热路径、机械干涉等因果链 | 方向对但关键一环缺失，或以判分语义替代物理机制 | 机制错误或只重复 code |
| 证据 | 指到案例 id、check_id、finding code、PL 条目或可核对的规则描述；不臆造 code | 有正确依据但过于笼统，关键标识缺失 | 引用错误对象或臆造 code |
| 行动 | 修复与结论匹配；blocking 先硬约束，review 先主导项；必答“过度/不改分”例子齐全 | 动作方向对但缺必答例子、条件分支或“是否继续改”的判断 | 动作与结论矛盾或会引入新缺陷 |
| 未知 | 列出离线答不了的项并写 `NOT RUN`（或同义“缺/未给”），不猜型号、不补默认值 | 列表明显不全、状态归类错误，或未标明不可得 | 猜型号/补默认坐标/把未知写成已确认 |

- 汇总口径：60 个“题×人”单元 × 5 维 = 300 格；✓ 计 1，△/✗ 不计入 ✓ 率（百分比按 ✓/总数）。
- `题面未给 code 名时写 check_id / 规则描述` 按 ✓ 计（题面试答要求 1、3）；本轮无人臆造 finding code。
- 主标记只认一个；复合写法按主标记计。本轮 60/60 均为单主标记，无“可确认+待补”式复合。

### 1.3 规则专项检查（逐条）

1. **规则 0（第一问句所在层 + 能力/盲区例外）**：逐题核对第一问句。X01/X02/X03/X04/X06/X07/X11/X12/X13/X14/X15/X16/X19/X20 均按判分层（`可确认`/`待补`）；X08/X09/X17/X18 按工程层（`条件`）；X10 按“能不能插拔”（`待补`）；X05 存在标准侧争议（见 §4.4）。
2. **规则 5（数据缺失两级）**：X04（未声明 connectors）与 X20（缺 placement / 几何越界类）逐人核对。X20 主层 3/3 正确；X04 仅 Z2 明确写“待补”，Z1/Z3 用“报缺失/记缺失”未点明第②级（见 §4.3）。

## 4. 重点专项

### 4.1 X10：三人主标记是否 3/3 `待补`

**是，3/3。** Z1/Z2/Z3 均写 `待补`，且都把“离线不报错”限定为“贴边距离在容差内”，没有一个把它升成 `可确认` 或降成 `条件`。

- Z1：“不能判能插拔；离线不报贴边失败只说明距离在容差内”；补 3D/插拔包络；补后若壳体碰撞，离线分数不变，须人工复核或新增机械检查。
- Z2：“不能确认能插拔；离线不报错只证到边距离在容差内”；补插头壳体、卡扣、手指、线缆弯曲半径 3D；补 3D 碰撞时离线分数不变。
- Z3：“不能确认能插拔；不报错只说明贴边几何在容差内”；补 3D 与插拔方向评审；补 3D 发现碰撞，离线分数不变（漏报）。

**判断**：v6 把 X10 第一问改为“这份候选布局能插拔吗”达到了预期层位；X10 结论维 3/3 ✓，且“离线分数不变”这个易漏点 3/3 都写到。X10 本轮无残留问题。

### 4.2 X13：三人是否给出 `hpwl_high` 属性与 review 降级

**是，3/3 都给出 `hpwl_high` 与“超阈值 → review”的降级；翻转识别也 3/3。**

- 三人均写出：原布局 `ck-analog` 22.8 mm > 14 mm 失败 → `review`；成对 12.7 mm ≤ 14 mm 通过 → `acceptable`；翻转项是 `ck-analog`，不是 HPWL。
- Z1：`依据` 明写“HPWL 全局阈值，仅 `hpwl_high` 软检查失败降回 `review`”；`行动` 写“HPWL 超阈值→review”。
- Z2：`行动` 写“超阈值则 `hpwl_high` 软失败→review”；并写“HPWL 差≠布局差”。
- Z3：`未知` 写“HPWL 超阈值时 `hpwl_high` 失败→降回 `review`”；但 `行动` 只写“接受取舍，只监控线长”，缺工程复核项 → 行动维 △。

**判断**：v6 点名 `hpwl_high` 达到了预期；3/3 不再把 HPWL 变差误读成 verdict 降级。Z3 的残留是行动层太薄，不是属性缺失。

### 4.3 X20：是否 3/3 `可确认` + `blocking`；X04 的“未声明 connectors”与规则 5

**X20 主层：3/3 `可确认` + `blocking`。** 三人均把“缺 placement 属硬检查命中”直接判 `blocking`，无人写 review/待补主标记；均指出“补默认坐标 = 伪造数据 / 假通过”；均按题面“code 名未给”用规则描述或 check_id，未新造 code。

## 6. 限制

- **样本量小且同构**：每轮 3 个样本，三份作答高度同构；不能据此推断模型能力，也不作认证/对外能力声明。
- **隔离是约束式**：只读题目副本、禁读仓库/答案/联网/运行命令，不是容器/权限强隔离；无法排除对训练语料的记忆。
- **独立性边界**：未读前几轮 scoring/evaluation；但 `README.md`（任务指定输入 #4）本身含前几轮摘要，因此并非对轮次历史完全盲。
- **标准侧未决项**：X05（答案 vs 规则 0）是主争议；X03/X04 的硬/软属性未在题面给出，Z1 的“硬则 blocking”按题面缺口不扣；X20 的 `out_of_board` 类未在题面定义，Z2/Z3 的降级含标准侧成分；X03 的“螺钉/固定件”术语有歧义（P7 案例本身没有 fixed 器件，P8 的 H1 是 mounting_hole）。这些都可能让另一位评审给出不同的 △/✓ 边界。
- **五维是整体判断**：✓/△ 边界有主观性；证据维按题面“check_id/规则描述”口径接受，导致 60/60 饱和、区分度低；若改成“每题必须至少一个具体 id”，分数会下降。
- **未跑判分器**：未重跑 `benchmarks.json` 的 scorecard，未做 DRC/布线/阻抗/热/3D；所有 `NOT RUN` 均按作答文本判断，不证明真实工程结论。
- **“三人同题模式”是描述统计**：只描述本轮 3 人，不作显著性推断。

### 1.2 五维判定标准

| 维度 | 本轮判定标准 |
|---|---|
| 结论类型 | 主标记落在答案/规则 0 推出的层；不把 `review` 写成 `acceptable`，不把软代理超阈值写成「已证实失效」 |
| 机制 | 给出电流回路/回流、耦合路径、热路径或机械干涉的因果，而不是只重复 code |
| 证据 | 案例 id、finding code、check_id、PL 条目，或能定位该检查的具体规则；**题面未给 code 名时写 check_id/规则描述计 ✓**；新造 code 计 ✗ |
| 行动 | 修复与结论匹配（`blocking` 先硬约束、`review` 先主导项），不过度整板重排；X01/X08 的必答例到位 |
| 未知 | 列出离线判分答不了的项并标 `NOT RUN`，不猜型号、不补默认坐标 |

### 1.3 本轮边界口径（会影响个别格）

- **a. 证据「整行锚点」**：`依据` 字段若只写缺口清单或「软检查/距离检查/案例」泛称，但同一行的 `判定` 给出了 check 名（如 `loop_span`）或具体规则（如「包围盒相交」「贴边/重叠容差」），仍计 ✓；两处都没有 → △。
- **b. 题面未给硬/软属性的条件式 verdict**：X03/X04 题面未给属性，答案按硬检查判 `blocking`；Z1 写「硬则 blocking 否则 review」且写明了正确分支，不判错（记作题面缺口，见 §4.6）。
- **c. X05 标准侧争议**：答案 v6 标 `条件`，而规则 0 v6 的「能力/盲区例外」指向 `可确认`。两种都接受：主口径不判作答错，字面口径另报（§4.4）。
- **d. `条件` 两段**：可确认的几何/配置事实 + 尚缺的条件；只写一段计 △。本轮按作答主标记共 13 条 `条件`（X05×1、X08×3、X09×3、X17×3、X18×3），13/13 两段齐全（若把 X05 的 Z2/Z3 按答案字面也算条件，则 15/15）。
- **e. 单主标记**：复合主标记计 △；本轮 60/60 只有单主标记。Z3 X14 的「acceptable/review」是对成对 verdict 的并列写法，不是主标记，记备注。
- **f. 规则 5**：① 布局输入缺失 → `missing_placement` 硬检查 → `blocking`；② 契约未声明对象（如案例无 `connectors`）→ 该检查不适用/`待补`，**不是** `missing_placement`。

## 6. 限制

- 每轮 **3 个样本**，隔离为约束式（非容器/权限强隔离），无法排除对训练语料的熟悉度；三份作答高度同构，**不能**推断模型能力，也不作认证或对外能力声明。
- 单评审 B 的一次判断；✓/△ 的边界受 §1.3 口径影响，尤其证据的「整行锚点」规则——若改成「`依据` 字段必须含案例 id/check_id」，证据维会再降 2–3 格，Z1 的 91 会再低一点。
- X05 的主口径与字面口径会改变结论维 60↔58、Z2/Z3 20↔19；两套数都给出，合并时需明确取哪套。
- 答案 v6 自身在 X05 与规则 0 之间存在张力；X20 的「两类 finding」表述偏薄。这两处的「标准答案」不唯一，评分已按「不计作答错」处理。
- 未读往轮 scoring/evaluation，本轮分数**不与往轮横比**；README 的往轮摘要只用于确认维度定义。
- 未运行判分器/EDA；所有结论基于题面、答案与案例 JSON 的文本核对，案例坐标未重算。

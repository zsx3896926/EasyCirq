=== easyeda sch --help ===
Schematic operations

Usage:
  easyeda sch [flags]
  easyeda sch [command]

Available Commands:
  align               Align parts' rendered bboxes (left|right|top|bottom|centerx|centery) to a reference part
  apply               Replay a declarative step file (playbook) against EasyEDA
  attribute-inspect   Inspect one active-page attribute's visibility through three official read paths
  attribute-move      Move one bound Name/Designator attribute using x/y only
  autoconnect         Pin-aware planner: auto-pick direction/offset and connect a pin (or batch) to a flag/netport
  autolayout          Module-aware planner: place parts by module zone with deterministic, lint-clean coordinates
  autoplace-free      Pack parts into the sheet's blank space (zone-less; keeps other parts fixed)
  block-apply         Instantiate a circuit block: place its parts, wire internal_nets, bind ports
  bridge-check        Detect共线合并短路 (bridges) and孤儿桩 (orphans) at wire-tree granularity
  check               Reconstructed per-item design check the SDK DRC can't itemize
  clear               Clear the active schematic page (delete all page primitives: components, flags, wires, buses, graphics)
  clusters            列出 L1 虚拟组(器件 + 它自己的 marker/桩线)并判组间重叠 / 出图纸
  compose             Compose authored Lib circuits onto one sheet and compile a guarded SCH Apply
  connect             Stub a wire out of a pin and place a netflag/netport at its far end
  connectivity        Export layout-independent schematic connectivity IR
  connectivity-diff   Compare two connectivity snapshots offline
  design-diff         Compare local schematic identity, connectivity, geometry and complete compose plans
  designator-geometry Export measured current-page Designator text bboxes (read-only)
  designators         Allocate official reference numbers and repair placed component bindings
  destagger           批量消 marker-overlap:换方向/桩长并带桩线一起挪(默认 dry-run;--apply 执行)
  disconnect          Remove a pin's stub wire and its netflag/netport together (inverse of connect)
  distribute          Equalize edge-to-edge gaps between parts along one axis (x|y)
  drc                 Run the official schematic DRC SDK gate (may be boolean/aggregate only)
  export-image        Render the page — or only the given primitives — to SVG/PNG/PDF
  extract-layout      Reverse-derive a block's schematic_layout template from a placed instance (issue #140)
  frame               Apply or verify computed module frames and titles from JSON
  gate                S5 校验门:按固定顺序跑 layout-lint → check → bridge-check → drc,出一张报告

=== easyeda sch gate --help ===
Run the schematic verification gate: every checker, in one fixed order, as one report.

Pipeline (order is fixed on purpose — cheap and explanatory first):

  1. layout-lint   几何真值,一次 components.list,解释后面的连锁误报
  2. check         重建式逐条设计检查 + Go 侧几何 marker 规则
  3. bridge-check  wire-tree 粒度的合并短路 / 孤儿桩
  4. drc           官方 SDK DRC,最慢且需前台,放最后

Why one command: the four checkers exist as separate commands, so every run
started with an undecidable question — which ones, in what order, whose exit
code counts. The audit log shows agents answering it four different ways for
the same failure. Here the order is fixed, the blocking rules live in code, and
the output is one verdict.

Verdict is three-state, because "the checker could not run" is NOT "the board
is broken":

  pass     every executed stage passed
  fail     the schematic has blocking problems — see 阻塞项 / blockers
  blocked  a checker could not run (connector down, page not open, bad shape);
           the schematic was never fully judged. Remaining stages are skipped
           rather than run into the same wall.

Blocking rules: layout-lint overlap/pin-coincidence · check fatal+error ·
bridge-check bridge(real short) · drc fatal. Tight spacing, orphan stubs, and
non-fatal DRC items are advisory — --strict promotes them to blocking.

--json emits every stage's full native report under stages[].detail, so it is a
superset of the four single commands' JSON: nothing needs a second run.

Usage:
  easyeda sch gate [flags]

Examples:
  easyeda sch gate
  easyeda sch gate --json
  easyeda sch gate --strict                 # 告警也阻塞
  easyeda sch gate --only layout-lint,check # 只跑便宜的两关
  easyeda sch gate --skip drc               # 窗口不在前台时跳过 DRC
  easyeda sch gate --fail-fast              # 第一个阻塞失败就停

Flags:
      --all-pages           gate every page (geometry on inactive pages is shallow — cannot combine with --strict)
      --fail-fast           stop at the first blocking failure instead of collecting every stage
  -h, --help                help for gate
      --json                emit the aggregate report as JSON, with each stage's full report under stages[].detail
      --min-gap float       layout-lint stage: min edge-to-edge gap (mm) before a pair is flagged as tight (default 2.54)
      --only string         run only these stages (comma-separated: layout-lint,check,bridge-check,drc)
      --overlap-eps float   check stage: min positive-area extent (mm) for the marker-overlap/titleblock-overlap rules (default 1)
      --pin-eps float       layout-lint stage: max distance (mm) at which two pins of DIFFERENT components count as coincident; 0 = strict equality
      --skip string         skip these stages (comma-separated)
      --strict              promote advisory findings (tight spacing, warn-level, orphan stubs) to blocking

Global Flags:
      --doc string                pin every mutating action to this schematic page / PCB (uuid or name): the CLI switches to it and confirms via live document.current before editing, refusing rather than land the edit on whatever page is foreground — removes the doc-switch race
      --force-stale-read string   deprecated compatibility option; stale PCB reads now continue with staleRisk and authoritative workflows still save, reload, then read back
      --host string               daemon host (default "127.0.0.1")
      --ports string              daemon port range (start-end) (default "60832-60841")
      --project string            route by project name/uuid instead of --window (survives windowId churn)
      --skip-version-check        deprecated compatibility option; version differences are diagnostic and no longer block actions
      --window string             EasyEDA window ID

=== easyeda pcb dump --help ===
Capture components (anchor/rotation/locked/bbox/pads), board outline, silkscreen,
live DRC rules and copper layer count in ONE file.

With --out, a separate <out>.capture.json records the persisted file SHA256,
byte count, capture identity/timing and missing observations. stdout mode
continues to emit only the snapshot JSON.

--include-copper also captures tracks/arcs, vias, pour boundaries, materialized
poured copper, regions and static fills. Each category records available/unknown,
so a failed read cannot be mistaken for an empty board.

The snapshot is what `pcb layout-score --from <file>` replays offline, so a
reference board can become a regression fixture that needs no live editor.

Board outline requires the PCB to be the FOREGROUND document (the platform
returns null otherwise) — the snapshot records that degradation under
`partial[]` rather than silently pretending the board has no edges.

Usage:
  easyeda pcb dump [flags]

Examples:
  # 抓当前板为 fixture
  easyeda pcb dump --project ceshi --out /tmp/ceshi-board.json

  # 只要器件+板框（省两次往返）
  easyeda pcb dump --no-silk --no-rules --no-layers

  # 离线重放打分
  easyeda pcb layout-score --from /tmp/ceshi-board.json

Flags:
  -h, --help             help for dump
      --include-copper   capture exact routed/area copper and rule-region lists with per-category availability
      --label string     record this name as the snapshot's project label
      --no-layers        skip copper layer count
      --no-rules         skip live DRC rules (thresholds fall back to the JLCPCB baseline)
      --no-silk          skip silkscreen (drops the silk-consistency dimensions)
      --out string       write snapshot plus <out>.capture.json with persisted file SHA256 and capture provenance (default: stdout only)

Global Flags:
      --doc string                pin every mutating action to this schematic page / PCB (uuid or name): the CLI switches to it and confirms via live document.current before editing, refusing rather than land the edit on whatever page is foreground — removes the doc-switch race
      --force-stale-read string   deprecated compatibility option; stale PCB reads now continue with staleRisk and authoritative workflows still save, reload, then read back
      --host string               daemon host (default "127.0.0.1")
      --ports string              daemon port range (start-end) (default "60832-60841")
      --project string            route by project name/uuid instead of --window (survives windowId churn)

      --window string             EasyEDA window ID

=== easyeda sch export-image --help ===
Render the active schematic page, or ONLY the primitives you name, to
SVG / PNG / PDF (#166).

Why not a viewport capture (the removed `sch snapshot`): that path is viewport-dependent — a
backgrounded tab never repaints, so it silently hands back the previous
full-page frame. This renders the requested primitives directly: no viewport,
no foreground requirement, no dialog. SVG is vector, so an agent can zoom into
dense wiring without resampling a blurry screenshot.

--ids selects those primitives and exports just them (the export box shrinks to
the selection). Without --ids it exports the whole active page.

Usage:
  easyeda sch export-image [flags]

Examples:
  easyeda sch export-image --ids id1,id2 --out block.svg
  easyeda sch export-image --format png --out page.png
  easyeda sch export-image --scope page --format pdf --page P2 --out p2.pdf

Flags:
      --format string       svg | png | pdf (default svg)
  -h, --help                help for export-image
      --ids string          primitive IDs to export alone — CSV: id1,id2 (omit to export the whole page)

  -o, --out string          write the rendered file to this path
      --page string         schematic page to export (name or uuid)
      --scope string        selection | page | project (default: selection when --ids given, else page)
      --stay                with --page: stay on that page instead of restoring the previous one

# 目标：EasyCirq 作为国际顶尖产品的 harness 形态

> 2026-11-05 立。用户：「EasyCirq 是要作为一款国际顶尖的产品去做的。」
> 前置约束不变：**本地交付，不做 BS 架构、不做账号、不做多租户**。
> 本地也能是顶尖产品——VS Code、Figma Desktop、Ollama、LM Studio 都是本地形态。

---

## 一、一句话

> **让一个没读过我们文档的工程师，装上之后 30 分钟内交付一块能下单的板；
> 并且全程他都能看见「凭什么说可以交付」。**

前半句是产品力，后半句是 harness。**缺任何一个都不是顶尖。**

---

## 二、"顶尖"必须落成数字，否则是形容词

每一条都是可测门槛，不是愿景：

| 维度 | 门槛 | 怎么验 |
|---|---|---|
| **首次价值** | 新人从解压到拿到一张 `可以下单` 的卡 ≤ **30 分钟**，全程只用面板 | 找没接触过的人实测，录屏计时 |
| **可读性** | `en-US` 与 `zh-CN` **两套语言 100% 完整**，缺一个 key 构建就失败 | i18n lint + 缺键即 fail |
| **无中文泄漏** | 英文环境下界面/CLI/错误信息里 **0 个汉字** | 自动扫描（正则扫 CJK） |
| **失败可解释** | 每条错误必须回答三件事：**发生了什么、为什么、下一步做什么** | 已有 `test_failure_explainability` 扩展成全量 |
| **不假装完成** | `pending`/`blocked`/`stale` 在任何界面**永不呈现为通过** | 专门的光谱测试（5 种状态 × 每个显示面） |
| **性能** | 首屏 < **800 ms**（4 年前笔记本），交互响应 < **100 ms** | 本地基准脚本，进 CI |
| **可访问性** | WCAG **2.1 AA**，axe 检查 0 个 critical；**全键盘可用** | axe-core + 手工键盘走查清单 |
| **韧性** | 面板崩了 CLI 照常；daemon 挂了面板显示 degraded 而不是白屏 | 杀进程测试 |
| **安全** | 只监听 `127.0.0.1`；CSP 默认拒外链；日志**不含**密钥/网表内容 | netstat + CSP 头断言 + 日志扫描 |
| **可支持** | 一键导出**诊断包**（版本、doctor、日志、脱敏环境），用户不用教 | 导出并校验脱敏 |
| **可复现** | 同一份输入 → 逐字节相同的产物（已部分成立，要全链路） | 已有 plan SHA / selftest，扩到交付包 |
| **无遥测** | 默认 **0 上报**；开启要显式勾选并显示发送内容 | 抓包验证：默认无外连 |

> **不接受的回答方式**："体验很好""很专业"。上面每一项都要有命令输出或测试。

## 三、现在离这个标准差多远（诚实的差距盘点）

### 已有且够用

| 能力 | 现状 |
|---|---|
| 动作面 | **44 个顶层命令 / 184 个类型化动作**，能力覆盖原理图→PCB→BOM→制造 |
| 相位机 | S0–DELIVER，证据驱动，只有 `pass` 放行 |
| 证据门 | `sch gate`（三态 pass/fail/**blocked**）、`card`（0/1/**2**） |
| harness 循环 | `easycirq run`，相位动作白名单，越界直接拒 |
| 自更新 | `easycirq update`，sha256 校验、原子替换、可 `--check --exit-code` |
| 企业知识 | 规则、知识检索、人审台账、器件库 |
| 多客户端 | claude / codex / agents 三个技能目录同步 |

### 硬短板（这就是要解决的）

| 短板 | 量级 |
|---|---|
| **零 i18n** | Go 源码里 **17,317 行**含中文；文档全中文。**不国际化就不可能是国际产品** |
| **没有产品界面** | 一切都靠记命令；拒绝理由跑完就没了 |
| **无上手引导** | 新人不知道从哪开始 |
| **无诊断包** | 出问题只能靠用户描述 |

**所以目标的重心不是"加功能"，是"把已有能力做成产品"。**

## 四、产品面（五个surfaces，面板是其中之一）

### S1 面板（产品门面）

一个本地面板，**不是状态显示器，是工作台**：

**一、工程与板**
- 工程列表（最近/全部）、当前板快照缩略、页面/窗口状态
- 连接器版本必须 `v1.0.22`，不符要**醒目且可点**直达修复步骤

**二、相位与证据**（核心）
- S0–DELIVER 相位条，每格五态：`pass / fail / blocked / pending / stale`
- 点一格 → 缺什么、怎么补（`howToFix`）、上次跑是什么时候
- **`pending` 与 `stale` 有自己的颜色，永不为绿**

**三、交付卡**
- 大字判词：`可以下单` / `还不能下单` / `还没检查过`
- 与 KPI 定义对账：`必查 14/15 · 缺证据 N`

**四、Agent 工作面**
- 对话流：模型想做什么 → 允许/拒绝 → 为什么
- **拒绝高亮**（这是 harness 的全部意义）
- 可停止、可续跑（已有续跑能力）
- 每一轮对应的动作可点开看原始 JSON

**五、历史与产物**
- 时间线：谁在什么时候推进了相位、跑了什么门、结果如何
- 产物列表：交付包、BOM、报告，可打开、可导出

### S2 语言（国际化）

- 全部用户可见文案进资源文件；`zh-CN` / `en-US` 双份完整
- 英文**不是翻译腔**：术语统一（Phase / Evidence / Gate / Delivery Card）
- CLI 错误信息同样双语，`--lang` 或系统语言自动选择
- 文档双语，英文版是**一等公民**

### S3 上手（首次运行）

- 首次启动引导：检查 EDA → 导入连接器 → 选工程 → 解释"相位"是什么
- 每一步能跳过，能回来
- **30 分钟首次价值**靠这条实现

### S4 诊断与支持

- 一键诊断包（脱敏）
- 面板内 `doctor` 可视化：daemon、连接器、Python、技能目录、端口
- 每个红色状态配**一条可执行的修复命令**

### S5 交付与生命周期

- 签名安装包（Windows 至少 Authenticode）
- 离线安装包（无网可装）
- 自更新走面板（已有 CLI 能力，包一层）
- 兼容性矩阵：CLI / 连接器 / 技能 三者版本对应关系**显式化**

## 五、技术形态（守住本地、守住单一真相）

| 项 | 选择 | 理由 |
|---|---|---|
| 前端 | 单页，**无框架必需**；构建产物进二进制（embed） | 客户机不该装 node |
| 后端 | `easycirq panel`，内嵌 HTTP，**只监听 127.0.0.1** | 不新增部署单元 |
| 数据 | 一律来自 CLI 的 `--json` 或证据文件 | **单一真相来源** |
| 判定 | **面板内零判定逻辑** | 否则会出现第二个真相 |
| 语言 | 资源文件 + 运行时切换 | 满足 S2 |
| 实时 | 先轮询（1–2 s），必要时 SSE | 先简单可测 |

**铁律：面板是"渲染器"，不是"第二套逻辑"。** 任何判定差异都是 bug，用测试钉死。

## 六、验收判据

### A. 面板（10 条）

1. `easycirq panel` 起得来，打印确切 URL
2. **只监听 `127.0.0.1`**（`netstat` 证明不是 `0.0.0.0`）
3. 相位条五态颜色与证据**一一对应**
4. `pending`（门没跑）**不显示为绿**
5. `card` exit=2 → 显示"还没检查过"，不是"通过"
6. 改板后证据变 `stale` 且面板标出
7. 任意一次拒绝，面板能说清：**哪个相位、想做什么、为什么不行**
8. 连接器版本不符有醒目提示
9. 杀掉面板进程，`easycirq phase` 照常
10. 干净安装后打开面板**无构建步骤**

### B. 国际化（5 条）

11. `en-US` / `zh-CN` 键集合**完全相等**（缺键 = 构建失败）
12. 英文环境下**扫描到 0 个汉字**（CJK 正则）
13. 术语表统一（Phase/Evidence/Gate/Delivery Card 等有对照表）
14. CLI 错误信息双语，`--lang` 生效
15. 英文 README / QUICKSTART 可独立完成首次任务

### C. 质量（5 条）

16. axe 检查 **0 critical**；键盘可走完主流程
17. 首屏 < **800 ms**，交互 < **100 ms**（基准脚本进 CI）
18. 空状态/错误状态/离线状态**都有设计**，不是白屏
19. 深色/浅色都可用
20. 无遥测：默认抓包**零外连**

### D. 交付（4 条）

21. 签名安装包
22. 离线安装可用
23. 诊断包可导出且**已脱敏**（断言不含网表内容/密钥）
24. `inspect-bundle` verdict `ok`，且包内含面板

## 七、分阶段（每期都可交付，不是半成品）

| 期 | 内容 | 交付证明 |
|---|---|---|
| **P0 地基** | i18n 脚手架 + 字符串抽取（面板+CLI 错误）+ 诊断包 + 无遥测 | 英文环境 0 汉字；诊断包可导出 |
| **P1 面板 MVP** | 工程选择、相位条、交付卡、证据详情、实时刷新 | A1–A6、A9、A10 |
| **P2 Agent 工作面** | 对话流、拒绝高亮、停止/续跑 | A7 |
| **P3 操作** | 跑门/推进按钮，仍走同一判定 | 面板操作与 CLI 结果**逐字节一致** |
| **P4 产品化** | 引导、快捷键、深浅色、无障碍、空/错状态 | B、C 全部 |
| **P5 交付** | 签名、离线包、自更新面板、兼容矩阵、双语文档 | D 全部 |

**P1 之后每一期都能给客户看。**

## 八、明确不做

| 不做 | 为什么 |
|---|---|
| 云端 / 账号 / 多租户 | 本地交付（已定）。国际产品 ≠ SaaS |
| 面板里画原理图 | 那是 EDA 的事，重复实现必不一致 |
| 面板内重算任何判定 | 会变成第二个真相来源 |
| 遥测默认开启 | 工程师对硬件设计数据极度敏感 |
| 移动端 | 工作场景在桌面 |
| 母语级多语种（日/德…） | 先做到中英都过硬，再谈第三语言 |

## 九、风险与处置

| 风险 | 处置 |
|---|---|
| i18n 改造面巨大（17k 行） | **P0 只抽"用户可见"字符串**，注释/日志暂不译；用 lint 保证新增代码必须走资源文件 |
| 面板变成要长期维护的前端 | 无框架、单页、构建产物 embed；测试只断言关键 DOM 文本与语义 class |
| 面板与 CLI 判定漂移 | 面板零判定 + A3–A7 测试 + P3 的"逐字节一致"判据 |
| "顶尖"变成无止境 | 二节的数字就是边界；达不到就诚实标 NOT RUN，不加形容词 |

# 目标：用一块高难度板子把产品压一遍

> 2026-11-05 立。用户：「目标达成之后，再用 EasyCirq 跑一块难度高的板子走一遍，
> 边走边修边优化产品本身。」
>
> 定位：这是 `docs/goal-easycirq-product.md` 的 **P6 验收阶段**——
> 产品不是"功能做完"就算完，得有一块真板子从头走到尾。

---

## 一、一句话

> **不是证明我们能画板，是用一块真板子把产品的洞挖出来，并且当场补上。**

上一轮真板子干跑（S0→S6）就是这么挖出一个致命断链的：交付卡永远 `not_measured`，
因为产出证据的脚本没暴露成子命令。**那个洞靠读代码、写测试都发现不了，只有真跑一遍才露出来。**

这一轮要做的，是把这个方法用到一块更难的板子上。

---

## 二、选题：什么样的板子算"难"

不选一块"一定能过"的板子自证清白，也不选一块注定失败的板子做样子。
难度按**可量化的维度**定，并且**必须是产品声称自己擅长的领域**：

| 维度 | 门槛 | 为什么它难 |
|---|---|---|
| 电源轨数量 | **≥ 4 路**（含至少 2 种拓扑：buck + LDO） | 电源完整性、时序、上电顺序都是真问题 |
| 器件数 | **≥ 40 个**（不含测试点） | 布局/编组/去耦都要真的做取舍 |
| 网络数 | **≥ 80 条** | 手工连不现实，必须靠工具 |
| 混合信号 | 含至少一个**模拟前端 + 数字部分** | 地平面、噪声、去耦位置 |
| 保护电路 | 输入反接 / 过流 / TVS 至少一项 | 企业规则能真正咬住 |
| 约束 | 至少一条**几何或电气约束**（如去耦距离、电流密度） | 排队列布局与 KPI |

### 选定板子：**USB-C 供电的四路电源分配板**

```
输入：USB-C（5V/3A）或 DC 插孔（12V）
Rail1  12V → 5V   @ 2A    buck         （带输入保护）
Rail2  5V  → 3.3V @ 1.5A  buck
Rail3  3.3V → 1.8V @ 800mA LDO
Rail4  5V  → 4.0V  @ 500mA LDO
时序：5V 先起 → 3.3V 后起（RC 或 EN 链）
保护：输入反接、过流、TVS
附属：一颗 MCU 做电压采样与告警（复用已验证的 MCU 最小系统）
```

**为什么是这块**：

- 它压在**我们声称擅长的地方**（电源、企业规则、布局取舍），不是挑软柿子
- 4 路轨 + 2 种拓扑 + 时序，`power-net check`、去耦检查、KPI 全部会被真的用上
- 输入保护是企业规则最容易咬住的场景
- 不依赖冷门器件，选型风险可控

**换选题的规则**：如果开跑后发现关键器件在立创商城不可得，**换器件不换难度**
（保持上表的门槛），并把这次换料记录下来。

## 二之二、这是一条**难度阶梯**，不是一块板子

用户 2026-11-05：「这块板子上机验证完，再验证一个更高难度的板子，**都是一样的去做**。」

所以本目标包含**连续的几块板**，一块比一块难，每块走同一套流程：

```
板1（当前）→ 上机验证 → 修产品 → 板2（更难）→ 上机验证 → 修产品 → 板3（如需要）
```

### "上机验证"是什么意思

**不是设计文档、不是纸面推演、不是离线仿真。** 是：

- 真的在 EasyCirq 里建工程、落器件、连线、跑门
- 真的读回 EDA 的现状（`sch read` / 板子指纹）
- 真的拿到 `easycirq card` 的判词
- 面板上能如实显示这块板的真实状态

**离线算得再漂亮，没上机就等于没做。**

### 难度递增门槛（每块必须比上一块更难，且可量化）

| 维度 | 板1 | 板2（更高难度） | 递增规则 |
|---|---|---|---|
| 电源轨 | ≥ 4 路，buck + LDO | **≥ 5 路，≥ 3 种拓扑** | 轨数或拓扑数 +1 |
| 器件数 | ≥ 40 | **≥ 60** | +50% |
| 网络数 | ≥ 80 | **≥ 120** | +50% |
| 功率 | ≤ 2 A/轨 | **≥ 3 A 单路 + 大电流路径** | 引入新的功率约束 |
| 隔离 | 无 | **≥ 1 处电气隔离 / 明确的爬电间隙** | 引入**安全**维度 |
| 混合信号 | 有模拟前端 | **模拟前端 + 独立 ADC + 分地** | 从一个地变成分地 |
| 热 | 无显式约束 | **含热约束**（功率器件温升可算） | 引入热维度 |

**板2 候选**：**24V 输入的带隔离电机驱动 + 电流采样控制板**
（H 桥 5A 峰值、分流电阻 + 运放采样、数字隔离、过流比较器、反接/续流保护）

选它的理由：压在**电源 + 模拟 + 保护 + 安全间距**上，是板1 的自然升级，
且引入板1 完全没有的三样东西——**大电流路径、电气隔离、分地**。

**允许换选题，不允许降难度。** 器件买不到就换器件，门槛不动。

### 硬规则：**选型前先 `easycirq blocks ls`**

**每块板都必须走「离线先行」六阶段**（`easycirq/references/schematic-offline-first.md`）：

| 阶段 | 做什么 | 碰 EDA？ |
|---|---|---|
| S1 离线规格化 | 功能模块清单、电源树、引脚/复用表、BOM↔封装↔C 号、NC 声明 → `spec.json` | 否 |
| **S2 离线布局与连接优化** | 版式规划 → 模块候选 → 标签/端口规划 → 打分选优 → `style-plan.json`；**先跑 `scripts/sch_style_plan_check.py`，未过不得进器件** | 否 |
| S3 离线质量度量 | 各 checker 出原始报告 | 否 |
| S4 KPI 门禁 | 15 项 KPI 聚合；`apply_allowed=true` 且**连续 2 轮 PASS** 才允许上机 | 否 |
| **S5 一次性上机** | dry-run 对账 → **单次批量写入** → save → reload → 回读 → 导图复核 | **是** |
| S6 沉淀落库 | KPI 回执、门禁证据、失败模式 | 否 |

> **跳过 S1–S4 直接落图，症状是「块落下了但一部分引脚没连」「标号撞图签」「组框重叠」**
> —— 全部是布局没规划的表现，不是电路设计问题。
> 板1/板2 前面几十轮就是这么撞过来的（见 `reports/hard-board/board1/friction.md` 的 #32/#33/#39）。

产品内置 **39 个已验证电路块**（AMS1117 LDO、BQ24074 power-path、CC1101 射频前端、
CH334F USB hub、ESP32-S3 最小系统、INA226 监测、PMOS 高侧软启动、光耦隔离……）。
`block-apply` 会自动**放器件 + 连内部网络 + 绑端口**，而且布线前有几何硬门
（bbox 重叠、两器件引脚共点都是硬错误）。

**能用块拼出来的，就不要从零件开始。**

从零件开始看着自由，实际是放弃产品积累的全部安全资产。板1 的教训：
手搓 51 个零件，撞上"排版没给标号留位置"；而块自带布线计划，**根本不会撞**。


### 每块板都要产出

```
reports/hard-board/
├─ board1/   goal.md / friction.md / decisions.md / phases.md / final-card.json
├─ board2/   同上
└─ ladder.md 两块板的难度对照 + 每块挖出的产品缺陷计数
```

`ladder.md` 要能回答一个问题：**跑完第二块板，产品比跑完第一块时强在哪里**——
用"修掉的产品缺陷数"和"堵住的断链数"回答，不用形容词。

## 三、"走完一遍"的定义

**不是"画完了"，是拿到一个有证据支撑的交付判词。**

判词只有三种，**"还不能下单"也是合格结果**：

| 判词 | 含义 |
|---|---|
| `可以下单` | 所有必查项通过，证据齐全 |
| `还不能下单` | 有明确未通过项，且说得出是哪一项、为什么 |
| `还没检查过` | 有门没跑 —— **这一种不算"走完"**，除非能说清为什么跑不了 |

**"走完一遍"的最低要求**：面板上每一格都不是 `pending`，每一格的红都有归因。

## 四、边走边修的规则（这是本目标的核心）

每遇到一次卡顿，**当场**做四件事，缺一不可：

1. **记**：写进 `reports/hard-board/friction.md`，含命令、原始输出、发生了什么
2. **分类**：
   - `产品缺陷`（功能错/缺/难用）→ 修代码
   - `能力缺口`（产品本来就做不到）→ 记录并**明确标为不承诺**
   - `文档缺失`（能做但没人告诉用户怎么做）→ 补文档，并加一条测试守住
3. **修**：产品缺陷必须**当场修掉并加测试**，不许"记下来以后再说"
4. **回归**：修完跑全量，确认没弄坏别的

### 一条硬规则：**不许为了让流程走通而放宽守卫**

如果板子卡在某个门上，正确的动作是**修产品**或者**如实记录"过不去"**，
而不是把门调松、把阈值改大、把检查跳过。

**放宽守卫 = 这个目标失败**，即使板子最后"交付"了。

## 六、验收判据

| # | 判据 | 怎么验 |
|---|---|---|
| 1 | 板子达到第二节的**全部难度门槛** | 器件数/网络数/轨数由 `easycirq sch list --json` 统计 |
| 2 | 交付卡**有明确判词**（三种之一） | `easycirq card --json` 的 `state` |
| 3 | 面板上**没有 `pending`** | `easycirq phase show --json` 逐相位断言 |
| 4 | 每一格红都有**归因说明** | `friction.md` 或 `decisions.md` 里对得上 |
| 5 | `friction.md` 里每条**产品缺陷**都有对应提交 | 提交号可查 |
| 6 | 没修的那些**明确标为"不承诺"** | `friction.md` 的分类字段 |
| 7 | 修完**全量回归不掉**（pytest / go 基线） | 回归输出 |
| 8 | **没有放宽任何守卫** | 逐一核对守卫文件 diff：门/阈值/白名单 |
| 9 | 最终交付卡**原样保存**，不手工编辑 | `final-card.json` 与命令输出一致 |
| 10 | 面板能正确显示这块板的真实状态 | 打开面板截图/断言 |

## 七、明确不做

| 不做 | 为什么 |
|---|---|
| 为了"走通"而放宽门 | 见第四节硬规则 |
| 手工修 EDA 里的东西来掩盖工具缺陷 | 那是在测人，不是测产品 |
| 追求"高难度"到超出产品能力 | 难度门槛是第二节那张表，够了就停 |
| 承诺布线质量到"可投产" | 已知边界：自家样板 `clearance 146` vs 目标 0 |
| 边跑边改目标 | 目标先写完，跑的过程中只记缺口，不改判据 |

## 八、风险

| 风险 | 处置 |
|---|---|
| 器件买不到，流程卡在选型 | 换器件不换难度，记录换料过程 |
| 布线条数太多，时间不可控 | 先做出"有证据的判词"，布线深度按时间取舍，**取舍要记下来** |
| 修产品把别的弄坏 | 每次修完立刻全量回归 |
| 无意识地把守卫调松 | 判据 8 专门查这个：逐条核对守卫文件 diff |
| 真实模型跑不了（无 key） | 用 `--fake` 剧本驱动相位机；**真模型这一段标 NOT RUN** |

# 目标：EasyCirq 以 harness 形态交付，带一个本地面板

> 2026-11-05 立。用户：「让我们的 EasyCirq 以 harness 的形态交付，有一个类似于 DeepSeek Harness 的面板，根据已有的能力去做。」
>
> 前置约束（2026-11 已定，不再讨论）：**本地交付，不做 BS 架构、不做账号、不做多租户**。

---

## 一、一句话

> 把已经存在的东西——相位机、证据门、交付卡、循环、审计日志——**装进一个本地网页**
> 让人不用记命令就能看见「这块板走到哪、卡在哪、缺什么」。

**不是做新能力，是把已有的能力做得看得见。**

---

## 二、为什么值得做（不是装饰）

现在这些东西都**存在但不可见**：

| 已有 | 现在怎么看 | 问题 |
|---|---|---|
| 相位机 S0–DELIVER | `easycirq phase show` | 要记参数、认 JSON |
| 证据状态 pass/fail/blocked/pending | 同上 | 人分不清 `blocked` 和 `pending` 的区别 |
| 交付卡 | `easycirq card` | 纯文本，数字对不上 KPI 定义时看不出来 |
| 循环在做什么 | `easycirq run` 的 stdout | 跑完就没了，**「刚才它为什么被拒」查不到** |
| 审计日志 | 日志文件 | 没人会去翻 |

面板要解决的**唯一问题**：**让"拒绝"和"缺证据"变得不可能被忽略。**

这跟 harness 的目的一致——不是让 AI 更聪明，是**让人没法假装做完了**。

## 三、现有能力盘点（面板只吃这些，不新造）

### 数据源（都已存在，都已实测）

| 来源 | 形态 | 已经验过 |
|---|---|---|
| `easycirq phase show --project <uuid> --json` | JSON 1528 字符 | ✅ 本机实测 |
| `easycirq card --json` | JSON 302 字符，exit 0/1/2 | ✅ 本机实测 |
| `easycirq status --json` | JSON | ✅ 支持 `--json` |
| `easycirq sch status --json` | JSON | ✅ 支持 `--json` |
| daemon `GET /health` | 健康 + 连接器状态 | ✅ 已有路由 |
| daemon `POST /action` | 184 个类型化动作 | ✅ 已有路由 |
| 相位证据文件 | `~/.easycirq/phase/<uuid>.json` | ✅ 已落盘 |
| 审计日志 | 每次动作一条 | ✅ 已有 |

### 明确不新造

- **不加新动作**：面板调的就是 `phase` / `card` / `status` 已经做的判定
- **不在面板里重算**：所有判定都在 `phase.py` / 门里，面板**只显示结果**——
  否则就是第二个真相来源，迟早不一致
- **不做远程**：只监听 `127.0.0.1`，和 `llm-proxy` 同一条纪律

## 四、面板要有四块（按重要性）

### ① 相位条（最重要）

```
S0 需求 → S1 图纸 → S2 编组 → S3 摆放 → S4 布线 → S5 校验 → S6 存盘 → DELIVER
                    ✓已过        ✓已过       ⏳blocked    ✗fail      · pending
```

- 每个相位一个格子，**颜色只有四种**：`pass` 绿 / `fail` 红 / `blocked` 黄 / `pending` 灰
- 点一格 → 显示「缺什么、怎么补」（`howToFix`）
- `stale`（板子变了、证据失效）单独一种颜色，且**自动标出来**

> 判据：**一眼能看出"能不能交付"，不用读任何文字。**

### ② 交付卡

- 大字号一句话：`可以下单` / `还不能下单` / `还没检查过`
- 下面一行：`必查 14/15 · 缺证据 N · 提醒 M`
- **数字必须与 KPI 定义对得上**（`metrics/schematic-kpi.v1.json` 的 total）

> 判据：卡片说 `ready` 而实际有缺证据 → 面板要红，不许显示绿。

### ③ 循环回放

`easycirq run` 每轮的：模型想做什么 → 被允许/被拒 → 为什么。

- 直接读 `run` 落盘的日志
- **拒绝那一行要显眼**（这是全部意义所在）

> 判据：随便挑一次拒绝，面板要能说清「在哪个相位、想做什么、为什么不行」。

### ④ 工程与连接器

- 当前工程、页面、窗口
- 连接器版本（必须 `v1.0.22`，不符要醒目提示）
- daemon 状态

## 五、技术形态

| 项 | 选择 | 理由 |
|---|---|---|
| 前端 | **单个 HTML 文件**，无构建、无框架依赖 | 客户机上不该要求 node |
| 后端 | `easycirq panel` 子命令，内嵌 HTTP，只监听 `127.0.0.1` | 复用现有二进制，不新增部署单元 |
| 数据 | 子进程调 `easycirq ... --json`，或直读证据文件 | 单一真相来源 |
| 刷新 | 轮询（1–2 s）或 SSE | 先轮询，简单可测 |
| 端口 | 从 daemon 的 `23111-23120` 里取，占用则顺延 | 与现有约定一致 |

**关键：面板进程启动失败不能影响 CLI**，两者互不依赖。

## 六、验收判据（每条都能跑）

| # | 判据 | 怎么验 |
|---|---|---|
| 1 | `easycirq panel` 起得来，打印确切 URL | 起服务，`curl` 拿 200 |
| 2 | **只监听 127.0.0.1** | `netstat` 验证不是 `0.0.0.0` |
| 3 | 相位条颜色与实际证据一致 | 造 4 种状态（pass/fail/blocked/pending）各截图/断言 |
| 4 | `pending`（门没跑）**绝不显示成绿** | 断言 HTML/JSON 里该格不是 pass |
| 5 | 卡片 `exit=2`（未检查）→ 面板显示"还没检查过"而非"通过" | 断言 |
| 6 | 板子改动后证据变 `stale` 且面板标出 | 改板 → 刷新 → 断言 |
| 7 | 拒绝理由可见 | 用 `--fake` 造一次拒绝，断言面板能显示原文 |
| 8 | 连接器版本不符要有醒目提示 | 伪造版本号，断言 |
| 9 | 面板挂了不影响 `easycirq phase` | 杀掉面板进程，跑 CLI，断言正常 |
| 10 | 装完就能用（无需 node / python 之外的东西） | 干净目录安装后打开面板 |

## 七、明确不做

| 不做 | 为什么 |
|---|---|
| 账号 / 登录 / 多租户 | 本地交付（已定） |
| 远程访问 / 端口转发 | 同上；监听 `0.0.0.0` 是安全风险 |
| 面板里画原理图 | 那是 EDA 的事，重复实现必不一致 |
| 面板里重新计算任何判定 | 会变成第二个真相来源 |
| 模型对话输入框（第一版） | 先把「看得见」做完，交互放第二版 |
| 移动端适配 | 工程师在桌面用 |

## 八、分阶段

| 阶段 | 内容 | 可交付 |
|---|---|---|
| **P1** | 相位条 + 交付卡，只读 | 能回答"这块板能不能交付" |
| **P2** | 循环回放（拒绝高亮）+ 工程/连接器信息 | 能回答"刚才为什么被拒" |
| **P3** | 动作按钮（跑门、推进），仍走同一判定 | 不用切终端 |
| **P4** | 模型对话（复用 `easycirq run`） | harness 完整形态 |

**P1 做完就可以交付**——它已经回答了唯一重要的问题。

## 九、风险

| 风险 | 处置 |
|---|---|
| 面板与 CLI 判定不一致 | 面板**不含任何判定逻辑**，只渲染 CLI 的 JSON；不一致就是 bug，用测试钉住 |
| 颜色让人误以为"绿=没问题" | `pending`/`stale` 必须有自己的颜色，且**永不显示为绿** |
| 又变成一个要维护的前端 | 单文件、无构建、无依赖；测试只断言 DOM 里的关键文本与 class |
| 客户机没有浏览器 | 面板是**可选**的；CLI 永远是主路径 |

# 目标：把方法论做成代码，而不是提示词

> 2026-11-04 立。用户明确：harness 形态的目的是**「把方法论做成代码，而不是提示词」**。
> 所以这不是"让 AI 更会画板"，是**让 AI 跳不过步骤**。

---

## 零、一句话

> **每个阶段都要有证据才能往下走；没有证据就是 NOT RUN，NOT RUN 阻塞，永远不等于通过。**

---

## 一、为什么不是"做一个更强的 agent"

`sch gate` 的帮助文本里记着这条动机，是真实故障：

> "四个检查器本来是分开的命令，于是每次运行都从一个无法回答的问题开始——
> 跑哪几个、什么顺序、谁的退出码算数。
> **审计日志显示 agent 对同一个失败的四种不同回答。**"

模型会在同一个问题上给出不同答案。**把顺序和阻塞规则放进代码，就是消灭这种自由。**

所以 harness 的职责是三条：
1. **按顺序调门**（不是让模型挑）
2. **拒绝跳步**（不是提示"建议先做 S2"）
3. **把 NOT RUN 当阻塞**（不是"先跳过"）

---

## 二、已经落成代码的（不用重做）

| 条款 | 代码 | 判词 |
|---|---|---|
| 检查顺序固定 + 阻塞规则 | `sch gate` | **三态**：pass / fail / **blocked** |
| 交付要有证据 | `card` | exit=2 |
| 计划脏了不许 emit | `emit_apply` | 拒绝 |
| 候选必须人审 | `review_ledger.promote` | 拒绝 |
| 撤回的候选不许重跑 | `regress` | 拒绝 |
| 改内核必产物不变 | `equivalence.py` | 逐字节比对 |
| 阶段进度 | `sch status` | S1–S6，`?` 表示判不了 |

**这些门本身已经是对的。缺的不是门，是"谁按顺序调、跳不过去"。**

---

## 三、缺的三条

| # | 缺口 | 现状 |
|---|---|---|
| ① | **阶段之间没有强制** | `sch status` 检测得到状态，但你现在就能从 S1 直接跑 `sch place`，没人拒绝 |
| ② | **探索纪律还在提示词里** | R1 先算边界（`feasibility.py` 存在但没人强制先跑）、R4 未标定不排序、R7 三轮无改善换问题、R8 NOT RUN 不是结果 |
| ③ | **没有循环** | 谁按顺序调这些门？现在靠 agent 自觉 |

---

## 四、终态（每条可验）

1. **`easycirq phase` 能显示**：当前相位、每个相位的证据状态
   （`run` / `pass` / `fail` / `blocked` / **`NOT RUN`**）。
2. **`phase advance` 是硬门**：前置证据不是 `pass` 就 **exit≠0**，
   并说清**缺哪条证据、怎么补**。
3. **至少一个真实转换是强制的**：S5 校验门未 `pass` → 交付被拒。
   （`card` 现在 exit=2，但要把 `blocked` 也当阻塞，且接进相位机。）
4. **NOT RUN 永远不等于 pass**：有测试证明"故意不跑 → 必须被拒"。
5. **不破坏现有基线**（见第八节）。

---

## 五、明确不做（这一轮）

| 不做 | 为什么 |
|---|---|
| **给 184 个动作逐个分相位（白名单）** | 最花时间、最容易分错、分错会卡住正常工作流。**先搭证据链，跑过真实任务再铺** |
| **循环 / 模型调用** | 第 1 层做完，循环退化成"顺序调用器的薄壳"。先别造 |
| 改现有门的判定逻辑 | 那些已经验过，不动 |
| 把 R1–R8 全部落码 | 先落**能量化**的（有命令、有退出码的）；主观的留在文档 |

## 六、设计

### 6.1 相位与证据

```
S0 spec → S1 图纸 → S2 编组 → S3 摆放 → S4 布线 → S5 校验 → S6 存盘 → DELIVER

每个相位：
  requires: 进入它之前必须 pass 的证据列表
  evidence: {相位, 命令, exit, verdict, 时间, 文档哈希}
```

### 6.2 证据状态机（关键）

```
NOT RUN  ──跑一次──→ pass / fail / blocked
                      │
blocked ──修好环境再跑──→ pass / fail
fail    ──修板──→ pass
```

**只有 `pass` 放行。** `blocked`（检查器没跑成）、`?`（判不了）、`NOT RUN`（没跑）
**一律阻塞**——这是与现有 `sch gate` 三态判词直接对齐的。

### 6.3 证据往哪存

`.easycirq/phase/<projectUuid>.json`（本机，不进工程）。
理由：相位是"我们对这块板的判断进度"，不是板子的一部分；换机器应该能重建，
但**不能因为换机器就假装跑过了**——所以带文档哈希，板子变了证据作废。

### 6.4 强制的落点

| 层 | 谁强制 | 强度 |
|---|---|---|
| 1a `phase` 命令 | CLI | 弱（人可以不看） |
| 1c `advance` 校验 | CLI 退出码 | 中（脚本/agent 会停） |
| **1b daemon 动作白名单** | **daemon 拒绝派发** | **强**（硬调也拒） |

**这一轮做 1a + 1c。1b 留到有真实任务数据之后。**

## 七、分阶段

### 阶段 1 · 证据链（本轮）
- [ ] `easycirq phase` 显示当前相位与各相位证据状态
- [ ] `easycirq phase run <phase>` 跑该相位的门并记录证据
- [ ] `easycirq phase advance` 校验前置证据，不是 pass 就拒
- [ ] 证据带文档哈希，板子变了自动作废

### 阶段 2 · 接一个真门（本轮）
- [ ] 把 `sch gate` 接成 S5 的证据
- [ ] `card` 接进相位机：`blocked`/`NOT RUN` 一律不出交付卡

### 阶段 3 · 真实任务验证（本轮）
- [ ] 拿一个新工程，从 S0 走到 S5，看会不会卡住正常工作流
- [ ] **量出**：走完要跑几次门、几次被拒、哪些拒绝是误报

### 阶段 4 · 视数据决定（下一轮才谈）
- [ ] 白名单要不要铺开
- [ ] 循环要不要做

## 八、判据（顺序不能颠倒）

1. **不许把"检测到"说成"强制"** —— `sch status` 已经能检测 S1–S6，
   但那不是强制。本轮完成的标志是**它会拒绝**，不是它会显示。
2. **每条能力配一个「故意跳步 → 必须被拒」的测试**。
3. **NOT RUN 标 NOT RUN** —— 没跑过的门、没验的环境，一律照实标。
4. **不许为了跑通而放宽现有的门**（`sch gate` 三态、`card` exit 码、`equivalence`）。
5. **不破坏基线**：

```
pytest       5146 passed / 4 skipped
go test      17 包无 FAIL
connector    1241/1241
布局单测      124 passed
layout verify 14 项全 PASS
plan SHA     frontier-i 27a311f6… · selftest d0c7ef5b…
```

---

## 九、最大的坑（先写下来）

**给 184 个动作分相位会分错。**

分错的后果不是"漏了一个门"，是**正常做板被卡住**——那比没有强制更糟，
因为用户会去找绕过办法，然后永远绕过去。

所以：**先只强制一个转换（S5 → 交付），跑过真实任务，再谈铺开。**

## ADR-001 页面模板按实测数据（含标题栏 keep-out），不硬编码 A4/角落

- **状态**：accepted（2026-10-29）
- **决策域**：L1 资产 + L2 规则
- **关联**：设计文档 §1、§3（R1/R2）；契约 §1.1

### 背景

v1 的 `easycirq/scripts/sch_layout_plan.py` 把页面与标题栏写成常量：页面 `1170×825`、边距 `12`、标题栏 `610..1170 × 12..380`。这套常量与实测模板并不一致；同一轮训练还暴露了“落点前没有量块尺寸，器件顶出图纸、压标题栏”，后续又出现“块比框大、框内大片空白”。更关键的是，模板并不是固定的：

- `easycirq/references/sheet-templates.json` 明确写着：EasyEDA Pro **没有设置纸张尺寸的 API，也没有独立的标题栏 bbox**；keep-out 只能由 live sheet bbox 按**长宽比匹配模板**后再按比例裁角得到，默认回退是右下角 `0.6×0.24`。坐标系是 **y-up**，标题栏在 bbox 的**右下角（高 x、低 y）**。
- 仓库内的离线证据也不等于常量示例：`tests/annotation_layout/fixtures/photo-led-v14/sheet.json` 记录的标题栏是 `460..1160 × 10..190`，页面 `1170×825`、内框 `10..1160 × 10..815`；契约示例又是 `610..1170 × 12..380`。三组数字说明“写死一个矩形”必然在某个模板/工程上错。
- 模板变化（横向/纵向、A3/A4、标题栏隐藏、站点差异）会让写死的可用区整体偏移；这类错误在离线看不出来，到了真机才以“压标题栏/出界”出现。

### 决策

1. 页面模板是**数据资产**：`easycirq/assets/page-template.json`（schema `easycirq-page-template/v1`），由 `easycirq sch sheet-geometry` 实测生成，至少包含 `page{width,height,margin}`、`title_block{rect,provenance}`、`regions[]`。
2. 标题栏 keep-out 以**实测矩形**为准；`regions` 由脚本从 page + title_block 计算（左条 + 右上条），允许人工覆盖，但覆盖结果必须通过“regions 互不重叠、不压标题栏、并集覆盖可用区”的校验。
3. 求解器与标签器**只从模板对象读几何**，不得出现 `1170`、`825`、`12`、`610`、`380` 之类模板常量；模板加载失败或 provenance 不可接受 → `blocked`。
4. provenance 分级：`sch sheet-geometry`（实测，首选）> `official-svg-vectors`（离线导出，可用于离线规划）> `fallback-ratio`（按长宽比回退，仅限离线实验并显式告警）> `none`（不可用）。进入 EDA 的 plan 至少要求非 `none`；`fallback-ratio` 必须在 plan 里留警告并由人确认。
5. 标题栏隐藏是合法模板，但必须在资产中显式声明（keep-out 为空且 provenance 明确）；“没读到标题栏”不能自动当成“没有标题栏”。

### 备选与不采用理由

| 备选 | 不采用理由 |
|---|---|
| 继续硬编码 A4 横向 + 右下角 | 实测模板与常量不一致；换模板/站点/图幅即错；已有“压标题栏、出界”现场 |
| 只按 `sheet-templates.json` 的比例回退（0.6×0.24） | 长宽比无法区分同比例模板；回退只应作为兜底，不能替代 `sheet-geometry` 实测 |
| 求解时现场问 EDA 要标题栏 bbox | 求解必须离线、可批量、可复现；EDA 单写者、慢、会卡死（FX-01），不能在求解循环里读 |
| 假设标题栏永远在右下角 | 横向模板通常如此，但纵向/隐藏/自定义模板不保证；契约要求 keep-out 来自实测，不是方位假设 |
| 把 regions 写进模板文件手工维护 | 容易与 page/title_block 漂移；应由 page + title_block 计算，人工只做覆盖并校验 |

### 后果

- **正面**：换模板不改代码；R1/R2 的判定有唯一几何来源；离线与真机对同一份模板达成一致；模板错误只修一个资产。
- **代价/风险**：多一份测量与版本维护；`fallback-ratio` 可能给出“看起来能用”的错 keep-out；隐藏标题栏的语义需要显式字段。
- **缓解**：schema 校验 + provenance 告警 + 至少覆盖“横向 / 纵向 / 隐藏标题栏”三种 fixture；任何 R1/R2 回读失败都反查模板版本。

### 复测触发

1. 换图纸模板/图幅/方向（A4→A3、横向→纵向）。
2. EDA 或连接器版本升级，`sheet-geometry` 输出字段/语义变化。
3. 出现 `fallback-ratio` 或 `none` provenance。
4. 任一工程在 apply 回读中出现 zone 压标题栏、出界（R1/R2 失败）。
5. `sheet-templates.json` 的比例表或角点定义变更。

## ADR-002 分页先于落位

- **状态**：accepted（2026-10-29）
- **决策域**：L2 规则 + L3 工具
- **关联**：设计文档 §1、§3（R6/R7）；契约 §5

### 背景

v1 是“单页装箱”：把模块塞进一张页面的 regions，塞不下就 `blocked` 或 unplaced。第一轮训练直接出现“块太多 blocked”；夜间流程也明确“页面合并/拆分必须遵守页面预算，不能因为求解器失败自动新开页”。另一方面，模块是布局原子：把同一个功能块拆到两页，会让网络标签、阅读顺序和后续返工全部失真。

如果让 zone_solver 在排不下时自行加页，会产生三个问题：页数不可预测（每次求解可能不同）、模块可能被拆开、EDA 预算失控（每页一次 apply）。因此页数必须在落位之前由独立阶段决定。

### 决策

1. `pagination.py` 是独立阶段：输入模块清单 + 亲和组 + 模板，输出页数 N、每页模块分配、页间阅读顺序。
2. 算法按契约 §5：先按亲和组（同电源域/同接口）聚簇；按可用面积下界得最少页数 N0；贪心/首次适应把聚簇分配到 N0 页，超面积则 N0+1，直到全部放下。
3. 分页结果**冻结**后，`zone_solver.py` 只在单页内工作；不得加页、不得拆模块、不得把“排不下”变成“再开一页”。
4. 跨页信号用同名网络标签/端口表达；页间阅读顺序写入 page plan。
5. 达到页数上限仍放不下 → `blocked`，给出“拆功能/换模板/减模块”的建议，不静默扩页（上限见 Q7）。

### 备选与不采用理由

| 备选 | 不采用理由 |
|---|---|
| 单页装箱，排不下就 blocked | 多模块工程直接不可用；第一轮已出现“块太多 blocked” |
| zone_solver 排不下时自动加页 | 页数不可预测、模块可能拆开、EDA 次数失控；违反“页数=规划结果” |
| 人工指定页数/每页模块 | 不可扩展、容易把亲和组拆开；人给的是约束，不该是坐标级决策 |
| 所有页联合优化（全局装箱） | 组合爆炸、难解释、难复现；先做确定性贪心，benchmark 证伪后再升级 |

### 后果

- **正面**：页数可预测、可审计；模块不跨页；每页的 apply 预算固定；分页错误可以在离线单独测。
- **代价/风险**：贪心可能留下半空页；亲和组来源不准则分页质量差；页数上限是新的策略参数。
- **缓解**：benchmark 记录 `page_count` 与 `page_utilization`；亲和组优先从模块计划读；上限触发时给结构化建议而不是硬失败。

### 复测触发

1. 实际 `page_count` 持续高于预期，或 benchmark 显示页均利用率低于 0.45。
2. 亲和组来源变化（模块计划 → netlist 自动推导，或反之）。
3. 单工程模块数超过既有样本（例如 >20 个模块）。
4. 出现“为了放下而建议拆模块”的情况（说明分页/分区策略需要重定）。
5. 页数上限 Q7 定值后。

## ADR-003 硬规则验证器门禁 EDA

- **状态**：accepted（2026-10-29）
- **决策域**：L2 规则 + L3 工具
- **关联**：设计文档 §3、§4；契约 §0

### 背景

v1 的把关主要靠 EDA 自己：`sch frame apply` 会拒绝重叠的 zone（FG-02），`layout-lint` 在落点后检查。但这套门禁既不完整也太晚：

- frame apply 只挡“zone 重叠”，不挡器件出界、压标题栏、文字碰撞、模块间距不足。
- FG-03 的“标题压相邻块网络标签”是导出图肉眼发现的，规划器的 `title_clearance_violations` 只算本块，挡不住跨块文字碰撞。
- 真机写入慢且可能卡死（FX-01：单次调用挂到 15 min），失败后返工成本极高；在真机上才发现几何错误，等于用最贵的资源做最便宜的检查。

离线几何检查是毫秒级、可枚举、可测试的；把硬规则前移，才能在落点前把“必然失败”的方案砍掉。

### 决策

1. `hard_rules.py` 对一份完整 page plan 跑契约 §0 的 R1–R7，输出 `findings[]` 与 `verdict`（`pass` / `blocked`）。
2. `verdict=blocked` 时，`layout_engine.py` 不生成 apply 命令；`sch_layout_apply2.py` 在执行前再次校验 verdict 与 plan 哈希，双重门禁。
3. 硬规则是**门禁**不是评分：质量分再高也不能抵消一条 violation；benchmark 的 `score` 只用于候选排序。
4. 落点后，apply 用同一组可测谓词对回读结果复检（R1–R5 的几何部分）；回读漂移超容差即失败，不自动重试。
5. findings 必须可定位：规则号、页码、对象 id、矩形、期望/实际；禁止只返回布尔值。

### 备选与不采用理由

| 备选 | 不采用理由 |
|---|---|
| 继续依赖 `frame apply` 拒绝 + 落点后 lint | 只覆盖 zone 重叠；出界/标题栏/文字/间距都漏；发现太晚 |
| 只做 warning，不阻断 | 现场已经证明“看到警告仍继续”会反复返工；门禁必须硬 |
| 落点后人工看导出图 | 不可复现、不可批量、依赖个人；与“机器能判”的 DoD 冲突 |
| 在 apply 内部做几何修正（自动挪块/裁框） | 会把“验证”变成“边执行边改”，plan 与结果不一致，无法审计 |

### 后果

- **正面**：失败前移、返工减少；plan 可审计；R1–R7 每条都能单测；apply 只需处理“计划正确但执行漂移”。
- **代价/风险**：validator 必须与 EDA 的几何语义保持一致（bbox 定义、描边、y-up、取整）；过严会误杀可用方案，过松会漏。
- **缓解**：用真实失败做 violation fixture（FG-01/02/03 各一条）；对“边界接触/取整误差”写明确容差；回读发现 validator 漏检时，先补规则再放行。

### 复测触发

1. EDA/连接器的几何语义或 `frame apply` 行为变化。
2. 出现新的失败类（taxonomy 新增 FG/FT 条目）且现有 R1–R7 挡不住。
3. validator 误报导致可用 plan 被 blocked（记录误报样本）。
4. 回读发现“validator pass 但真机失败”（漏报），必须补规则/测试。
5. 任何 apply 绕过 verdict 的事件。

## ADR-004 离线文字/标签求解 + 单次 apply

- **状态**：accepted（2026-10-29）
- **决策域**：L3 工具 + L4 测试
- **关联**：设计文档 §1、§4；契约 §2（`text_metrics.py`、`label_solver.py`、`sch_layout_apply2.py`）

### 背景

文字是 v1 最晚暴露、最难返工的一类问题：第一轮“分区标题与块内网络标签打架（同一高度）”，后续 MEMS 区标题仍可能压到 ES8311 右侧标签。根因是标题只保证在本块上方 `titleGap`，没有把相邻块的标签纳入避让；而检测只能靠导出图。

同时，真机不是试验场：单工程落点分钟级，`block-apply --json` 可能卡分钟级，daemon 还可能卡死（FX-01）。在真机上试字号/标签位置，既慢又不可复现。文字 bbox 完全可以用字号表离线估算，标签位置也是离线可组合搜索的——前提是度量资产准确。

### 决策

1. `text_metrics.py` 与 `device_metrics.py` 提供离线文字/器件度量；`label_solver.py` 在落点前放 net label / 文字，满足 R5（文字互不碰撞、不压框线）。
2. 只有 `sch_layout_apply2.py` 接触 EDA：把已验证的 page plan 转成命令/playbook，按计划落点一次。
3. 真机上不做参数搜索：不改 gap、不改字号、不挪标签；失败就回离线改 plan，产生新哈希再执行。
4. apply 后必须回读 + 导出图；回读文字 bbox 与 plan 比对，超差即失败并留证。
5. 文字求解无解（密集/未收录字号/旋转不支持）→ `blocked`，不允许“先放上去看看”。

### 备选与不采用理由

| 备选 | 不采用理由 |
|---|---|
| 让 EDA 自动摆放标签，再人工修 | 不可控、不可批量；碰撞仍在，且人工修不可复现 |
| 真机迭代调字号/位置 | 慢、会卡死、预算不可控；同一输入可能得到不同结果 |
| 导出图后人工挪文字 | 事后返工，破坏 plan/结果一致性；无法作为门禁 |
| 只用固定偏移放标签，不做碰撞求解 | FG-03 已证明固定 `titleGap` 不够；相邻块标签密度不同 |

### 后果

- **正面**：文字问题在毫秒级离线暴露；plan 确定、可回放；真机只做一次执行与回读，预算可控。
- **代价/风险**：文字度量是估算，与实际渲染有偏差；字体/字号/旋转/描边变化会让估算失真；apply 必须幂等且能识别“计划已过期”。
- **缓解**：度量资产记录版本与样本；建立“估算 vs 回读”的偏差基线；偏差超容差先修度量再放行；apply 绑定 plan 哈希与页面身份。

### 复测触发

1. 回读文字 bbox 与估算偏差超过容差（连续多个工程）。
2. 字体、字号层级、网络标签样式或 EDA 渲染版本变化。
3. `label_solver` 的 `blocked` 比例升高（说明度量或策略不够）。
4. 出现“离线 pass、真机文字仍碰撞”的漏报。
5. apply 从单次变成需要重试/补丁流程。

## ADR-005 版本化度量资产 + 失效触发

- **状态**：accepted（2026-10-29）
- **决策域**：L1 资产
- **关联**：设计文档 §2、§6.1；契约 §1.2/§1.3；[sedimentation-protocol.md](sedimentation-protocol.md) 的 L1

### 背景

度量资产是“尺子”，尺子错了，后面所有几何都错。现场已经量到漂移：

- 同一块 ES8311：第一轮 `560×340`，最终资产表 `521×309`。
- WROOM 的 `block-apply --dry-run` 估算 `460×100`，真实落位 bbox `245×420`（高度差 4.2 倍）。
- 早期 benchmark 的 `ENVELOPES` 与资产表不一致（wroom 460×100、es8311 560×340），导致基准不可信。

这些不是“偶发误差”，而是**资产没有版本/没有失效检查**的必然结果。沉淀协议要求 L1 带 `measured_at` 与版本字段；与当前块定义/客户端不符即重测。

### 决策

1. 三份资产全部 schema 化并带版本：`page-template.json`（v1）、`text-metrics.json`（v1）、`device-metrics.json`（v1）。
2. 每份资产记录：`measured_at`、EDA/连接器版本、站点（easyeda.com / lceda.cn）、测量命令、样本量、owner；缺任一项视为过期。
3. **单一数据源**：模块、测试、benchmark 只读资产，不复制数字；代码里不保留“默认包络/默认字号”兜底。
4. 失败关闭：未收录器件/字号、halo 缺边、模板缺字段 → `blocked`；不用估算值静默替代。
5. 版本升级规则：字段/语义变更升 schema 版本；数值重测只更新 `measured_at` 与值，但必须在变更记录里写“旧值→新值、影响范围”。
6. 过期检查进入 CI/夜间收口：资产超过 30 天、EDA/符号库版本变化、块内器件变化 → 重测；重测后跑 benchmark 与 validator 回归。

### 备选与不采用理由

| 备选 | 不采用理由 |
|---|---|
| 把尺寸写成代码常量 | 已导致基准与资产不一致；换器件/EDA 版本即错，且无人知道该改哪 |
| 每次求解前现场测量 | 求解必须离线；EDA 单写者、慢、会卡死；无法批量/复现 |
| 缺数据时用“经验估算”兜底 | 会静默产出错图；WROOM 4.2 倍误差就是估算的代价 |
| 只存一份大 JSON、不分 schema | 无法独立升级/校验；模板、器件、文字的失效触发不同 |

### 后果

- **正面**：几何可复现；错误定位到“哪把尺子过期”；基准与实现共用同一数据；变更可审计。
- **代价/风险**：测量成本；资产过期会阻塞（这是有意的）；owner 不明确时资产会腐烂。
- **缓解**：测量 SOP 单执行器串行；变更记录模板化；夜间收口固定跑过期检查；缺失数据时给“需要重测哪些项”的明确清单。

### 复测触发

1. EDA、连接器、符号库或站点（easyeda.com ↔ lceda.cn）变化。
2. 标准器件的符号/封装/附件（stub/flag/net label 风格）变化。
3. benchmark 残差或 apply 回读偏差连续超容差。
4. 资产 `measured_at` 超过 30 天（或无 `measured_at`）。
5. schema 字段/语义变更，或新增标准器件/字号。
6. 出现“按旧资产规划、真机 bbox 明显不符”的案例。

## 7. 决策生命周期

| 状态 | 含义 | 操作 |
|---|---|---|
| `proposed` | 方案讨论中，未作为实现依据 | 可改；不进契约/代码 |
| `accepted` | 当前实现依据 | 改动需新增/修订 ADR，并写复测触发 |
| `superseded` | 被新 ADR 取代 | 保留原文，标题下加 `superseded by ADR-xxx`，不删除 |
| `rejected` | 评估过但不采用 | 记录理由，防止重复讨论 |

新增 magic number 的最少信息：值、单位、来源（实测/契约/推导）、有效条件、复测触发、owner。缺任一项只能算草稿，不能进代码默认值。

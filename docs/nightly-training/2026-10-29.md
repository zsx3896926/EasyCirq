## 02:00–04:00 第二轮：量尺寸闭环与执行器

### 关键教训

1. **dry-run 给的“块估算”不可靠**：WROOM 块 dry-run 报 460×100，真实落位后 bbox 是 245×420（模组本体高 420）。必须用“真实落位 → 读 components.list includeBBox → 反写包络”来量。
2. **分区框与块的包含关系必须用实测 bbox 重建**：先在空页落块，量 bbox，再一次性画 frames；否则旧 frame 标题会残留、分区与块错位。
3. **分区边要按最近邻块中点封顶**，否则 padding/titleGap 会让相邻 zone 重叠，`sch frame apply` 直接拒绝。
4. **trim 要选重叠较小的轴**：按 y 一刀切会把“上下堆叠”的 zone x 范围切反（minX > maxX）。
5. **块重叠判定不能用 (x,y,w,h) 的 _overlap 去套 bbox**，会误报 review。

### 流程定型（nightly loop）


## 05:00–06:20 第三轮：执行器产品化与守护进程卡死

### 发现

1. **执行器会卡死**：连续写入后 daemon 的 “write/document transition is being verified” 状态可能永不释放，单个 CLI 调用挂到 15 min 超时。处理：`easycirq daemon stop` → 重启 daemon（connector 会自动重连，doctor 恢复 ok），再继续。
2. **provenance group 命名**：`sch group list` 里块实例组名是 `<block-short-id>(<instance>)/<net>`（不带 `block.` 前缀）；`--json` 结构是 `{groupsByPage: {pageUuid: [...]}}`。用 `sch group-move --groups g1,g2,...` 才能带动桩线与 netflag。
3. **块重叠多来自附件（stub/flag）而非器件本体**：加大块间距（gap 80）比反复微调原点有效。
4. 把实测包络沉淀成 `easycirq/assets/block-envelopes.json`；规划器支持 `--envelopes`，缺 envelope 时自动查表。

### 新增

- `easycirq/assets/block-envelopes.json`（11 个块实测 W×H + 页面/标题栏尺寸）。
- `easycirq/scripts/sch_layout_plan.py --envelopes`：块只给 id/title 也能排布；查不到包络 → blocked。
- `tools/sch_layout_apply.py`：规划落盘后的 EDA 执行器（打开项目→clear→逐块落位→实测→provenance group 校正→重建 zone→导出→指标）。
- 规划器测试 8 个用例。

### 指标格式（每工程）

`{blocks, fits, overlaps, apply_exit, zones_reapplied, export_exit}` + PNG；后续加入 `wires_total/wires_ok` 与 `style_score`。

### B/C 失败根因（环境/接口层）

1. **windowId 会变**：daemon 重启/连接器重连后窗口 id 变化，hardcode 的 --window 失效 → `project open failed: window ... is not connected`；必须先用 `project info` 取 `windowId`。
2. **`block-apply --json` 会卡分钟级**：真实落块加 --json 可能长时间不返回；改用“落块前后 designator 差集”识别新器件。
3. **`sch clear` 可能返回 ok 但页面没清空**（12 个 part 仍在）：必须落块前校验 components.list 零件数=0，否则中止，不能在残留上叠加。
4. **frame 回读浮点误差**：zone 坐标带小数时 `width: got 419.7, expected 419.66408` 直接失败；全部取整。
5. daemon 的 write-transition guard 长时间不释放 → `daemon stop/start` 清理，连接器会自动重连。

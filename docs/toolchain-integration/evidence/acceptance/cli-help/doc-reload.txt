Save a document, close its tab, and reopen it — a real reload, unlike
"doc switch" which only changes the foreground tab.

Why: a freshly CREATED PCB document's copper-pour reflow keeps using the rules
snapshot taken at creation — writing rules (pcb drc-rules-set) and re-pouring
(pcb pour-rebuild) have NO effect until the document is closed and reopened.
After a reload the reflow honors the current rule configuration (clearance AND
thermal-spoke generation). Run "pcb pour-rebuild" after reloading a PCB.

The target document is saved first (schematic.save / pcb.save by type), so no
edits are lost. Defaults to the active document; pass a name/uuid to reload
another (it is brought to the front first).

The reopen leaves the reloaded document foreground, so reloading a NON-active
page would move the active tab. This command restores the pre-reload active
document afterward and reports it as "activeRestored", so the ★ does not drift
(issue #67).

Usage:
  easycirq doc reload [name|uuid] [flags]

Examples:
  easycirq doc reload                      # reload the active document
  easycirq doc reload PCB3 --project ceshi # reload a specific PCB
  easycirq pcb pour-rebuild                # then re-pour under the refreshed rules

Flags:
  -h, --help   help for reload
      --json   emit JSON instead of a line

Global Flags:
      --doc string                pin every mutating action to this schematic page / PCB (uuid or name): the CLI switches to it and confirms via live document.current before editing, refusing rather than land the edit on whatever page is foreground — removes the doc-switch race
      --force-stale-read string   deprecated compatibility option; stale PCB reads now continue with staleRisk and authoritative workflows still save, reload, then read back
      --host string               daemon host (default "127.0.0.1")
      --ports string              daemon port range (start-end) (default "23111-23120")
      --project string            route by project name/uuid instead of --window (survives windowId churn)
      --skip-version-check        deprecated compatibility option; version differences are diagnostic and no longer block actions
      --window string             EasyEDA window ID (usually prefer --project)

# EasyCirq 终极目标

## 一句话

**让一个不懂 EDA 的人，用日常语言说清"我要什么"，就能拿到一块有证据、可复现、能打样的板**——AI 可以独立完成，但每一步都必须先离线跑通再上真机，且没有任何一步能靠"看起来没问题"蒙混过关。

## 终局体验（客户侧）

客户说：**「做一个能测温度、超温就响的板子」**

客户看到四样东西，别的都不需要看：

| 阶段 | 客户看到 |
|---|---|
| 开工 | 一句确认：能不能做、大概多少钱、多久 |
| 设计 | 一张原理图 + 一份 BOM（关键部分高亮，术语点开有白话解释） |
| 上机前 | **一张卡**：绿/黄/红 + "还差什么" + "下一步做什么" |
| 打样后 | 一张验收卡：焊好没有、通电没有、功能验没验 |

客户**永远不需要知道**：daemon、connector、typed action、KPI、gate token、快照、回读。

## 系统不变量（任何情况下都不能破）

1. **未过离线门禁，任何写入被 daemon 拒绝**——是 403，不是建议。
2. **每条结论带证据**（脚本名 + 输出），没做的标 `NOT RUN`。
3. **保存成功 ≠ 写入成功 ≠ 重开仍在 ≠ 质量通过**，四件事分开报告。
4. **不为清告警改电气事实**（不改网名、不删保护、不伪造 NC）。
5. **离线通过 ≠ 真机通过 ≠ 实物可用**，三级证据不互相冒充。
6. **缺证据 = BLOCKED**，不是"默认通过"。

## 终态验收指标（全部可测）

| # | 指标 | 目标 |
|---|---|---|
| 1 | 首次可用时间（装到第一条审计） | ≤5 分钟 |
| 2 | 客户需理解的工具术语数 | 1（"板子"） |
| 3 | 每个决策点客户需看的卡片数 | 1 |
| 4 | 失败可解释率（拒绝时给出下一步） | 100% |
| 5 | 无令牌写入被 daemon 拦截率 | 100% |
| 6 | 交付卡与实测证据一致率（不虚报） | 100% |
| 7 | "我要什么" → "能打样"全链路可追溯 | 100% |

## 三层的终局形态

| 层 | 终局 |
|---|---|
| 执行层（Go） | 所有写入都过 gate；所有读取都可回读；失败都带下一步 |
| 方法层（skill） | 18 项 KPI 是**尺子**不是目标；KPI 达标才允许写；文档只写"判据/动作/禁止/指针" |
| 分发层 | 一个 MCP server（跨宿主）+ 一个 `setup` 向导（装完即用）；客户零概念接入 |

## 明确不做

- 不做 EDA 渲染器，不替代 EasyEDA 本身。
- 不做"一键出板"的黑箱：必须保留证据链与阻断项。
- 不承诺未验证的"量产可用"。
- 不为了降低门槛而放宽门禁；门槛低在**入口**，不是低在**标准**。

## 达成判据

一位不懂 EDA 的客户，在不看任何文档的情况下：

1. 一条命令装好；
2. 一句话说出需求；
3. 拿到一张写着"可以打样 / 还差什么"的卡；
4. 打样回来后拿到验收卡。

**四步全程没有人工介入解释工具概念——目标达成。**

### 仍未做的（NOT RUN）

| 项 | 阻塞原因 |
|---|---|
| 实物打样与验收 | 需要下单、收货、焊接、通电、实测——AI 无法独立完成 |
| 跨机器复现 | 只有同一台机器上的隔离目录安装验证 |
| 原理图视觉正确性 | 本机无确定性 SVG→PNG 工具链，只能验证文件含预期图元与标签 |

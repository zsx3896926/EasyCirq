# Agent协作契约

## 三方分工
| 角色 | 承担的事 |
|---|---|
| 用户 | 描述目标、已有东西和真实约束，决定重要的功能/预算/外观取舍 |
| 当前Agent + 本Skill | 理解需求、查资料、推荐/核算、组织阶段、调用工具、恢复失败、解释结果与交付 |
| EDA执行能力 | 按真实协议读取/修改/保存工程，返回实际对象、检查和失败；例如 easycirq 运行时及其本机连接器 |
本Skill不是可独立运行的应用，也不包含LLM服务、EDA、自动布线引擎、设备固件或物料供应服务。Agent能否操作本机取决于真实宿主权限与工具，不能由对话口头声明补足。

## 多 Agent 协作

### 选择与分工

简单画图、局部改板默认单 Agent。独立资料核验、计算、布局候选和审查能与主任务重叠时，按需启用子 Agent，默认最多 3 个；用户或宿主限制优先。四层/高速等复杂任务先评估并行收益，不强制每个阶段多开。无子 Agent 能力时由主 Agent 串行承担，不要求用户换客户端。

| 角色 | 输入与交付 | EDA 权限 |
|---|---|---|
| 主 Agent / 指定写入者 | 维护设计意图、执行修改、回读、保存及最终验收 | 共享工程唯一写入者 |
| 电气 Agent | 原厂资料、选型、供电/接口计算，提交来源和适用条件 | 不操作共享窗口 |
| 布局 Agent | 冻结网表/几何/约束，提交候选、对象 ID、冲突及预测 | 不操作共享窗口 |
| 审查 Agent | 冻结导图与结构化证据，提交问题位置、依据和验证缺口 | 不操作共享窗口 |

只启用当前需要的角色。资料、几何测量和视觉审查形成不同证据；多个 Agent 意见一致不能替代原生检查、连接证明或保存重开。

### 快照与建议协议

委派时提供：任务范围、project/document/page 身份、快照版本或 SHA-256、只读输入路径、独立输出目录、约束和完成条件。子 Agent 返回：所用快照、对象 ID、问题/候选、证据路径、建议动作、影响范围及未验证项。建议明确标记未执行，不直接修改共享工程或公共交接文件。

主 Agent 是建议的唯一集成者。每批写入前回读当前身份与状态，核对相关对象、连接、几何和约束；基础快照过期时，重新分析或基于新快照重新验证建议，不能照旧坐标盲写。采纳后执行最小改动并重跑受影响检查；互相冲突的建议先统一设计意图再执行。

### 写入归属与交接

在项目交接中记录当前 owner、project/document/window 身份及进行中动作。该记录是协作约定，不是工具级互斥锁。未确认窗口空闲且归属明确前，不执行写入，也不切页、切工程、保存、reload、铺铜或探测共享 GUI；辅助 Agent 读取已导出的冻结文件。

需要转交写入权时：原 owner 停止并清理排队写入，完成或核实进行中操作，保存/回读并记录快照及未决项，明确释放；新 owner 确认接管后重新核对现场。超时或失联不等于释放，不能依靠滞后空闲通知抢窗口。归属未知时暂停共享写入，继续离线工作；有明确交接后恢复。

只有工程副本、EDA 执行会话/窗口路由和输出目录均独立，且已验证命令不会落到同一活动窗口时，才允许多个候选并行写入。只复制工程名或多开终端不算隔离。候选由主 Agent 选择并统一验收，不直接合并不同候选的铜对象。不同模块也不能在同一 PCB 上由多个 Agent 同时写入。

### 效率与结束条件

给每个子任务明确范围和结束条件，避免递归扩张、重复查资料和全量日志交接；阶段完成后汇总、回收闲置角色。记录总墙钟耗时、EDA 等待、返工、最终违规、调用/模型成本（可测时），在同范围基线上比较收益，不以 Agent 数量或累计并行工时宣称提速。

子任务完成不代表工程完成；主 Agent 负责最终连接、几何、官方导图与保存重开验收，以及统一交付。工具层未实现互斥锁或隔离时，如实说明，不能宣称并发写入已被技术阻止。

## 工作循环
每轮执行“读当前事实 → 明确下一步工程意图 → 调用合适能力 → 回读差异 → 更新状态 → 向用户说明必要结果”。不要在生成方案后就结束用户已要求的实际绘图任务。
保留目标、当前交付范围、用户已选偏好、关键假设、EDA工程/页身份、已完成/待做动作和已知问题。继续任务时重读现场，不要求用户重讲，也不依旧截图重复写入。
执行工具报错/字段变化时查当前help、工具Skill和日志，只重试已确认未完成部分。不要用无限重试或临时绕过接口换取“成功”。

## 部分写入、超时与冲突

执行器返回 `partial`、超时、`ok:false`、`noChanges:true` 或字段缺失时，先把它当成“实际状态未知”，按以下顺序处理：

1. **先停依赖写入。** 不继续铺铜、布线、删除、导出或基于计划状态生成 BOM；已排队的下游动作全部暂停。
2. **回读现场。** 原理图逐个对象读 pins/net，PCB 读 components（含 pads）、tracks、vias、pours、outline；不沿用失败回执、旧截图或上一轮 dump。
3. **对账键顺序。** 先用 `uniqueId`（原理图与 PCB 共有的身份），再用位号/designator，最后用坐标+层+对象类型。同名网不等于同一对象；坐标接近也要用 `primitiveId` 区分。
4. **只补差异。** 把“计划 / 实际 / 差集”写下来，只执行差集中的新增或修改；已存在的对象不重复 create，已删除的对象确认不存在后再继续。
5. **禁止整批盲重试。** 整批重放会制造重复器件、重复导线，或把一次局部失败扩大成多处修改。工具层细节见 [EDA 执行](eda-execution.md) §4 与 [工具动作陷阱](tool-gotchas.md) §2。
6. **记录部分计数与未决项。** 至少写 `requested / applied / verified / missing / conflicting / unverified` 六类数量，列出仍未解决的对象与下一步；未解决项写进 `design-state.json` 的 `open_items`，`blocking:true` 的不能进入下一门禁。
7. **冲突处理。** 实际对象与计划不一致（位号被改、网络被重连、器件被移动或删除）时，不回写覆盖，先记录冲突与差异；影响功能、网表或装配的冲突必须让用户决定，纯坐标/丝印冲突可按当前布局意图处理并留证据。
8. **重新进入门禁。** 部分写入修复后，重跑受影响的门禁检查（G2–G5 对应项），不能拿修复前的结论继续。

## 停止规则（DRC 平台期）

同一布局、同一网络优先级下，连续 3 轮 `pcb drc --json` 的违规总数改善都小于 30%，即触发停止规则：

- 改善率按 `(上一轮总数 − 本轮总数) / 上一轮总数` 计算；总数持平或上升按 0% 处理。
- 触发后停止在同一布局上继续挪线、挪过孔、改单条 track；从以下结构方案中选择并记录理由：重排布局（回到 G3）、改 4 层（回到 G4 叠层决策）、拆页/拆板，或如实报告 `BLOCKED` 并列出未收敛项。
- 每轮 DRC 前先 `pcb save` → `doc reload` → 重新回读，避免拿旧回执比较；轮次写入 `routing.drc_rounds`，触发写 `stop_rule_triggered:true`。
- 停止规则不取消关键网证明：DRC 数字下降不等于连接正确，仍需 G5 的 `net-path` 与保存重载证据。

方法细节与 2 层/4 层取舍见 [PCB 布线策略](pcb-routing-strategy.md)。

## 证据协议

**先落盘，再摘要。** 完整 JSON/PNG/CSV 先写到项目 `evidence/`（或制造目录），终端只输出结论、必要错误摘要和文件路径；不要用截断的 stdout 当证据，也不要把整段日志粘进对话。

每个证据条目至少记录：

| 字段 | 内容 |
|---|---|
| `command` | 实际执行的命令，含 `--json`、`--project`、`--doc` 等关键参数 |
| `exit_code` | 进程退出码；非 0 也要保留输出文件 |
| `timestamp` | ISO 8601，带时区 |
| `versions` | easycirq CLI/daemon、Connector、EDA 客户端版本；人工证据写工具与版本 |
| `path` | 证据文件路径（相对项目根） |
| `sha256` | 文件哈希；大文件至少记录一次 |
| `role` | 对应门禁证据角色（见 [门禁定义](design-gates.md) §13.2） |

- 支持 `--json` 的检查优先用 JSON；只有 human 输出时保留完整文本并注明 `format=text`。
- `staleRisk` 非空、`partial:true`、`ok:false`、`noChanges:true` 都不是权威证据；必须 `save → doc reload → fresh readback` 后重新取证。
- 视觉证据用 `sch export-image` 导出的 PNG/SVG，或已确认非 stale 的 `pcb snapshot`；旧截图、聊天里贴过的图不能当本次结论。
- 证据与最终板框/器件数/版本不一致时标 `STALE_EVIDENCE`，重跑受影响检查。
- 证据分层与计算记录要求见 [证据与轻量记录](evidence.md)；落盘与解析陷阱见 [工具动作陷阱](tool-gotchas.md) §1、§9。

## 最短接通路径
1. 从现有上下文和工具发现判断本地/云端、操作系统、AI客户端、EDA与执行器是否可用。用户未说明且无法读取时才问必要环境信息，不把云端容器当用户电脑。
2. 执行当前环境能完成的健康检查。已经连接就直入设计，不重复安排安装；缺哪一项解释哪一项。
3. 用户已要求“帮我安装/配置”时，在授权范围按官方当前说明准备和执行；没有该授权或工具实际需要额外权限时，给具体必要请求。不要额外索取“一切权限”。
4. 只能由用户做的动作（登录、EDA开关、打开实际页面等）一次一个，说明“点哪里/要看到什么”。等真实结果后再继续，不把执行、确认状态都推给用户。
5. 无本机通道则坦白“当前还不能在你的电脑里画图”，继续可独立完成的设计；提供最少的接入步骤，不声称换个聊天窗口就自动拥有本机能力。

## 阶段推进
把自然语言需求翻译成内部需求/模块/约束，Agent维护设计记录。把图纸、检查、文件的真实位置呈现给用户；不要求新手手动制作设计JSON、复制网表、拼接CLI参数。
原理图与PCB可按任务执行到任一阶段。建立内部工程检查点，用户未要求等待时自动检查并继续；偏好已明确就沿用。需要关键未知参数时只暂停依赖部分。
对于“做一个设备”，记录硬件、固件/算法、手机/网页端、制造装配与实测的依赖。可以用已配置相关能力完成授权工作；不能把未做的固件/手机端也算交付。

## G1 冻结后的变更影响

G1 之后新增或删除任何器件（包括“只是去掉调试排针”“USB 只供电所以删 ESD”），都必须先填项目 `docs/change-impact-<位号或变更号>.md`，再改工程。最小覆盖：

| 影响面 | 必须回答 |
|---|---|
| 原理图 | 符号/封装/引脚/网络怎么变；NC 与测试点怎么处理 |
| 网表 | 计划网表 vs 实际网表 diff 结果；单引脚网与悬空脚 |
| PCB | 已放置器件、布线、铺铜、丝印、板框是否受影响；是否需要重排/重布 |
| BOM/采购 | 行删除/新增、C 号、DNP、库存与 SMT 状态 |
| 测试 | 测试计划、测试点、验收项是否需要改 |
| 重新导入 | `pcb import-changes` 后逐对象回读，确认删除件真的消失、网表一致 |

- 静默删除是门禁失败：G1 的 `change_impact` 检查要求每个冻结后增删都有存在的文件；`pcb import-changes` 不会自动删除原理图已移除的器件，必须回读确认。
- 变更方法、等级、批次与回滚按 [变更影响决策](decisions/i01-change-impact.md) 执行，不在本文重复。
- 变更后重跑受影响门禁（G2–G5），旧证据标失效。

## 结果与故障翻译
将失败翻成“发生了什么 → 哪部分未完成 → Agent已处理什么 → 用户仅需做的下一步”。不要首屏输出栈、网络协议或十条排障命令。
不要用“完成度90%”掩盖关键动作不可用；分别报告图纸、PCB走线、检查、保存与实测。用户可以选择听细节，Agent仍需保留原始诊断便于复验。

## 立创商城与嘉立创服务衔接
以用户任务驱动供应链查询和制造准备：先保证工程可行，再将准确C号/商品、EDA绑定和装配变体连起来。公开查料、上传BOM、SMT匹配、购物车/订单和支付分别使用当前能力与真实状态，不把同一集团服务当一个共享库存API。
读取商城事实优先可用的专用工具/官方页面；不虚构采购接口、不在无授权时上传完整工程。遇到缺货，准备工程复核的替代方案；遇到登录/权限缺口，保留已做文件并给一个实际接续步骤。

## 完整idea的持续推进
用户委托的是可用设备时，按idea-to-product.md维护硬件、程序/交互、结构、供应制造和实测的依赖；此Skill提供方法，Agent按当前能力执行与协调。不要在DRC通过、BOM准备或贴片完成后把剩余程序/联调当用户自己负责的隐含事项。
用户只要局部工作时不扩大范围。缺实物/权限等真实阻断时，完成独立准备、记录已知状态并给可恢复接续条件；不因为“生态优先”虚构内部云服务或工厂代开发能力。

## 门禁与工具陷阱入口

阶段退出证据门见 [门禁定义](design-gates.md)：G2 未过不导入 PCB、不布局；G3 与 G4 未过不布线；G5 未过不进入制造；G6 未过不声称可下单。动作级陷阱与正确命令见 [工具动作陷阱](tool-gotchas.md)。三者分工：本文管协作、回读与记录，门禁文档管退出条件，陷阱文档管单条命令的实际行为。

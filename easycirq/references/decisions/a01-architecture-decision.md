# 架构决策记录：备选、代价、冻结与重评

> 用途：规定怎样把架构决定写成可复核记录。证据等级 E3（离线方法整理；本轮未重开原厂正文，未做硬件验证）。不能替代具体型号手册、误差/热/成本计算、EDA 回读与实测。

## 目录
1 触发条件；2 输入；3 Agent 可独立完成的判断；4 必须停下的条件；5 决策规则与表；6 改变哪个工程决定；7 完整案例；8 证据与验证方式；9 与现有资产的分工；10 来源、未知与重评触发。

## 1. 触发条件（A1）
| 深度 | 使用条件 | 产出 |
|---|---|---|
| D0 不建记录 | 局部、可逆、单文件改动，不跨模块，不改变接口 | 不留决策头 |
| D1 轻记录 | 一个不可逆或跨模块决定，且没有第二个可行备选 | 决策头 + 被选方案与代价 |
| D2 完整记录 | 两项以上可行备选，或需求、数量、供电、温度、认证可能变化 | 备选表 + typed block + 受影响对象表 |

- 触发比较：两项以上路线都能通过硬约束；决定跨 SCH、PCB、固件、BOM、测试；封装、电源拓扑或连接器体系难改；数量级、供电或认证要求变化。
- 不触发或跳过：只有一条路线满足安规、接口或供货；纯布局重排且不改网表；一次性原型且明确不迁移。跳过必须写理由与有效期。

## 2. 输入
- Agent 能自己读：项目验收表、既有淘汰表、`source-register.md`、脚本输出、现有连接表；先读再引用，写 path:start-end。
- 必须问用户：使用场景、目标数量、预算与外观偏好、外壳与认证约束；一次问清，不让用户填工程规格书。
- 缺失即停：验收项不可观察；成本比较缺数量场景；比较依赖价格/库存但页面无数据。写“待查”并停下，不用默认值补。

## 3. Agent 可独立完成的判断
- 把需求翻译成可观察验收项，剔除没有验收项支撑的功能。
- 按 5.1 的维度逐项比较，给出排除判据与重评条件，识别受影响的 SCH、PCB、固件、BOM、测试。
- 重算可算部分；不能算的写 NOT RUN，不写成通过。

## 4. 必须停下的条件
- 比较依赖未核对的物理脚、封装、pinmux、ADC 限制或隔离耐压。
- 关键代价（价格、库存、MOQ、包装、认证）没有可核对来源，却要用它淘汰方案。
- 两个备选在硬约束上无法区分，只剩偏好；交给用户按用途与预算选择。决定涉及安全、安规或电池保护边界而手册条件未读时同样停下。

## 5. 决策规则与表
### 5.1 比较维度（A2）
| 维度 | 必须写 | 禁止 |
|---|---|---|
| 功能与约束 | 对应哪条验收项、缺它会违反什么；电压/电流/温度/封装/安规 | “更好”“更先进”；忽略硬约束比价格 |
| 成本构成 | BOM、面积、层数、装配、测试、认证分项；未核实写待查 | 无依据综合分、虚构价格 |
| 功耗与热 | 各状态电流、峰值与同时性、热耗散路径 | 只写典型值或只算平均 |
| 实现调试与软件依赖 | 新工具、新封装、调试口、下载方式；SDK/驱动/协议栈版本与许可 | “应该能做”“软件都有现成的” |
| 供应制造与未决 | 封装、可贴、包装、MOQ、生命周期；owner、截止点、停止条件 | 用商城库存推定可贴；未决项留空 |

### 5.2 排除判据与重评（A3）
- 排除只写可观测判据：计算越界、手册范围不满足、验收项缺失、封装/工艺不可行；一项硬约束不满足即可排除，不用加权总分掩盖。
- 每条被淘汰方案保留一行，并写“什么条件下反而应选它”；条件变化时先复评该行，不重新发明方案。

### 5.3 决策记录字段（A4）
| 字段 | 必填内容 |
|---|---|
| 备选 | 至少两个可行项；只有一项时说明为什么没有第二项 |
| 排除判据 | 逐项可观测理由，不用综合分 |
| 代价 | BOM、面积、功耗、热、测试、周期、供货、认证分项；未知写待查 |
| 假设与有效期 | 每条假设的来源、有效期、过期后的动作 |
| 冻结点与重评触发 | 什么证据齐备后不再改；需求、数量、供电、温度、距离、供货、认证变化 |
| 受影响对象 | SCH、PCB、固件、BOM、测试，逐项写状态 |

格式使用集成人维护的 `easycirq/assets/decisions/decision-record.template.md`；字段语义变更提给集成人，工作流不另建第二套模板。

### 5.4 过度设计检查（A5）
- 每个新增功能必须对应一条验收项；找不到就拒绝或延期，不先做“以后可能用”。新增功能按链计数：电源域、接口、调试口、测试项；能共享既有 3V3、I2C、U0 才允许合并。三问：不做会违反哪条验收？最简实现是什么？代价由谁承担？

### 5.5 需求变化后的重新决策（A6）
- 数量级、供电、温度、接口、认证、供货任一变化，重跑受影响对象表；未执行写 NOT RUN。冻结决定先标 superseded，旧记录保留；只改局部且不影响接口时用 local-only 记录。

## 6. 改变哪个工程决定
- 电源拓扑（LDO、Buck、Buck-Boost、充电器）：改变 SCH、PCB 热区、BOM、温升与续航测试。
- 封装与引脚、接口与电平、数量与制造路线、认证与外壳：改变 PCB 焊盘、固件配置、连接器、线束、BOM 包装、备损、SMT/手焊、测试抽样与 EMC/安规测试。

## 7. 完整案例
- [R4-CASE-A01：首发 25 块到 1000 台](cases/r4-case-a01-requirement-change.md)。决定：把 1000 台当假设需求重做代价与受影响项；电芯硬上限未确认前充电器子块 `blocked`，若规格书确认 ≤4.20 V 则 `rejected`，先解决充电器选型。代价：BOM、包装、热与测试计划全部重核。下一个检查：电芯规格书的硬上限/允许充电条件；若硬上限 ≤4.20 V，换 `VBAT(REG)` max ≤4.20 V 的型号；保护板只作协调。
- [R4-CASE-A02：对既有最小架构门的应用](cases/r4-case-a02-overdesign-gate.md)。决定：四项新增中只保留有验收项支撑的两项。代价：砍掉第二串口与独立状态灯子系统。下一个检查：I2C 地址与总线电容预算（待查）。

## 8. 证据与验证方式
- E1：本次核对原厂正文，或有真实 EDA 回读/实测；E2：通用方法，具体值须按型号重算；E3：离线分析、构造案例或推断。
- 本文为 E3：只整理记录方法与既有项目纸面结论，本轮未重开原厂正文、未运行 EDA、未实测；验证方式是逐条回指 path:start-end 与来源 ID，不能算的写 NOT RUN。不能证明具体器件的电气保证、热、成本、供货与整机性能；记录完整不等于硬件已验证。

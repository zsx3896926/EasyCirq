# 引脚与资源规划：分配顺序、冲突检查与未决项

> 用途：在 `module-integration.md` 的资源表之上补分配顺序、容量预算、换封装核对与映射规则。证据等级 E3（离线方法整理；本轮未重开原厂正文，未做硬件验证）。不能替代完整物理脚表、pinmux、封装 NC 清单与实测。

## 目录
1 触发条件；2 输入；3 Agent 可独立完成的判断；4 必须停下的条件；5 决策规则与表；6 改变哪个工程决定；7 完整案例；8 证据与验证方式；9 与现有资产的分工；10 来源、未知与重评触发。

## 1. 触发条件
| 深度 | 使用条件 | 产出 |
|---|---|---|
| D0 不建计划 | 单模块、无新增外设、全部复用既有资源 | 沿用 `module-integration.md:186-214` 的一行 |
| D1 轻更新 | 新增一个固定总线或不超过两个 GPIO | 更新资源表 + 保留清单，不建完整 JSON |
| D2 完整计划 | 新 MCU/模组、换封装、多外设，或 strap/调试/下载存在冲突风险 | 完整 pin plan + `pin_plan_check.py` + unresolved 列表 |

- 触发：新增外设、换型号或封装、复用启动 strap 脚、第二串口/第二总线、ADC 通道分配、连接器脚位变化。不触发或跳过：只改固件配置且引脚不变；只做布局重排；原型飞线且明确不迁移。跳过必须写理由与有效期。

## 2. 输入
- Agent 能自己读：模组/芯片完整物理脚表、封装图（NC/EPAD）、参考设计、`easycirq/references/projects/p01-low-power-wireless-sensor.md:383-396` 的既有固件脚表、`module-integration.md:186-214` 的 10 列资源表。
- 必须问用户：必须保留的调试/下载方式、量产测试点、哪些扩展是真实需求、能否接受跳线或飞线。缺失即停：完整物理脚表、pinmux 表、ADC 通道/衰减限制、封装 NC 清单；缺任一项写待查，不进入原理图落图。

## 3. Agent 可独立完成的判断
- 按 B1 建资源清单与容量预算，按 B3 给出分配顺序与保留项。
- 按 B4 做纸面冲突检查并运行脚本；按 B5 做同系列/封装逐脚 diff，把差异转成 PCB、固件与连接器待办。

## 4. 必须停下的条件
- 物理脚、pinmux、ADC 限制或封装 NC 未核对，却要给出“可接/不可接”的结论。
- strap 脚被外设占用且无法改启动方式；调试脚或下载口被占且没有替代救援路径。
- 同一 bank 电压不一致或电压域未知；封装未引出的脚被当成可用脚。
- 只有“模组通常这样接”“参考设计就是这么画的”这类依据。

## 5. 决策规则与表
**B1 资源清单与容量**
| 资源类 | 容量记法 | 不能算作可用容量 |
|---|---|---|
| GPIO | 按电压域与复用后的可用脚计 | 封装总脚数 |
| ADC/DAC | 按通道、参考、采样率与共用关系计 | “有 ADC”一句 |
| 定时器/PWM/DMA | 按实例、互补/死区能力、通道与触发源计 | 只看 PWM 通道数；默认每外设独立 DMA |
| 通信 | UART/SPI/I2C/CAN/USB 分开计 | 逻辑脚名相同即视为可复用 |
| 中断/时钟/调试 | 按中断源、时钟树、专用脚与调试口占用计 | 把专用脚或下载脚并入普通 GPIO 池 |

**B2 引脚限制**（逐脚必查）
- 启动 strap：复位采样窗内必须稳定，外围电容/按钮会拖偏；查 strap 表与采样窗。
- 调试：SWD/JTAG 或 U0 下载口被占会失去救援能力；查调试口表与启动配置。
- 默认态与电压域：复位/未启动/调试暂停/看门狗期间输出高、低还是高阻；同一 bank 只能同一电压，跨域必须电平转换。
- 模拟：ADC 通道、参考范围、衰减档与输入阻抗限制；模拟脚当输出即冲突。
- 封装与互斥：NC、EPAD、重复电源脚与未引出脚只按封装图与 pin list；同一物理脚不能同时承担两个外设，复用表写“复位后由谁配置”。

**B3 分配顺序**
1. 先锁不可替代项：电源、复位、时钟、strap、调试、下载、Flash 保留脚。
2. 再定固定总线并分配普通 GPIO：I2C/SPI/UART 先定 owner、上拉、片选与地址，一个总线只能有一个上拉 owner；扩展口最后分配，不得占用 strap 或调试脚。

**B4 冲突检查**
- 唯一权威是 `module-integration.md:186-214` 的 10 列资源表；本文不另建第二张资源表。`resources` 只写最终分配；候选、延期或已拒绝的资源写 `candidates` 并标 `status=deferred|rejected`，不得同时出现在 `resources`（脚本对 ID 与 kind+pin 双重检查）。检查重复物理脚、重复逻辑资源（同一逻辑脚被两个资源占用）、未知脚、ADC 资源落在输出脚或 `analog_used=false` 的脚、strap/debug 脚上的资源 ID/kind 不匹配、bank 电压不一致、封装未引出；缺字段输出 unknown 而非通过。

**B5 换型号/封装**
- 逐脚 diff 顺序：物理脚/pinmux → 封装 NC/EPAD → strap/boot → ADC 通道 → 调试/下载 → bank 电压；任一差异都要重跑 B4，并更新连接器脚、固件配置与 BOM，不得用“同系列所以兼容”放行。

**B6 映射到网表/连接器/程序**
- 只保留一张源表：物理脚 → 网络名 → 连接器脚 → 固件配置 → 测试点；网表、连接器表与固件配置引用同一网络名，不各自维护第二套映射。连接器脚序按 `module-integration.md:236-241` 的三方表写；未核对的 MPN/额定/配对端子写待查。

**保留清单与容量预算**
- 保留：调试口、下载口、复位/启动按键、每组已用总线的一个备用脚、一个扩展口；保留项不得被普通功能占用。容量预算按资源类记“总数 / 保留 / 已分配 / 剩余 / 来源”；手册未读时总数写待查，不填 0。

**unresolved 列表**
- 每项写：未知项、影响哪个决定、owner、何时必须补、缺它就不得进入哪一步、复评触发；未解决项不得从计划里删除。

## 6. 改变哪个工程决定
- 脚位与复用改变 SCH 网络名、PCB 焊盘与走线、固件配置、连接器脚序与测试点；换封装或型号再改变 BOM、钢网/焊盘、调试夹具与替代等级，并重跑 B4 与连接器核对。

## 7. 完整案例
- [R4-CASE-B01：第二串口与下载/调试口复用冲突](cases/r4-case-b01-pin-allocation-conflict.md)。决定：第二串口暂不分配，保留 U0 下载/调试。代价：少一个串口外设，扩展延后。下一个检查：模组完整物理脚表、pinmux、ADC 通道与封装 NC（待查）。

## 8. 证据与验证方式
- 本文为 E3；脚本输出同为 E3（离线纸面检查），实际运行可复现，但不构成 E1 硬件证据；`board_verified=false`。脚本只证明输入 JSON 通过/未通过所列纸面检查，不证明引脚表真实。
- 运行：`python easycirq/scripts/pin_plan_check.py easycirq/assets/decisions/pin-plan.r4p1.example.json`；stdout 单个 JSON，退出码 0 通过、1 有需复核 findings、2 输入错误。不能证明：物理脚存在性、pinmux 真实性、ADC 电气限制、封装 NC、时序与实测。

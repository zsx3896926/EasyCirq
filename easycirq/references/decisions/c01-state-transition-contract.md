# 工作状态与转换契约：三轴、恢复与 POR
> 用途：把“状态快照”升级为可执行的三轴转换契约，覆盖部分供电、恢复与断电再上电。证据等级 E3（离线方法整理；本轮未重开原厂正文，未做硬件验证）。不能替代器件 POR/BOR 门限、电源时序实测、总线释放测量与固件状态机实现。
## 目录
1 触发条件；2 输入；3 Agent 可独立完成的判断；4 必须停下的条件；5 决策规则与表；6 改变哪个工程决定；7 完整案例；8 证据与验证方式；9 与现有资产的分工；10 来源、未知与重评触发。
## 1. 触发条件（C1）
| 深度 | 使用条件 | 产出 |
|---|---|---|
| D0 不建契约 | 单电源、无休眠或复位源、无断电保持，状态不影响接口电平 | 沿用 `easycirq/references/module-integration.md:156-170` 的一行 |
| D1 轻记录 | 只有一个电源域，但存在休眠或看门狗 | 状态表 + 转换表，不建矩阵 |
| D2 完整契约 | 电池与外部供电共存、部分供电、可关断轨、用户插拔、升级/调试 halt、多复位源 | 三轴状态表 + 转换表 + 状态×接口矩阵 + POR 四项 |
- 触发：电池与外接电源共存、USB/适配器热插拔、负载开关或分区供电、看门狗/欠压/失联恢复、调试 halt、升级、断电再上电。
- 不触发或跳过：单电源常开且没有状态相关负载；纯布局重排；一次性飞线原型且明确不迁移。跳过必须写理由与有效期。
## 2. 输入
- Agent 能自己读：电源树与电流预算、`easycirq/references/module-integration.md:156-170` 的状态表、`:263-273` 的反灌路径表、项目测试计划、固件初始化顺序；每条写 path:start-end。
- 必须问用户：电池与外接电源是否可能同时存在；断电或复位后哪些输出必须归零；现场是否允许调试 halt；是否有 OTA/升级通道；可接受的恢复时间与数据丢失。
- 缺失即停：POR/BOR 门限与保持时间、复位源是否可观测、部分供电时谁给谁供电、升级平台证据。缺一项写待查，不用“通常能复位”补。
## 3. Agent 可独立完成的判断
- 按 C1 选深度，按 5.1 建三轴，按 5.2–5.3 填状态与转换；把不可观测的复位源标 unknown。
- 按 5.4 把 WDT、欠压、失联、POR 分成不同恢复类；按 5.5 列出 POR 四项待查；按 5.6 生成状态×接口矩阵。
- 按 5.7 判升级子项是否 applicable；按 5.8 列部分供电与反灌路径；把每个动作落到设计或验证项。
## 4. 必须停下的条件
- 不知道 POR/BOR 门限、保持时间或释放顺序，却要写“上电可靠”或“复位后安全”。
- 复位源不可区分（WDT、欠压、软件复位共用同一标志），却要设计不同恢复动作。
- 部分供电时反灌路径未画，或对端在自身断电时仍可能驱动。
- 平台没有 OTA/升级证据，却建立升级状态或写 acceptance=pass。
- 电池保护、充电终止电压或安全边界未核，却要靠状态机放行充电。
## 5. 决策规则与表
### 5.1 三轴
| 轴 | 取值示例 | 不能混用 |
|---|---|---|
| product_state | powered_off、por、boot、run、sleep、debug_halt、fault_recovery、upgrade | 把“充电中”当产品状态；它是 supply_condition |
| supply_condition | no_supply、battery_only、usb_only、usb_and_battery | 把“USB 插入”当转换本身；它是 supply_change |
| reset_cause | por、wdt、brownout、comm_loss、debug_reset、unknown | 把 comm_loss 写成复位；它可能只重启通信任务 |
### 5.2 状态记录（每个状态一行）
- 必填 entry、exit、completion。entry 写进入条件与谁拉哪根线；exit 写离开条件；completion 写可观测完成判据（电压、日志、总线释放、时间窗），不能写“正常”。
### 5.3 转换记录（每个转换一行）
| 字段 | 必须写 |
|---|---|
| trigger | 事件与判据（阈值/边沿/超时） |
| supply_change | 哪条供电路径变化，先断还是后断 |
| control | 谁在什么时刻拉哪根线（EN、CE、负载开关、复位） |
| load_state | 转换前后负载与总线状态 |
| completion | 可观测完成判据 |
| abort | 失败/超时/掉电时回到哪个状态、谁复位 |
### 5.4 恢复类
| 恢复类 | 判据 | 必查 | 不能假设 |
|---|---|---|---|
| WDT | 看门狗超时，电源未跌出范围 | 复位标志、外设复位、输出默认态 | 复位后总线自动释放 |
| 欠压 | 轨跌破器件 BOR/POR 或负载跌出推荐范围 | 门限、保持时间、复位释放 | 用 typ 门限放行 |
| 失联 | 通信超时但电源与复位正常 | 重试/退避、总线释放、对端状态 | 一律整机复位 |
| POR | 断电后再上电 | 5.5 四项 | 只写“上电复位” |
### 5.5 断电再上电（POR）四项
| 项 | 必须回答 | 未知时 |
|---|---|---|
| 阈值 | 哪条轨到多少伏、哪个器件先释放复位 | 待查，不得写 pass |
| 保持时间 | 复位低电平/电源稳定的最小时间与 RC 实际值 | 待查；RC 计算只作筛查 |
| 总线释放 | 复位期间谁高阻、何时允许驱动 | 待查；按 `D-S08` 的总线清除方法另测 |
| 对端不驱动 | 对端未上电/复位时是否经 ESD 二极管或上拉驱动本端 | 待查；按 `easycirq/references/module-integration.md:263-273` 画路径 |
- RC 只用于筛查：`t = -R·C·ln(1-Vth/Vdd)`，门限/延迟口径按 MCU-S06；算出的时间不是器件保证值，必须用实际门限与容差复算并实测。
### 5.6 状态×接口矩阵
| 状态 | 每列一个接口 | 必须写 |
|---|---|---|
| 每个状态一行 | 驱动器/接收器/上拉/可关断轨 | 电平或高阻、谁供电、是否允许驱动、转换后何时释放 |
### 5.7 升级子项
- 平台有 OTA/升级证据：建 upgrade 状态与转换，写镜像校验、回滚、断电中断、总线释放。
- 平台无证据（本仓库 P01/P02 均无 OTA 平台证据）：`applicable:false` + 理由 + `acceptance: PARTIAL/NOT RUN`；不得建立“升级中”状态冒充 coverage。
### 5.8 部分供电与反灌
- 每个部分供电场景写：哪条轨有电、哪条无电、电流从哪到哪、对端是否驱动、谁承担漏电。
- 至少覆盖：一方断电、双方断电、热插拔瞬间、可关断轨关闭后。路径表按 `easycirq/references/module-integration.md:263-273`，不另造分类；反灌到 VBUS 按 IF-S11，充电器终止电压/power path 按 PWR-S07，转换器启动/输出按 PWR-S09。
## 6. 改变哪个工程决定
- 改变 EN/复位 RC、电源路径与负载开关、上拉电源域、串联限流、理想二极管/ORing、固件初始化顺序与复位标志、测试计划与 BOM；可关断轨还改变变体与 DNP。
## 7. 完整案例
- [R4-CASE-C01：电池与 USB 外部供电共存节点的状态契约](cases/r4-case-c01-battery-plus-external-supply-states.md)。决定：三轴建状态，升级标 applicable:false。代价：POR 四项与反灌路径全部待查，不能放行充电配置。下一个检查：电芯规格书硬上限/允许充电条件与 BQ24074 4.23 V max 的匹配（硬上限确认 4.20 V 时 `rejected`；仅标称 4.20 V 时 `blocked`/待核）。
## 8. 证据与验证方式
- 本文 E3：只整理方法与项目纸面事实，本轮未重开原厂正文、未运行 EDA、未实测；`execution=OFFLINE_PLANNING`，`hardware_execution=NOT RUN`。

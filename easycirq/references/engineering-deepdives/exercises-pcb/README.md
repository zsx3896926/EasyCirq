# PCB 预布局审题练习使用说明

> 20 道单题 + 8 对成对案例。目标不是“找错越多越好”，而是学会区分五类判断：**明确错误、条件风险、有意取舍、看似异常实际合理、信息不足**。
>
> 题目在 [exercises.md](exercises.md)，成对案例在 [paired-cases.md](paired-cases.md)，参考答案在 [answers.md](answers.md)，独立试答输入在 [blind-prompts.md](blind-prompts.md)（v2 题面）。
>
> 所有题都绑定 [PCB 预布局基准集](../../pcb-placement-benchmarks.md) 的案例 id，或明确标为“构造题，不对应案例”。判据引用 [PCB 布局细节](../../pcb-placement-details.md) 的 PL 条目；机制解释见 [PCB 机制卡](../../pcb-lessons.md) 和 [PCB 工程习惯](../../pcb.md)。基准集为 15 条案例：12 条 `synthetic` + 3 条真实板派生（`D1`–`D3`，见[读法文档 §1.1](../../pcb-placement-benchmarks.md#11-证据等级synthetic-与-derived)），派生案例只用于跨案例对照，不新增题目。

## 怎么用

1. **先独立作答**：每题写结论类型（`可确认` / `条件` / `待补`）、机制、依据（案例 id / code / PL 编号）、还需补什么、建议动作，以及哪些是 `过度` 修改。
2. **再读答案**：对照四类标记，重点看自己有没有把“条件风险”写成“明确错误”，或把 `review` 写成 `acceptable`。
3. **对成对案例**：先写出“只改的那一个条件”，再判断结论是否翻转；没翻转时，说明该条件不是主导项，或说明离线判分没覆盖它。
4. **盲测**：用 [blind-prompts.md](blind-prompts.md) v2（v1 已试答、v2 已按评审修订）独立试答，不读 [exercises.md](exercises.md) 的类型标签和答案。
5. **不要背答案**：题目不抄案例坐标；换板/换叠层/换器件后必须重新判，不能把练习结论直接搬到真实工程。

## 评分维度

沿用基准集读法的五维（详见 [读法文档 §4](../../pcb-placement-benchmarks.md#4-五维评分维度)）：

| 维度 | 看什么 |
|---|---|
| 结论类型 | 是否区分 `可确认` / `条件` / `待补`，是否把软代理超阈值写成“已证实失效” |
| 机制 | 能否说出电流回路/回流、耦合路径、热路径、机械干涉，而不是只报 code |
| 证据 | 能否指到案例 id、finding code、检查 id、PL 条目；真实工程再指手册/网表 |
| 行动 | 修复是否与结论匹配；`blocking` 先改硬约束，`review` 先改主导项，不过度整板重排 |
| 未知 | 是否列出离线判分答不了的项（DRC/布线/阻抗/热/装配）并写 `NOT RUN` |

> 第一轮盲测的经验：结论类型是主要失分维度，且失分几乎全是“条件/待补/可确认”标记位移。v2 题面已要求“结论类型只写一个主标记 + 一句附加说明，并落在被问的那件事上”。

### 派生练习案例（D1–D3，不新增题目）

基准集新增的 3 条 `derived` 案例来自真实板回读 dump（8/23 器件子集、19 器件整板基线、一次被拒绝的直接移动），不是新的合成题。它们用来验证“**真实尺寸/单位换算（mil→mm）后判分是否仍成立**”，也可作为 X01/X04/X09/X19 的跨案例对照；**不改变 20 题数量与题型分布**。

| 派生案例 | 域 | 期望判定（以 `benchmarks.json` 为准） | 可用来练什么 |
|---|---|---|---|
| `D1-MCU-LDO-DECAP` | mcu | review：`distance_far` | 真实板 100 mil 去耦规则的换算；按焊盘距离而非中心距（对照 X01/X09） |
| `D2-PHOTO-LED-SENSE` | analog | acceptable：无 | “真实板基线在选定检查内通过 ≠ 整板无缺陷/已签核”；补 X19 的 `NOT RUN` 边界 |
| `D3-DUAL-BTN-D4-MOVE` | multi | blocking：`body_overlap` | 真实被拒绝的单件移动；移动前硬几何预检（对照 X04） |

用法：`python scripts/pcb_placement_benchmark.py --case D1-MCU-LDO-DECAP`（在 `easycirq/` 下）看 scorecard；判据与派生边界见[读法文档 §1.1](../../pcb-placement-benchmarks.md#11-证据等级synthetic-与-derived) 与 `docs/pcb-placement-training/derived-cases.md`。**不要**把这三条的子集结论写成“整板已验证/能打样”。

## 成对案例

8 对，每对只改一个条件（4 对来自基准集的 `*-PAIR` 变体，4 对是构造对照）。逐对写“改了什么 / 结论是否翻转 / 为什么”在 [paired-cases.md](paired-cases.md)：

| 对 | 基准 | 只改的条件 | 结论 |
|---|---|---|---|
| PC01 | `P1-MCU-MIN` → `P1b-MCU-MIN-PAIR` | 只移去耦电容到 `VDD`/`GND` 焊盘旁 | review → acceptable，翻转 |
| PC02 | `P2-BUCK` → `P2b-BUCK-PAIR` | 只把输入电容与 `SW` 电感靠拢 | review → acceptable，翻转 |
| PC03 | `P3-ANALOG` → `P3b-ANALOG-PAIR` | 只把模拟链整体挪离功率级 | review → acceptable，翻转 |
| PC04 | `P8-MULTI` → `P8b-MULTI-PAIR` | 只把连接器推到板边并让开固定件 | blocking → acceptable，翻转 |
| PC05 | `P7-WIRELESS`（构造对照） | 判定口径从包围盒改为“中心点落在净空内” | 同一布局 blocking → acceptable，翻转（假通过） |
| PC06 | `P1-MCU-MIN`（构造对照） | 判定口径从焊盘回路改为器件中心距 | 同一布局失败 → 通过，翻转（假通过） |
| PC07 | `P5-BATTERY`（构造变体） | 只把 NTC 从充电 IC 旁移到电池端子旁 | 工程结论翻转；离线 verdict 不翻转（`ck-prot` 仍失败） |
| PC08 | `P2-BUCK`（构造对照） | 只把叠层从 2 层改 4 层 | 离线 verdict 不翻转——离线代理不覆盖可布通/阻抗 |

## 完成级别与盲测状态

- 题目、成对案例、参考答案：**作者编写完成**（基于契约与 PL 条目）。
- **独立盲测：已完成六轮**（2026-10-29），全部记录在仓库开发环境的 `docs/evidence/pcb-placement-blind-2026-10-29/`（证据目录不随 Skill 安装，故此处不设外链）：
  - **第一轮（v1 题面，3 Agent + 单评审）**：结论类型 43/60 = 71.7%；机制 95.0%；证据 100%（**存在泄题**：题面直接给案例 id + PL 编号，个别题写了期望 verdict/codes）；行动/未知 96.7%。
  - **第二轮（v2 题面，3 Agent + 2 名评审交叉评分）**：结论类型 A 61.7% / B 60.0%；机制 96.7% / 95.0%；证据 95.0% / 100%；行动 100% / 96.7%；未知 93.3% / 90.0%。300 个评分单元**一致率 92.7%**。
  - **第三轮（v3 题面，3 Agent + 2 名评审交叉评分）**：结论类型 A 53.3% / B 50.0%；机制 100% / 98.3%；证据 95.0% / 98.3%；行动 98.3% / 93.3%；未知 96.7% / 95.0%；300 单元一致率 92.3%（结论维仅 76.7%）。低点归因是「条件簇」答案与成对表口径冲突，不是内容退步。
  - **第四轮（v4 题面，3 Agent + 2 名评审交叉评分）**：结论类型 **A 88.3% / B 88.3%**；机制 98.3% / 96.7%；证据 98.3% / 98.3%；行动 93.3% / 96.7%；未知 **100% / 100%**；300 单元一致率 **98.3%（结论维 100%）**。
  - **第五轮（v4 题面 / v5 答案口径，3 Agent + 2 名评审交叉评分）**：结论类型 **A 100% / B 93.3%**；机制 95.0% / 98.3%；证据 93.3% / 100%；行动 98.3% / 98.3%；未知 93.3% / 91.7%；300 单元一致率 95.0%。**X05/X20 主标记冲突归零**（X05 6/6 `条件`、X20 6/6 `可确认`），X13 翻转识别保持 3/3，X01/X02/X10/X11 保持 12/12；扣除 X20 verdict 层的标准侧前提缺口后结论维 98–100%。已满足合并条件（见证据目录 `round5-evaluation.md` §7）。
    - **重点验证结果**：X01/X02/X10/X11 主标记 12/12 全对；**X13 翻转识别 0/3 → 3/3**（都写出 `ck-analog` 22.8 mm > 14 mm 失败 → 12.7 mm 通过、`review`→`acceptable`、HPWL 变差不降级），归因是 v4 给题面补了基线。
    - 扣除两处**标准侧**冲突（X05/X20 的答案-vs-规则 0 不一致，三人 3/3 同向、非作答错）后，结论维 53/54 = **98.1%**，作答侧零 ✗；唯一非争议内容错误是 X12/U3（把 `review→acceptable` 读成“两份 verdict 相同”）。
  - **第六轮（v5 题面：X20 补硬/软属性，3 Agent + 2 名评审交叉评分）**：结论类型 **A 100% / B 96.7%**（两评审 0 个 ✗）；机制 98.3% / 98.3%；证据 100% / 100%；行动 98.3% / 93.3%；未知 91.7% / 91.7%；300 单元一致率 97.7%。**X20 主标记与 verdict 层均归零**（6/6 `可确认`、6/6 `blocking`），X05 保持 6/6 `条件`，X13 保持 3/3，X01/X02/X10/X11 保持 12/12。第六轮目标达成（见 `round6-evaluation.md`）。
- **评审驱动的修订**：
  - v2 题面（第一轮后）：X01 补“软检查、无硬检查命中”；删 PL 编号与 verdict/codes 提示；X11 要求标记落在被问对象；X01/X08 过度例必答。
  - v3 题面（第二轮后）：试答要求新增 2b「主标记落在判分器判定层」；answers v3 新增「标记口径」规则 0、X05 证据事实修正、X10 → `待补`、X11 → `可确认`。
  - v4 题面/答案（第三轮后）：2b 改为**取“第一问句所在层”**；X13 补基线；条件簇（X07/X12/X13/X14/X15/X16）主标记统一为 `可确认`，成对表 PC03 同步。
  - **v5 答案（第四轮后）**：X05 主标记 → `条件`（第一问是机制）、X20 主标记 → `可确认`（第一问是判分器 verdict）、X13 数值统一 22.8 mm。**第四轮分数按 v4 口径计算，未追溯。**
  - **v5 题面（第六轮前）**：X20 补“缺失布局项属硬检查，任一硬检查命中即 `blocking`”，关闭第五轮记录的 verdict 层前提缺口；答案补“`missing_placement` 是硬检查 → `blocking`”。第六轮在此版本上跑完并归零。
- 限制：每轮 **3 个样本**；第二/三/四轮为双评审（第一轮单评审）；隔离是**约束式**（禁读仓库/答案/联网/运行命令，不是容器/权限强隔离），无法排除对训练语料的记忆；三份作答高度同构，**不能**据此推断模型能力，也不作为认证或对外能力声明。
- 这些题不是认证考试，也不证明 Agent 在真实工程中判断正确；它们只覆盖本组题面的判断类型，且全部基于离线几何/网表代理。六轮的题面/答案键/评审/作答者均不同，分数不可跨轮直接比较；结论类型在当前口径下已饱和（第六轮 96.7–100%、两评审零 ✗），继续加轮次收益递减。
- 真实工程未做的检查一律写 `NOT RUN`：DRC、布线/可布通、阻抗、EMC、热、机械/装配、打样与真机验证。

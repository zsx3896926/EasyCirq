## X01 去耦电容按焊盘还是按中心距

**场景来源：** `P1-MCU-MIN`（成对：`P1b-MCU-MIN-PAIR`）

**给定：**

- 某 MCU 最小系统案例的候选布局把去耦电容放在板子对角的远端、远离 MCU 的电源脚区域；成对案例保留其余布局，只把这两颗电容移到 `VDD`/`GND` 焊盘旁。
- 案例的 `checks` 用引脚对（`C1` 的脚 ↔ `U1` 的 `VDD` 脚）计算距离并设阈值；**该检查为软检查，本案例没有硬检查命中**。

**问题：** 判分器应给什么 verdict 与 codes？如果实现只比较“器件中心到器件中心”，会得到什么结论？哪些结论能确认、哪些必须等真实板？改动时先动哪一处？**请给出至少一个“过度动作”的例子（必答）。**

## X02 Buck 输入电容与高 di-dt 回路

**场景来源：** `P2-BUCK`（成对：`P2b-BUCK-PAIR`）

**给定：**

- 某 Buck 案例的候选布局让输入电容离开关管/电感较远；反馈件位置在阈值内，取样点与补偿作人工复核项。
- 判分器用 `loop_span`（高 `di/dt` 回路跨度的代理）判软检查；没有硬检查命中。

**问题：** 这份布局应判 `blocking`、`review` 还是 `acceptable`？依据是什么？只看“电容和开关在同一网络”会不会漏掉问题？写出机制，并列出真实工程还要确认的三项（其中至少一项标 `NOT RUN`）。

## X03 天线净空：包围盒还是中心点

**场景来源：** `P7-WIRELESS`

**给定：**

- 某无线案例里模组本体压在天线净空矩形内，净空区还被电容/固定件部分占用。

**问题：** 判分器应给什么 verdict 与 code？如果实现改成“器件中心点落在净空内才算违规”，会得到什么错误结论？净空区里的铺铜、过孔、螺钉判不判？对这几项分别该写什么状态？

## X04 连接器贴边与固定件压件

**场景来源：** `P8-MULTI`（成对：`P8b-MULTI-PAIR`）

**给定：**

- 某多模块案例声明了连接器所在的板边，候选布局把连接器放在板内、离声明边超过容差；同时连接器与固定件让位区相交。

**问题：** 判分器应给什么 verdict 与 codes？如果连接器离声明边正好在容差内，还能不能报贴边失败？如果案例根本没声明连接器，能不能判“没贴边”？真实工程中“贴边”之外还要看什么？

**问题：** 为什么“终端跨隔离侧”会表现为贴边/朝向类硬检查？这是把多种缺陷压进一个代理，还是案例数据只声明了这一个硬检查？真实工程要分别核对哪两件事？各自能不能用离线分数代替？

## X11 反馈取样点在离线判分里的盲区

**场景来源：** `P2-BUCK`

**给定：**

- 某 Buck 案例的反馈件位置在阈值内，判分不针对取样点报失败。离线判分只用回路跨度与显式检查；两个不同取样点若几何相近且同网络，可能得到相同结果。
- 工程上“从输出电容远端取样”和“从规定输出点取样”是不同结论。

**问题：** 为什么离线判分可能区分不了这两个取样点？这说明判分器缺什么？真实工程该看什么？请设计一个补充检查或成对案例让差别暴露（只描述思路，不需要坐标）。**结论类型必须落在被问的那件事上（“离线判分能否区分取样点”），不要把整题笼统标成“待补”。**

## 试答要求

1. 逐题按子主张判断：可确认问题、条件风险、合理取舍或信息不足；给结论类型、机制、依据（案例 id，或 check_id / 规则描述）、需补信息、建议动作。
2. **结论类型只写一个主标记**（`可确认` / `条件` / `待补` / `过度`），必要时加一句附加说明；标记必须落在**被问的那件事**上。
3. **题面未给 finding code 名时不要臆造**：写 check_id、规则描述或“题面未给名、需按契约枚举”，不要新造 code。
4. 不确定就写 `待补` 或 `NOT RUN`，不猜型号、不补默认坐标；真实工程未做的检查一律写 `NOT RUN`。
5. **X01、X08 的“过度动作/过度修改”例子为必答项**；缺答按未完成处理。
6. 不要读取本文件以外的题目类型标签、答案或案例 `expected`；不要联网、不要运行命令。
7. 试答记录格式自定，但必须能逐条对照 [answers.md](answers.md) 的五维评分。

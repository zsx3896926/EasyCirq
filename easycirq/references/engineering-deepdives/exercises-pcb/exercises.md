## X01 去耦电容按焊盘还是按中心距

**类型：** 明确错误（在给定案例数据下）

**绑定案例：** `P1-MCU-MIN`（成对：`P1b-MCU-MIN-PAIR`）；**PL：** PL17、PL18

**给定：**

- `P1-MCU-MIN` 的候选布局把去耦电容放在板子对角的远端、远离 MCU 的电源脚区域；成对案例 `P1b-MCU-MIN-PAIR` 保留其余布局，只把这两颗电容移到 `VDD`/`GND` 焊盘旁。
- 案例的 `checks` 用**引脚对**（`C1` 的脚 ↔ `U1` 的 `VDD` 脚）计算距离，超阈值即失败；失败 code 为 `distance_far`，并计入 `soft_fail`。

**问题：** 判分器对 `P1-MCU-MIN` 应给什么 verdict 与 codes？如果实现只比较“器件中心到器件中心”，会得到什么结论？为什么“明确错误”只能限定在案例数据内说，换到真实板就变成条件风险？改动时先动哪一处，哪些动作属于过度？

## X02 Buck 输入电容与高 di-dt 回路

**类型：** 明确错误（在给定案例数据下）

**绑定案例：** `P2-BUCK`（成对：`P2b-BUCK-PAIR`）；**PL：** PL09、PL10

**给定：**

- `P2-BUCK` 的候选布局让输入电容离开关管/电感较远；反馈件位置在阈值内，取样点与补偿仍作人工复核项。
- 判分器用 `loop_span`（高 `di/dt` 回路跨度的代理）判软检查，失败 code 为 `loop_large`；没有硬检查命中。

**问题：** 这份布局为什么是 `review` 而不是 `blocking`？如果只看“电容和开关在同一网络”，会不会漏掉回路面积问题？请写出机制，并列出真实工程还需要确认的三项（提示：不要用“能连上”当回路闭合）。

## X03 天线净空：包围盒还是中心点

**类型：** 明确错误（在给定案例数据下）

**绑定案例：** `P7-WIRELESS`；**PL：** PL26、PL27

**给定：**

- `P7-WIRELESS` 里模组本体压在天线净空矩形内，净空区还被电容/固定件部分占用。
- 契约 v1 的 `keepout_violation` 判定是“器件包围盒与 `board.keepouts[].rect_mm` 相交面积 > 0”，不看中心点。

**问题：** 应给什么 verdict 与 code？如果实现改成“器件中心点落在净空内才算违规”，这份布局会得到什么错误结论？净空区里的铺铜、过孔、螺钉在 v1 里判不判？对这几项分别该写 `可确认`、`条件` 还是 `NOT RUN`？

## X04 连接器贴边与固定件压件

**类型：** 明确错误（在给定案例数据下）

**绑定案例：** `P8-MULTI`（成对：`P8b-MULTI-PAIR`）；**PL：** PL03、PL05

**给定：**

- `P8-MULTI` 在 `board.connectors` 里声明了连接器所在的板边，候选布局把连接器放在板内、离声明边超过 `connector_edge_tol_mm`；同时连接器与固定件让位区相交。
- 判分器分别用 `connector_edge_tol_mm` 与 `overlap_tol_mm2` 判这两件事。

**问题：** 应给什么 verdict 与 codes？如果连接器离声明边正好在容差内，还能不能报 `connector_off_edge`？如果案例根本没声明 `connectors`，能不能判“连接器没贴边”？真实工程中“贴边”之外还要看什么（PL03 的插头壳体、卡扣、线缆弯曲半径）？

## X05 终端跨隔离侧为何算 connector_off_edge

**类型：** 明确错误（在给定案例数据下）

**绑定案例：** `P4-COMM`；**PL：** PL03、PL04、PL15

**给定：**

- `P4-COMM` 的候选布局里，隔离器/终端与连接器朝向冲突，终端电阻跨到了隔离侧外。
- 该案例期望 `blocking`，`codes` 只有 `connector_off_edge`，没有为“隔离边界”单独设 code。

**问题：** 为什么“终端跨隔离侧”在这份案例里表现为 `connector_off_edge`？这是把多种缺陷压进一个代理，还是案例数据本身只声明了这一个硬检查？真实工程要分别核对哪两件事（机械可插拔 + 隔离边界）？各自能不能用离线分数代替？

## X06 热敏电阻贴在充电 IC 上

**类型：** 明确错误（在给定案例数据下）

**绑定案例：** `P5-BATTERY`；**PL：** PL14、PL16

**给定：**

- `P5-BATTERY` 的候选布局把保护 IC/检流电阻放在远离电池端子的位置，并把 NTC 贴在充电 IC 上；案例期望 `review` + `distance_far`（距离类软检查 `ck-prot`、`ck-ntc` 都失败，统一记这一个 code）。
- 目标是测**电池**温度，不是测充电 IC 温度。

**问题：** 这两条缺陷分别属于硬检查还是软检查？`ck-ntc` 能发现“离电池端子远”，但它能区分“贴充电 IC”和“悬空放在别处”吗？这说明判分器的语义边界在哪？真实工程里测温对象错误为什么可能比几何越界更严重？该写 `可确认` 还是 `条件`？

## X07 模拟链贴近功率级

**类型：** 条件风险

**绑定案例：** `P3-ANALOG`（成对：`P3b-ANALOG-PAIR`）；**PL：** PL21、PL22、PL23

**给定：**

- `P3-ANALOG` 把传感器入口与基准件放在 Buck 电感/二极管旁，案例期望 `review` + `distance_far`；成对案例 `P3b-ANALOG-PAIR` 只把模拟链整体挪到远离功率级一侧，即变为 `acceptable`。
- 案例没有给层叠、屏蔽、频率、耦合量。

**问题：** 哪些结论在“本案例内”可确认（位置关系、软检查超阈值），哪些必须等真实条件（耦合路径、频率、回流、屏蔽）？如果把功率级电流减半、开关频率降一个数量级，结论一定翻转吗？写出你能确认的与只能标 `待补` 的分界。

## X08 栅极驱动回路跨越大电流地

**类型：** 条件风险

**绑定案例：** `P6-MOTOR`；**PL：** PL13、PL14

**给定：**

- `P6-MOTOR` 的候选布局让栅极驱动回路跨越大电流地，分流器取样从远端绕回；案例期望 `review`，codes 含 `loop_large`。
- 离线判分只用 `loop_span` 代理，不读实际地平面与共阻抗。

**问题：** 说明“共阻抗耦合”的机制，以及哪些量决定是否真的误触发/振铃。离线 `loop_span` 能证明什么、不能证明什么？给出一个“过度修改”的例子和一个“改对了但离线分数不变”的例子。

## X09 晶体在距离阈值内是否就安全

**类型：** 条件风险

**绑定案例：** `P1-MCU-MIN`；**PL：** PL19

**给定：**

- `P1-MCU-MIN` 的晶体**在案例阈值内**，判分不报失败；它仍被列为人工复核项。按契约，`max_distance` 类检查失败统一记为 `distance_far` 并计入 `soft_fail`（去耦就是这一类）。
- 案例没有给晶体型号、负载电容、负阻裕度。

**问题：** 阈值内是否等于“晶体没问题”？起振/频偏取决于哪些未给条件？如果把晶体换成内置电容的陶瓷谐振器或有源晶振，结论分别怎么变？为什么同一个 `distance_far` code 既可能来自去耦、也可能来自晶振或模拟入口，报告里该怎么写才不误导？

## X10 连接器在容差内但插拔空间未知

**类型：** 条件风险

**绑定案例：** `P4-COMM`；**PL：** PL03、PL15

**给定：**

- 某候选布局的连接器到声明边的距离在 `connector_edge_tol_mm` 内，离线判分不报 `connector_off_edge`，verdict 可能落到 `acceptable`。

## X11 反馈取样点在离线判分里的盲区

**类型：** 条件风险

**绑定案例：** `P2-BUCK`；**PL：** PL12

**给定：**

- `P2-BUCK` 的反馈件位置在阈值内，判分不针对取样点报失败；离线判分只用 `loop_span` 与显式 `checks`。如果两个不同取样点在几何上距离相近、又属于同一网络，判分器可能给出相同结果。
- 工程上“从输出电容远端取样”和“从规定输出点取样”是不同结论。

**问题：** 为什么离线判分可能区分不了这两个取样点？这说明判分器缺什么（数据表达还是检查类型）？真实工程该看什么？请设计一个补充检查或成对案例，让这个差别在离线层面暴露出来（只描述思路，不需要坐标）。

## X12 输入电容靠拢的代价

**类型：** 有意设计取舍

**绑定案例：** `P2b-BUCK-PAIR`；**PL：** PL09、PL11

**给定：**

- `P2b-BUCK-PAIR` 只把输入电容与 `SW` 电感靠拢，verdict 从 `review` 翻到 `acceptable`。
- 靠拢的代价可能是：`SW` 铜面积变大、散热路径变挤、测试点被占、反馈通道被挤。

**问题：** 这个 `acceptable` 是“最优”还是“在给定检查下可接受”？如果靠拢后反馈走线必须穿过 `SW` 区，离线判分还可能给 `acceptable` 吗？此时该不该继续改？请把“可接受但有代价”和“已最优”分开表述。

## X16 去耦在背面看起来很远

**类型：** 看似异常、实际可能合理

**绑定案例：** `P1b-MCU-MIN-PAIR`（引用其 `reference.acceptable_alternatives` 的背面实现，非案例坐标）；**PL：** PL17、PL18

**给定：**

- `P1b-MCU-MIN-PAIR` 的 acceptable 目标是“去耦焊盘回路短且不绕行”，其替代实现允许把电容放背面正对 `VDD`/`GND` 焊盘。假设某实现就是这样：从装配面看电容在背面、位号离 MCU 很远。
- 案例只判焊盘回路距离，不判过孔共用与参考层完整性。

**问题：** 这是不是缺陷？为什么“器件中心距远”可能仍然合理？要确认“实际合理”还缺什么？如果过孔与 MCU 的地回路共用，结论会变成什么？请给出可确认与待补的边界。

## X17 模拟链不排成一条直线

**类型：** 看似异常、实际可能合理

**绑定案例：** `P3b-ANALOG-PAIR`；**PL：** PL21、PL22、PL23

**给定：**

- 某布局把模拟链放在远离功率级的一侧，入口到 ADC 的走线比“排成一条直线”更长，但案例判分 `acceptable`。
- PL21 明确“大器件不一定要与小信号块排一条直线”。

**问题：** “信号链顺序清楚”和“不排直线”矛盾吗？为什么分区/回流优先于版面整齐？这种走线在什么条件下会从合理变风险（入口保护、参考、串扰、连接器位置）？该怎么写这条结论的类型？

## X18 天线净空全层禁铜是否过度

**类型：** 看似异常、实际可能合理

**绑定案例：** 构造题，不对应案例；**PL：** PL26、PL27

**给定：**

- 某模组指南要求天线投影区**全层**禁铜、禁过孔、禁固定件；有人觉得“只禁器件就够了”。
- 契约 v1 的 `keepout_violation` 只检查器件包围盒与 `rect_mm` 相交，不读铜/过孔/螺钉。

**问题：** 为什么全层净空可能合理？v1 能证明铜/过孔/螺钉也没问题吗？对“净空内放固定件”与“净空下有铺铜”分别该写什么状态（`可确认` / `条件` / `NOT RUN`）？如果模组换成外置天线，结论会怎样？

## X19 只有几何快照能否判可布通和阻抗

**类型：** 缺少信息、无法判断

**绑定案例：** 构造题，不对应案例；**PL：** PL09、PL28

**给定：**

- 只有一份离线几何/网表快照与 `hpwl_mm`、`congestion_max` 指标；没有层叠、铜厚、阻抗规则、逃线通道、机械 3D、器件手册。
- 判分器固定输出 `routing_verified:false`、`drc:"NOT RUN"`。

## 使用建议

1. 先独立作答，再读 [参考答案](answers.md)。
2. 每题至少写：结论类型、机制、依据（案例 id / code / PL）、还需补充的信息、建议动作。
3. 不要把“我没见过”当成“错误”，也不要把“脚本没报”当成“设计正确”。
4. 对条件风险题，必须写出结论翻转的条件；对信息不足题，必须列缺失项，而不是猜一个答案。
5. 成对案例先写“只改的那个条件”，再判是否翻转；没翻转时说明原因，不要强行制造差异。

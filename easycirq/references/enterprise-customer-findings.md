## 二、已确认的事实（文档原文依据）

### A1 EDA 产品与版本 ✅

- 产品：**嘉立创EDA(专业版)私有部署**
- 服务端 **2.2.45.7**、客户端 **1.12.1**、浏览器访问配置 **1.2.2**
- 架构：**B/S**，「服务器端（Server）和用户端（**Browser & Electron**）」
- 服务器：Windows Server 2016+ / CentOS 7.4 / Ubuntu 20.04，仅 x86/AMD64
- 用户端：Windows 10+ x64、Linux（Ubuntu/UOS/deepin/Kylin）、macOS 12+

> ⚠️ **版本号对不上**：私有部署客户端是 **1.12.1**，我们现有连接器针对的公有专业版是
> **4.1.78**。这是两条不同的版本线，**不能假定 API 一样**。

### A3 能不能导出结构化网表 ✅ **能**

文档「生产文件导出 → 导出网表」原文：

> 网表类型：**allegro（.tel）、PADS(.asc)、Protel2(.net)、嘉立创EDA专业版（.enet）**
> 范围：本工程的原理图

另外这几样也都能导出：

| 类型 | 格式 |
|---|---|
| 网表 | `.tel` / `.asc` / `.net` / `.enet` |
| BOM | **XLSX / CSV**（支持模板） |
| 坐标文件 | XLSX / CSV / TXT（位号、封装、XY、层、旋转、SMD） |
| Gerber + 钻孔 | 标准格式，单位 mm |
| 原理图 | PDF / 图片 |

**结论：A3 = 是。离线检查这条路成立。**

### A4 客户端技术栈 ✅

**Electron**（文档原文「Browser & Electron」）。浏览器和客户端功能相同，
但浏览器有内存限制，大板建议用客户端。

### A5 私有部署改动 ✅ 有几处必须知道

| 改动 | 对我们意味着什么 |
|---|---|
| 需要 **License 激活**（嘉立创生成 .license） | 不影响我们 |
| 需要 **MySQL 8.4.2** | 数据都在这里 |
| **443 端口 + HTTPS + 域名证书** | 客户端连的是 `https://<域名>`，不是 IP |
| hosts / DNS 必须把域名解析到服务器 | 我们的 `wss://` 也要走这个域名 |
| 用户端要装 **crt 证书**才能不报不安全 | 若我们走 wss，证书链要能被信任 |

### A2a 插件 API ✅ 有插件和开放 API —— 而且**不用再问"是否同构"**

**因为 EasyCirq 只做嘉立创EDA**，插件 API 就是 `eda.*`，不存在"换成别家"的问题。
A2 从「客户是不是 EasyEDA 系」降级成一个窄得多的问题：

> **私有部署客户端（1.12.1）的 `eda.*` 是否与公有专业版（4.1.78）一致？**

同一个厂商、同一套 API 家族，差异大概率只在版本 —— 但仍要验，因为私有部署可能
为安全裁剪过接口。**验证成本极低**：装上我们的连接器 `.eext`，看能不能连上并回读。

文档原文（「六大核心优势 → 生态与集成」）：

> **开放API与丰富的插件生态**、可对接企业 PDM/ERP/PLM 等系统


文档「六大核心优势 → 生态与集成」原文：

## 四、网表格式适配：优先级已下调

> ⚠️ **本文早前把「任何能出 `.net` 的 EDA 都能用」当作主要理由。**
> 既然只做嘉立创EDA，**那个理由作废**。转换器的价值只剩下面这一条。

### 唯一站得住的理由

**私有部署客户端是 1.12.1，我们针对的是公有专业版 4.1.78。**
如果私有部署把插件 API 裁掉了或改了，连接器就用不了 —— 那时
**内置的「导出网表」是保底通路**，因为它不依赖插件。

### 所以顺序应该是

1. **先验连接器**（5 分钟）：装 `.eext`，看能不能连、能不能读回器件。
   **能连 → 转换器不需要做。** 连接器给的数据更全（有几何、有实时状态）。
2. 连不上 → 才做转换器，且**目标格式是 `.enet`（嘉立创原生）**，
   不是 Protel2/PADS/allegro —— 那三个是嘉立创给别人用的兼容格式，我们不关心。

### 原分析（保留，但理由已作废）


A3 已确认能导出 `.enet` / `.net` / `.asc` / `.tel`。

我们 L1 吃的是自己的 JSON 网表（`components[] / pins[] / net`）。
**写一个转换器，L1 立刻在客户环境可用——不需要连接器、不需要插件、不需要等服务端对接。**

### 优先级

| 格式 | 优先级 | 理由 |
|---|---|---|
| **Protel2 `.net`** | **最高** | 纯文本、格式最标准、几乎所有 EDA 都能出，社区资料最多 |
| PADS `.asc` | 次 | 也常见，格式稍复杂 |
| `.enet` | 待评估 | 嘉立创原生，但格式是否公开未知；如果是 JSON 反而最好解析 |
| allegro `.tel` | 低 | 复杂，且客户不一定用 |

### 要确认的一件事

**`.enet` 是什么格式？** 如果是 JSON（原生格式通常是），那它比任何第三方格式都准，
应该排第一。**要客户导一份样本来。**

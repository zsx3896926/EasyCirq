# 企业版演示（10 分钟）

> 这份是**给客户看的**：三个场景，每个都能当场跑。
> 每段输出都是真实执行结果，不是示意。
> 完整说明见 [接入指南](enterprise-onboarding.md)，客户环境清单见[信息清单](enterprise-discovery.md)。

---

## 这套东西解决什么问题

一句话：**把公司自己的规范变成每次检查都自动执行的判据，并把执行记录留在公司这边。**

三个具体变化：

| 现在 | 用之后 |
|---|---|
| 规范在 Word 里，靠人记 | 规范是可执行判据，违反就拦住交付 |
| 每个人各装一套，经验各存一份 | 库在服务器共享目录，全员同一份 |
| 每个工程师自己配 LLM key | 真 key 只在服务器，工程师机器上找不到 |

## 场景一：公司规范 → 可执行门禁（3 分钟）

### 放一条规则

`\\company-file\easycirq\knowledge\rules.company.json`：

```json
{
  "schema": "easycirq-enterprise-rules/v1",
  "rules": [{
    "id": "no-0402",
    "kind": "hard",
    "title": "禁用 0402 封装",
    "predicate": { "type": "footprint_forbidden", "patterns": ["0402"] },
    "evidence": "产线贴片下限 0603，0402 需外协",
    "owner": "硬件部 张工",
    "verified_on": "在一块 R0402 的板子上跑过，报 fail"
  }]
}
```

### 查一块板

```
$ easycirq enterprise check --netlist board.json

企业规则判定：fail
  ✗ no-0402-packaging            禁用 0402 封装  [hard] R1 的封装是 R0402
exit=1
```

干净板：

```
企业规则判定：pass
  ✓ no-0402-packaging            禁用 0402 封装
exit=0
```

**这条规则现在会拦住所有工程师的交付**，不是一个人记得、其他人忘。

### 拦住时说清三件事

```
$ easycirq enterprise review --netlist board.json

企业规范审阅：❌ 违反企业规范，不能交付
一、可执行规则（3 条，**影响交付**）
  ✗ 禁用 0402 封装 [hard]
      违反：R1 的封装是 R0402
      依据：企业设计规范 DS-2024-07 §3.2：产线贴片能力下限为 0603
      找谁：硬件部 张工
      规则来源：.../rules.company.json
二、可参考的企业知识（2/3 条命中，**不影响交付**）
  · 去耦电容摆放距离要盯着   命中：tag:去耦   来源：.../review-ledger.json
```

**「谁、依据什么、找谁」三件事必须同时出现**——否则被拦的人只会觉得工具在挡路。

## 场景二：全公司看得见这个库（2 分钟）

```
$ easycirq enterprise report --out kb.html
已生成 kb.html（8 条条目，自包含，可直接分发）
```

生成的网页**不引任何外部资源**（实测：无 `http://`、`https://`、`<script>`、`@import`、`src=`、`<link>`、`cdn`），
放内网共享，全员浏览器打开即可，内网出不去也正常显示。

它回答四个问题：

| 页签 | 回答 |
|---|---|
| 可执行规则 | 有哪些、依据什么、**本机拦了几次** |
| 可检索知识 | 有哪些、覆盖什么主题 |
| 企业器件参数 | 有哪些实测值覆盖了手册 |
| 读了哪些文件 | 到底加载的是哪个目录、哪几个文件 |

**问题区置顶**：没写 `verified_on` 的规则、永远检索不到的知识、读不进来的文件。

> 关于「拦了几次」：那是**本机记录**，不是公司汇总。报告脚注写明了。
> 从没拦到过的规则显示「无记录」，不是 0——两件事不一样。

## 场景三：服务器管人和密钥（3 分钟）

### 服务器上起网关

```
$ export COMPANY_LLM_KEY=sk-...                     # 真 key 只在这里
$ easycirq gateway --tokens tokens.json --listen :8443 \
    --llm-base-url https://api.deepseek.com \
    --llm-key-env COMPANY_LLM_KEY

easycirq gateway 已在 [::]:8443 上监听
  token 数：2
  LLM 转发：已启用 → https://api.deepseek.com（key 取自环境变量 COMPANY_LLM_KEY）
```

### 工程师接入

```
$ easycirq login --server https://easycirq.company.com --token <管理员发的>

已登录 https://easycirq.company.com
  token：e2e-…
  服务器可达 ✓
```

之后所有命令发往公司服务器，**本机不需要 daemon**。

### 密钥不下发，实测

| 请求 | 结果 |
|---|---|
| 有效 token | 200，上游收到 `Bearer sk-real-company-secret` |
| 无效 token | **401，上游一次都没被调用** |
| 过期 token | **401，上游一次都没被调用** |
| 上游 Authorization 里含工程师 token | **False** |

**工程师机器上任何文件都找不到真 key。** 这是方案 B 的立论，不是承诺。

### 多租户隔离，实测

| 请求 | 结果 |
|---|---|
| 甲打自己的窗口 | 200，由甲的连接回答 |
| 乙打自己的窗口 | 200，由乙的连接回答 |
| **甲拿乙的 windowId 打** | **失败** |

第三条是重点：如果两个租户共用连接表，它会成功。

## 现在还不能做什么（必须知道）

| 项 | 状态 | 卡在哪 |
|---|---|---|
| 把连接器接到**你们的** EDA 上 | ❌ 未验证 | 需要客户答 A2（插件 API 形态） |
| 真实模型调用 | ❌ 未验证 | 需要 C1/C2/C4 和内网 key |
| 账号体系（建号、邀请码、权限） | ❌ 未做 | L3，需先确认要不要 |
| 工程师连 CLI 都不装 | ⚠️ 部分 | 不需要本机 daemon，但仍需 CLI |
| 知识库并发编辑 | ⚠️ 部分 | 工具写入（promote）**已加锁并按 id 合并**；人工用编辑器同时改仍未加锁 |
| 知识库放数据库 | ❌ 未做 | 现在只支持文件目录 |

**最重要的是第一条**：整套东西在 EasyEDA Pro 上验过，但**没在客户的 EDA 上验过**。

## 试点怎么开始

```
第 1 周   客户填信息清单（重点 A2、A3）
          我们确认：能不能接、值不值得接

第 2 周   客户给 3~5 条真实规范 + 一块真板
          我们落成规则，跑出第一次"拦住"

第 3 周   共享目录上线，2~3 个工程师试用
          看会不会被误报烦到

第 2 月   决定要不要上服务器模式和 LLM 转发
```

**第一步不是装软件，是拿一条真实规范跑通。** 那一步过了，其余才有意义。

## 一句实话

**这套东西的价值全在"内容"上，不在工具上。**

没有成文规范（清单 D5）、没有历史项目可提炼（D6），工具再好也是空的——
库里没有规则，一切检查都是 `pass`，而 `pass` 什么也不代表。

所以第一件事永远是：**客户有多少条写下来、可执行的规范？**

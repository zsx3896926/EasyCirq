# 新手与工程师的协作

## 自动适应表达深度
新手或水平不明时先读 beginner-journey.md，优先使用生活化入口；下面的技术例子只在用户已有型号或工程时使用。Agent承担需求整理、检查和执行，不能让小白先学会CLI才开始。

## 从三句话开始
不要求用户先了解CLI或Skill内部。可以给最贴近当前任务的一条例子：

```text
做一块ESP32-S3温湿度采集板，USB-C供电，两层板，50×30mm，先出方案。
```
```text
原理图我已画好，帮我review，先别改。
```
```text
在当前工程加一路RS485，沿用现有接口位置，完成原理图和PCB修改并检查保存。
```

## 读信息，少追问
先读取工程、板框/接口、附件、既有BOM和规则。只合并询问会改变方案或阻断后续操作的事项；不在每个阶段重新确认已经确定的条件。
指定器件也要核查额定/封装/脚位与任务是否匹配，不能“用户指定所以无需电气核查”。明显冲突时提出可落地选项。
对“加CAN”，先看主控是否有CAN控制器；仅增加收发器不能凭空提供控制器功能。对“USB-C调试”，分清连接器、UART桥、原生USB调试和角色/供电路径。
对“留调试口”，只加入该主芯片支持且任务需要的调试/下载信号，避免无依据同时添加SWD、JTAG和UART全套接口。

## 检查点与等待
- 方案点：架构、电源树、关键器件和主要假设。
- 原理图点：连接与位号、关键参数、当前缺陷与待核。
- 布局点：板框/接口/锁定件、功能分区、关键回路及未覆盖规则。
- 交付点：实际图纸、保存、检查、制造输出范围。
只有用户要求分阶段确认，或真正需要新决定时才等待。用户只说“先方案”时严格不画图；用户要求“直接做完”时不要在四个点各问一次许可。

**统一自主执行规则**：用户授权整板自主完成（如“直接做到布线/DRC”）后，布局完成自检、记录证据并向用户展示当前状态即可继续布线，不逐检查点等许可；只有新增任务范围、已确认关键约束冲突、或确需用户取舍时才暂停。自主模式不降低质量门禁、证据要求和失败预算。

## 第一次使用时的连接诊断
先运行 `easycirq doctor` + `easycirq capabilities`（若工具可用）读取真实执行层与能力状态，不用旧配置路径或版本号推断。不要求用户重复启动已经运行的daemon，也不把历史环境配置路径写死。
没有执行能力时直说“当前可以做方案，尚不能写入EDA”，给最短配置/材料清单。安装/升级按用户授权处理；不宣称WorkBuddy等任意客户端已自动配置。

## 默认值的边界
可以沿用项目已有图面风格、命名、器件尺寸和板厂规则；新工程的封装/层数/工艺可给明确的暂定建议。
环境温度、隔离等级、负载电流、电池体系、接口角色和机械尺寸不静默设为“商业级/两层/5V”等。制造和安规相关参数不能因用户没说而默认满足。
不凭供应商名字默认贴片费用、基础库状态、库存或交期；这些随订单和日期核对。

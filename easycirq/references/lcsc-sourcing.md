# 立创商城：从设计选型到可核对购料表

## 1. 开始时取得最少输入
沿用已知用途、板数量、装配变体、预算与交期；实际采购时核对送达地区，不仅凭语言推断国内/海外下单渠道。向新手说“做几块、自己焊还是想收到焊好板”，不要让其先解释C号/MOQ。
用户未指定供应商时，中国大陆项目优先检索立创商城；尊重指定料、已有备料、企业认可供应商和其他地区供应链。电气/机械/可靠性是前提，价格是可行候选间的取舍。
仅设计/画图时可提前做关键料供货预检，但不强行启动购物车或订单流程；用户只要求原理图时，不因此购买元件。

## 2. 查准商品而不是搜到相似名字
优先“完整原厂MPN + 制造商 + 封装/关键参数”或用户给的C号；无源器件同时核对值/容差/耐压/功率/介质/温度/尺寸等适用规格。
依次确认：商品制造商/完整料号与封装，商品页C号，适用手册与关键额定，再做EDA库/封装/pin-pad核对。不能默认选搜索首条。
逐项保留内部映射：项目位号/Role、完整MPN、规格与封装、商城C号及实际商品链接、EDA device/symbol/footprint身份、引脚映射、装配变体。
C号与商品页URL中的数字ID不是可自行换算的关系。只引用实际检索/工具返回的链接，不拼接猜测商品URL，不伪造C号。供应商编号一致不代表用户库几何已正确。
商城附PDF可作为手册入口，仍核对制造商/型号/版本；商品页简表或“可替代”推荐不能覆盖原厂限制。

## 3. 查货、查价与证据
对关键料和计划采购料记录：渠道/交付方式、库存、查询时间、采购数量对应价格档、币种/含税口径、MOQ、下单步进或包装限制、包装形式、交期及来源。页面不提供的字段标未知，不猜测整盘/零剪通用规则。
同一商品更换交付方式或包装后，重新看该渠道的价格/库存/交期。分别标现货、合作/其他渠道、订货或待核；不把列表上“库存”混成一个可用数量。
在线查询不到或受登录/权限限制时，提供候选和待核项，保留已查证据。搜索摘要、缓存日期、旧BOM、器件属性价格只能作定位/参考，不说“实时已确认”，不用后台未公开API或绕过站点限制。
板厂SMT的可贴类型、库存、价格另查，不能借用商城数据。公开查价不代表登录用户实际优惠，最终结算与交期按具体页面复核。

## 4. 按批次算数量和现金支出
先区分每板用量、该装配变体的板数、备损/备件、用户已有可用库存，得到需购数量。只合并确认同一采购SKU且规格/装配要求一致的行，位号映射不丢。
需购数量由“实际装配需求 + 明确的备损/备件 − 已核实可用自有料”得出，最低为0。自有料核对型号/封装/状态；不要跨不同变体重复抵扣。SMT路线还须确认工厂接受、实际备料/入库及该订单选中状态，不能直接用个人散料抵扣工厂需求。损耗/备损不静默固定百分比。
按商品实际起订量、增量和包装规则取可下单数量；包装总数、最小起订量和订购步进不是同一概念。信息不全时标待核，不假设所有料按整包装倍数购买。
按最终购买数量选择适用价格档，再算行成本。逐档看清单位是元/个、元/盘还是其他单位；必要时换算并保留依据。数量不足不能套高数量低价。
分别给“理论装配用料成本”“本次实际购料支出”“剩余物料”；不足报价只计已报价部分并列未知，不能将部分小计称为整板总成本。
PCB/SMT/钢网或制具/运费/税费/烧录测试等按实际服务分项报价，尚未报价就列未计项。促销、账号优惠、补贴、免费政策需当前适用证据，不固化费率或承诺。

## 5. 缺货与替代料
优先核对同一准确型号/可接受包装或已认可采购渠道；其他型号分为“工程复核后的可替代候选”“需改封装/引脚/外围/程序的方案”“不能确认”。库存好不能直接判可替代。
比较电气范围/精度/动态/温度、封装尺寸与pin-pad、启动/接口/固件、保护/时序/热和装配工艺。主控、模拟、电源或RF替代尤其要看完整应用条件。
改料必须反映到工程、库绑定、BOM、采购表和变体，再跑受影响检查；不是只把购料表C号换成有货料。完全相同器件仅采购包装变化时也核对装配适配，不无故改图。
用户已授权常规选型/换料时在范围内推进；替代导致原功能、成本目标、交期、尺寸或已确认品牌约束实质改变时，解释取舍并取得必要决定，继续独立部分。

## 6. BOM配单与交接
以已保存工程和明确装配变体生成BOM，包含实际位号、每板数量、完整MPN/制造商、规格/封装、商城C号（已核实时）和必要备注。DNP不作为该变体采购需求，保留单独说明。
可参考商城BOM智能云表导入流程。原始需求、平台匹配结果和Agent工程审查是三种状态：平台“完全匹配”也要对照准确型号/品牌/封装/参数；待确认/无法匹配必须保留，AI匹配不自动成为可替代。
上传前保存原始BOM/工程版本；匹配后逐项核对C号、型号/品牌/封装、每板与批量数量、备损、购买数量、交付/包装以及来源；异常或重复行不直接确认。
实际读取商品、上传配单、购物车和提交订单依已提供工具/站点能力及用户授权执行，不虚构专用API、配单ID、购物车或订单成功。授权“帮我配单/上传到商城”只使用该目的所需BOM字段；查公共商品无需上传完整工程。涉及保密工程或额外分享时遵循实际数据边界。
需登录或手动选择时给一个具体动作；没有账户通道也交付本地可核对BOM与商品链接，不伪称云表已上传。下单/支付按用户明确的供应方、数量/商品、预算和宿主规则办理，不把一般设计需求当购买授权。

## 7. 对小白的呈现
优先一句话：“我会帮你找在立创商城买得到、规格合适的零件，并按这次做的数量配齐；如要工厂焊好，我会另核对贴片选料。”
展示推荐、当前可核实的支出/未知项、缺料和下一步即可。C号称“商城商品编号”，BOM称“零件清单”；后台保留完整映射和证据，不把采购表当作用户必须填写的作业。

按器件类型的必看参数、立创商城检索关键词/筛选顺序和替代分级见 [器件选型与替代资料](selection/README.md)。实时 C 号、价格、库存、MOQ、包装、生命周期和 SMT 可贴状态仍按本文流程逐项核对；没有实时证据就写 `待查`。

## 8. 原始 BOM、富化与字段分离

### 8.1 先导出原始 BOM，再考虑富化

- 画完或改完原理图先导出原始 CSV：`zhigou bom export --type csv --enrich=false`。原始文件保留 EDA 库自带的 `Supplier Part` 字段，是后续与商城、SMT 对账的基线；不要先手工改一版“看起来齐全”的表。
- `zhigou bom export --type csv` 默认会尝试按 MPN 富化 C 号；富化是 best-effort，失败时导出文件保持未富化并打印警告，导出本身仍成功。**富化失败不阻断设计与画板**：保留原始 CSV，在报告里写“C 号未富化/待核”；采购或下单前仍必须补齐可下单的 C 号或非立创渠道。
- `zhigou bom enrich <bom.tsv>` 只处理 TSV 输入，`--out` 写结果；它不是设计前置条件，失败就停在原始 BOM，不反复重跑。`bom-enrich` 在 `value=null` 时有已知异常，见 [工具动作陷阱](tool-gotchas.md) §7。
- 当前 `bom export` 没有 `--out` 参数；产物路径以 CLI 返回为准，需要固定文件名时按实际输出方式重定向或复制，不假设不存在的参数。
- BOM 与工程版本绑定：改图后重新导出，不沿用旧 CSV 配单。

### 8.2 身份、库存、包装、可贴性分开核

| 维度 | 要核什么 | 不能由什么推断 |
|---|---|---|
| 身份 | C 号、完整 MPN、制造商、封装/参数 | 搜索首条、相似型号、旧 BOM |
| 库存 | 当前渠道、数量、查询时间 | EDA 库里有 C 号 |
| MOQ/包装 | 起订量、增量、整盘/零剪、交期 | 单价页的“库存”数字 |
| SMT 可贴 | 基础库/扩展库、可贴状态、换料费、备料方式 | 商城有货、EDA 有库 |
| 装配 | 手焊/SMT/直插、封装难度 | C 号或“基础库”标签 |

**EDA 库里的 C 号不是当前库存。** 库身份只说明该器件曾绑定这个商品；下单前必须按当日商城页面核对 C 号、库存、MOQ/包装与价格，按当日 SMT 订单页核对可贴状态与费用。两者都未核时写 `待查`，不写“有货”。

### 8.3 字段与脚本

- 零件表模板见 [parts.example.json](../assets/parts.example.json)：`role / designators / mpn / manufacturer / package / footprint / lcsc / stock / smt_class / assembly / datasheet / alternates` 分列。
- `python scripts/bom_check.py <parts.json>` 检查结构字段、C 号格式、库存状态、手焊 0402、DNP 分类；`--strict` 把警告升为阻断。它不联网，`not_checked` 列出的库存、价格、SMT 可贴、封装几何与替代等价性仍须人工核对。
- 选型、封装与手焊/SMT 分界见 [选型、BOM与装配变体](part-selection.md)；商城业务流程、比价与配单交接仍按本文 §3–§6 执行，不在此重复。

# PCB经验：解释原因，并落到真实铜与装配

吸收hw-eda-engineer 0.6.0的经验表达，补充已有 [布局细节](pcb-placement-details.md)、[布线细节](pcb-routing-details.md) 和 [制造细节](manufacturing-details.md) 的应用方法。这里不额外累计为新的检查条目，也不引入固定毫米值、安培值或制造承诺。只有实质相关的卡才加载。

## 放件前与去耦

### BL01 同方向装配是优化目标，电气与机械约束优先

- **原因**：统一极性方向方便检查，但旋转器件可能拉长高频回路、反转接口或改变散热路径。
- **动作**：先锁定接口、孔、壳体与关键电路组，再优化视觉方向；位号与极性标记应能从实际装配面识别。
- **怎么查**：对比实际焊盘网络、装配图、板底视角和连接器配对件；旋转后重查关键回路，不只看3D是否整齐。关联PL04/09与制造检查。

### BL02 去耦看完整回路，不把“必须串经电容”当口诀

- **原因**：高频效果依赖电容焊盘、电源/地过孔、参考层、芯片引脚与封装的寄生；中心距离或走线顺序不能单独证明有效。
- **动作**：按器件推荐布局与实际PDN缩小供电及返回回路，评估背面放置、共享电容/过孔和多容值组合；不无条件规定最小容值最近、每脚独占电容或每电容恰好一个孔。
- **怎么查**：查看实际层叠、铜连接和焊盘到参考路径；有瞬态目标时进行匹配的PI分析/测量。关联PL17/18，查 [RP2040原厂布局资料等](design-experience.md)，不能把示例芯片要求推广全部器件。

### BL03 开关回路、采样点和热区分别识别

- **原因**：把整个电源块简单挤紧可能同时增大反馈耦合和热问题；Buck与Boost的脉动电流路径也不同。
- **动作**：依据开关状态找高di/dt回路，再摆输入/输出电容、开关、整流和反馈；电感下层铜、屏蔽与禁布依实际结构和原厂布局。
- **怎么查**：从真实铜逐段标出关键电流及返回、SW区和反馈取样点；检查热源对电池/温感影响。参考 [TI寻找开关回路](https://www.ti.com/document-viewer/lit/html/SSZTBF4/GUID-095BD04D-6DAF-42E7-9AA0-72CB14E1F58C)，关联PL09–16。

## 敏感路径与连接器

### BL04 护环必须知道自己跟随什么电位

- **原因**：高阻输入的表面漏电、吸湿污染和寄生电容会影响精度；简单用地铜包围不等于有效护环，驱动还可能引入稳定性问题。
- **动作**：先查前端手册与误差预算，决定是否需要护环、驱动源、电位、层别及清洗/涂覆要求；并非所有ADC/运放都需要护环。
- **怎么查**：核对真实网归属、输入寄生和制造清洁流程；按实际环境测偏置/漂移，普通DRC无法证明漏电精度。关联PL22/RT22。

### BL05 USB完整通道包括插座触点合并区

- **原因**：Type-C双面触点的汇合、ESD焊盘、测试支路及过孔可能形成不连续，差分线等长不能消除这些问题。
- **动作**：依据接口速率和平台指南安排触点合并、保护件与逃线；从收发器到插座检查参考与支路，按真实叠层求阻抗。
- **怎么查**：回读插座脚序、正反插连接和实际铜；按适用速率复核通道预算/测试，不能因为USB 2.0布线经验就放行高速SuperSpeed。参考 [TI SLLA414](https://www.ti.com/lit/an/slla414/slla414.pdf)，关联RT11–20。

### BL06 晶体与天线禁区都需要具体对象

- **原因**：无源晶体、有源振荡器、PCB天线、芯片天线、模组天线与外置天线的参考地和禁布条件不同。
- **动作**：按具体器件/模组定义逐层禁区、馈线和接地，不统一套用“下方都挖空”或“下方都铺地”；自动铺铜、缝合孔和壳体变更必须服从这些约束。
- **怎么查**：逐层看实际铜、过孔、壳体/电池/金属固定件，记录对应原厂图；射频效果与起振可靠性仍需相应实测。关联PL19/24、RT24–26与 [Espressif指南](design-experience.md)。

## 载流、焊接与交付

### BL07 露铜加锡不能自动变成可保证的载流能力

- **原因**：手工或批量上锡的厚度、连续性和润湿不易一致；焊盘颈缩、过孔和端子仍可能是瓶颈。
- **动作**：按可控铜厚、温升、压降、负载和工艺评估全路径；确需加强时设计可验证的铜厚/铜条/导体方案，列装配与质检要求。
- **怎么查**：检查实际截面假设、所有瓶颈及热连接，按目标负载测压降/温升；不能用未经工艺保证的锡厚替代计算。关联RT01/02/29。

### BL08 散热焊盘的电气网与工艺要分别核对

- **原因**：EPAD/tab不一定接地；散热孔可能带来吸锡，普通盖油也不等于填孔电镀或可靠阻止焊料流失。
- **动作**：依据器件定义指定网，结合钢网开口、孔径、填孔/塞孔/盖油选项与当前加工能力确定方案；同时检查散热与可焊性。
- **怎么查**：核对封装焊盘映射、钻孔/阻焊/钢网层和实际订单选项，必要时用装配检验/温升复验。不能给所有LDO散热片自动连GND。关联SC02/03与制造检查。

### BL09 螺钉和屏蔽片不能默认归GND

- **原因**：金属固定件可能接触机壳、保护接地、信号地或外部可触部位，也可能有绝缘要求；机械碰触会引入图纸之外的通路。
- **动作**：明确PTH/NPTH、焊盘/屏蔽脚意图、支柱和垫圈范围，依据隔离/EMC/安全要求选择连接方式；不能只为消除孤网把外壳脚接地。
- **怎么查**：检查全层铜、实物装配接触面、间距与插拔路径；3D只显示外形时保持电气连接待确认。关联PL02/05、RT10/31。

### BL10 “最终导出”必须对应同一版真实工程

- **原因**：移动后未重铺铜、旧DRC与新Gerber混用、装配变体不同都会让文件各自看似正常而整体不一致。
- **动作**：按实际工具能力保存、重算铜、回读网络/未布线、重查受影响规则，再导出同版制造包；板框应包含合法外轮廓及预期槽/内切口，而不是无条件只准一圈。
- **怎么查**：核对导出来源、时间/版本、层/钻孔/板框和BOM/坐标/变体，查看真实导出结果。脚本文件清点、固定字段`saved:true`或`passed:true`都不能证明保存/放行；不存在的检查器不得写成已执行。关联RT27/32–35与 [交付](jlc-handoff.md)。

## 使用和积累边界

本页为条件化检查方法，只有指定原厂链接支持其相应机制；仍按任务读取实际型号/板厂订单。制造边距、丝印/阻焊、孔径与SMT单双面能力查询当前渠道，不能沿用来稿的固定值。项目经验按 [经验库](design-experience.md) 的证据、授权和脱敏流程沉淀；没有真实PCB回读/样机测试时不写“布局已验证”或“可量产”。

### PCB 易错机制：封装内嵌 Board Outline（原生 DRC 永久失败）

**症状**：`pcb drc` 报 `Board Outline to SMD Pad — Clearance Error in the same footprint`，
最小间距小于规则值，影响同一器件的多个焊盘；改线宽、重铺铜、重建板框都无效。

**判定**：违规 `isInSameComponent=true`，且对象类型为 `Board Outline`。这说明**该器件的封装
自带板框图形**，不是布线问题。不要为了消告警去改网络/删器件/放宽规则。

**处置（2026-10-28 真机实测）**：
1. 运行 `python tools/zhigou_footprint_outline_diagnose.py` 点名器件、焊盘与对象 id；
2. 该子图元**枚举不到也删不掉**（删除返回成功但 save+reload 后引擎重建），所以**不要**
   尝试"删除图元"来修复；
3. 正确修复是器件/封装级：`zhigou sch replace --id <primitiveId> --lcsc <无内嵌 outline 的同类器件>`
   （或 `sch rebind-footprint` 换封装、或改库删除图形）；
4. 必须 `pcb save → doc reload → pcb drc` 复验（实测 4 条违规 → 0）。

**经验边界**：这是库数据缺陷，不是每种封装都有；只有 DRC 出现"同封装 Board Outline 违规"
时才按这条处理，不外推成所有器件都要换。

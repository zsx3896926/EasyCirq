# 路由器 A/B 与外部 Freerouting 结果的可比性

> 范围：同一块板、同一布局与规则下，比较官方路由器 / `route-short` / 外部 Freerouting / 后优化结果时“能不能比、怎么读”。本页不产生布线、不定义 RT/PL 编号；命令与回读以 [PCB 命令映射](pcb-command-map.json) 与 [PCB 执行工作流](pcb-execution.md) 为准。离线几何验证不等于原生 DRC。

先读 [PCB 布线策略](pcb-routing-strategy.md) §3（自动布线只作候选）与 [PCB 执行工作流](pcb-execution.md) §7（路由器选择）；验收仍按 [阶段门禁](design-gates.md) 的 G5 证据规则判。

## 0. 结论优先

- 只有“**同板**（板身份哈希）、**同规则**、**同验证口径**”的几行才能进同一张对比表。
- 外部 Freerouting 的 A/B 之前先做 **DSN 保真三查**；任一失真，这次 A/B 只能记 `NOT RUN`，不能拿数字下结论。
- **0 过孔不等于更优**：先确认焊盘层有没有写对。
- 采纳顺序：连通/关键网 → 违规 → 过孔/线长/折弯；耗时只记录，不参与“谁更好”。

## 1. 三同：可比性的前提

- **板身份**：记录工程/文档 UUID + 板文件或快照哈希 + 时间；换板、换布局、换层叠后旧对比立即作废。
- **规则**：记录原生规则（clearance / 线宽 / 过孔 / 网络类）与**外部路由器实际收到的规则**；两者不同时并列两套数字，交付按原生口径验收。
- **验证口径与工具版本**：换验证器或解析器后必须重算，不能把旧报告里的数字搬进新表。
- 每条结果写清来源文件与生成时间；缺一项即 `NOT RUN`。

## 2. DSN 保真三查

外部 Freerouting 只在 `--router` / `FREEROUTING_CMD` 时使用（见 [PCB 布线策略](pcb-routing-strategy.md) §3.3）；导出后先核对 DSN 内容，再交给外部路由器。

### 2.1 pin 名唯一

- 同一封装内焊盘号允许重复（热焊盘/屏蔽盘阵列），但 pin 名必须唯一（如 `41`、`41_2`…）。
- 检查：导出后看同一 image 内 `(pin …)` 是否重复。重复会让外部路由器静默丢 pin，某些网络永远布不上。
- 现象记录（2026-10-29 离线实验场，仅说明机制）：某 241 盘板旧导出只连 182/241；修正唯一命名后同板 226/241。

### 2.2 焊盘层语义

- 通孔盘（所有铜层）与 SMD 盘（单层）必须在 DSN 里分开发射：THT 盘每层都有 padstack，SMD 盘只在自身铜层。
- 把 SMD 盘写成通孔，外部路由器无需过孔即可换层 → **假的 0 过孔 + 高连通**：这是表示失真，不是质量优点。
- 检查：抽查含底层 SMD 的板，SMD pin 的 padstack 只能有 1 个层 shape。
- 盘形按真实形状导出（圆/胶囊/矩形）；`rect`/`circle` 强制模式只用于受控对照实验，不是保真默认。

### 2.3 规则传达

- DSN 至少要表达默认线宽/间距与 pad-track 间距。只写一个默认 clearance 时，外部路由器按更松的规则布线，之后用原生规则验收必然出现一批“违例”。
- EDA 侧导出语义要分清：`pcb export-dsn` 默认注入禁布区、只有 `--raw` 是裸导出；`getDsnFile` 会丢禁布区。两种都要先核对 DSN 内容。
- 受控实验里可把 DSN 写成与原生同规则（net class clearance 取 `max(track-track, pad-track)`、真实盘形），使“验证默认口径 == 外部路由器收到的口径”，再比较布线质量。

## 3. “0 过孔”判读

- **全通孔板**：0 过孔合理（本来不需要换层）。
- **含 SMD 盘**：0 过孔几乎必然是 DSN pad 层失真，先修数据再比较。
- 过孔数量不能单独当优点：它服从回流、屏蔽、散热与制造（RT16、RT30）。
- 记录时写清“这块板是否全 THT”与“via 计数来自哪个口径”。

## 4. 违规的两种口径

- **原生口径**：EDA 规则 + 真实盘形 —— 交付验收只用这个。
- **外部等价口径**：外部路由器实际收到的规则 —— 用于解释它的残余违例。
- 两者不同时必须并列写：`最终口径残余 N 条（列 kind）+ 参考口径 M 条`；禁止单边说“外部路由器违规/干净”，也不得把参考口径的 0 说成原生 DRC 通过。
- 残余违例要归因：**表示层**（盘形/旋转近似、oval 归一化）还是**真实几何**（线压盘、过孔压盘）；归因不清就写 `unknown` 或 `NOT RUN`。

## 5. 采纳顺序（不要颠倒）

1. **连通**：关键网逐条 `pcb net-path` 有证据；铺铜/平面承担的网络另用 `pour-list` 与 `dump` 证明，不用 `net-path` 冒充。
2. **违规**：`pcb drc --json` 读完整结果，并用 `python scripts/pcb_evidence.py drc-summary <drc.json>` 汇总；`pcb check` 看 `dangling-end`、线宽突变、禁铜等。
3. **质量**：过孔数、总长、折弯 —— 只有在 1、2 都通过后才谈。
4. **时间**：墙钟只记录，不参与“谁更好”。
- 后优化（拆线重布、捷径、共线合并）必须过同一套验证：**先不劣化连通与违规，再谈质量**；优化不能用来绕过 DRC 修复，也不能为了整洁重建无关铜。

## 6. 大板、超时与内存

- 外部路由器有实际规模上限：585 盘 4 层板在单次 300 s 上限下未收敛（6 个 pass、>240 条未连接、无 SES），加大上限到 16 pass 仍不收敛 —— 属“当前 DSN/规模限制”，记 `NOT RUN`，不输出指标、不补 0。
- 小规模 4 层板可正常跑通（46 盘板：46/46 连通、1 条 `edge-clearance`；router 也报同一板边问题 → 判为板边真实问题，而非路由器特性）。
- 日志里的 `total allocated` 是 JVM 累计分配量（GC churn），**不等于驻留内存**；以 peak heap 与进程上限为准。
- 超时后先比对 `track-list`/`via-list` 与 DRC 前后，再决定保留还是按网 `rip-up`；同一批不原样重发（SKILL §5 第 14 条失败预算），改为更小批次或离线补线。

## 7. 记录模板

| 字段 | 要求 |
|---|---|
| 板身份 | 工程/文档 UUID + 板文件或快照哈希 + 时间 |
| 布局与层叠 | 布局快照哈希、层数、内层类型 |
| 规则 | 原生规则 + DSN 实际规则（各自数值） |
| 外部路由器 | 版本、DSN 变体（裸导出/注入禁布区、盘形、间隔口径） |
| 结果 | 连通（pads/nets）、关键网证明、违规（两口径 + kind）、过孔、线长、折弯、日志路径 |
| 缺测 | `NOT RUN` + 原因（超时/未收敛/工具缺能力） |

## 8. 与门禁的关系

- 本页结论只作 G5 布线退出证据的输入；G5 仍按 [阶段门禁](design-gates.md) 判。
- 外部路由器结果只是候选；`PASS_WITH_WAIVER` 必须写明理由、条件与剩余风险，不能当 `PASS`。
- 本页不替代原生 DRC、SI/PI、热、EMC 与制造签核。

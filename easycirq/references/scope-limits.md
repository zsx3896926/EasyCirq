# 这套流程能做什么、不能做什么

> 写这份是因为：报警器那块板走通了，很容易让人以为"什么板都能这样出"。
> 实际上能做与不能做之间的界线很清楚，越界的需求会卡在中途。

## 已经走通过的类型

| 类型 | 例子 | 依据 |
|---|---|---|
| 纯模拟小电路 | 温度报警器（分压 + 比较器 + 三极管驱动蜂鸣器） | 2026-10-31 从零到 12 层 Gerber，全程走通 |
| 极简数字/指示电路 | 一颗 LED + 一颗限流电阻 | 2026-10-31 首次走通（2 器件 / 4 连接） |
| 需要器件选型的 | 从立创库选 NTC / LM393 / 蜂鸣器 | `lib search` + 按 C 号确认存在 |

这几类的共同点：**器件少（<15）、单页原理图、无高速、无射频、无 MCU 固件**。

## 需要额外条件的类型

| 类型 | 缺什么才能做 |
|---|---|
| 含 MCU 的板 | 引脚计划要真实填 `bank` / `reset_state` / `boot_sample` / `strap`（`pin_plan_check` 会要求），**而且固件不在本流程范围内** |
| 电源板（开关电源） | 环路稳定性、磁件选型、热设计——门禁一项都不查这些 |
| 高速/射频 | 阻抗、叠层、长度匹配——`pcb autoroute` 不保证信号完整性 |
| 多页大工程 | 图板一致检查能覆盖，但布局自动化在 >20 器件时未验证 |
| 需要 EMC/安规 | 完全没有对应检查 |

## 明确做不到的

| 做不到 | 为什么 |
|---|---|
| 证明电路功能正确 | 17 项检查都是"连接/结构/供电/一致性"，没有一项验证电气行为。这块板的两个致命缺陷都是人读电路发现的 |
| 保证布局美观 | 会给出 0 违规的 DRC，但 `OBJECTOUTSIDESHEET` 这类排版 warn 仍会出现 |
| 承诺量产可用 | 没有做热、EMC、寿命、批次一致性的任何验证 |
| 替代 EasyEDA | 不做渲染器，不接管 GUI 操作（导入插件、点界面仍要人） |
| 下单 | 需要客户的账号与支付 |

## 一句话

**这套流程把「从想法到可下单的制造文件」这条路铺平了，并保证路上每一关都有证据。**

**但它不保证这块板是对的。** 对错要靠人读电路、靠实物实测。

越界的需求不会静默通过——门禁会停在缺证据（BLOCKED），
但**它不会告诉你"这个设计思路根本不行"**。那句话只能由人说。

## 给下一个用这套流程的人

1. 先看要做的板属于上面哪一类；
2. 属第一类 → 按 `SKILL.md` 的流程走，能到 Gerber；
3. 属第二类 → 先解决"缺什么"，别先画图；
4. 属第三类 → 这套流程只能帮你做前半段（画图、出文件），验证要另找手段；
5. 任何时候：**门禁绿不等于板子对**。

## 含 MCU 的板：实测「额外条件」到底是什么（2026-11-01）

写了「需要额外条件」之后，用一个最小 MCU 引脚计划实测了流程实际会要求什么。

### 第一次：只填最少字段 → 被要求补 8 项

```
MISSING_FIELD 1 个引脚未声明 voltage_domain
MISSING_FIELD 1 个引脚未声明 bank
MISSING_FIELD 1 个引脚未声明 reset_state
MISSING_FIELD 1 个引脚未声明 boot_sample
MISSING_FIELD 1 个引脚未声明 strap
MISSING_FIELD 1 个引脚未声明 debug
MISSING_FIELD 1 个引脚未声明 analog_used
MISSING_FIELD 1 个引脚未声明 package_bonded
```

对比：纯模拟电路（`resources: []`）只要求 `voltage_domain` 一项——其余七项是
**可配置数字引脚**才有的概念。

### 第二次：补齐八项 → 只差一项

```
UNKNOWN_BANK_VOLTAGES  mcu.bank_voltages 为空，无法核对 bank 电压一致性
```

### 第三次：填上 `bank_voltages: {"GPIOA": "3v3"}` → 通过

```
status: passed | findings: 0
```

### 结论

**「含 MCU 需要额外条件」不是死路，是可满足的**——只要如实填写九个字段：

| 字段 | 含义 | 不能瞎填的理由 |
|---|---|---|
| `voltage_domain` | 引脚电压域 | 与 bank 电压不一致会报 `BANK_VOLTAGE_MISMATCH` |
| `bank` | GPIO 分组 | 用于电压一致性核对 |
| `reset_state` | 复位后的状态 | 影响上电瞬间的行为 |
| `boot_sample` | 启动时是否采样 | 影响 strapping 判断 |
| `strap` | 是否启动配置脚 | 填错会导致配置错 |
| `debug` | 是否调试脚 | 被复用时不能再作普通 IO |
| `analog_used` | 是否作模拟输入 | 与 direction=output 同时为真会报 `ADC_AS_OUTPUT` |
| `package_bonded` | 封装内是否真的引出 | 未引出的脚接不出来 |
| `mcu.bank_voltages` | 每个 bank 的电压 | 用于交叉核对 |

**这不是形式主义**：`analog_used` 与 `direction` 冲突会被单独报出来，
`bank_voltages` 与 `voltage_domain` 不一致也会被报出来。填假的会自相矛盾。

### 仍然不在本流程内的部分

引脚计划通过只说明**引脚分配自洽**。MCU 板还要有：

- 固件（本流程不涉及）
- 时钟、复位、启动配置的实际电路
- 烧录与调试接口

所以含 MCU 的板，本流程能做到「原理图 + PCB + 制造文件」，
**做不到「算得上能用的产品」**。

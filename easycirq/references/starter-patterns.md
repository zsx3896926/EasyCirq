# 起步方案：可查证的骨架，不是可直接生产的模板

根据用户用途挑最近的骨架，再加载模块卡、领域细节与原厂参考。不要替用户改成练手板；不预设芯片、C号、层数、尺寸或阻容值。下面均为任务组织模板，未经过本Skill真实画板和实物验收。

| 用户目标 | 最小功能链 | 第一轮要验证的风险 | 落地与验收 |
|---|---|---|---|
| USB小灯/指示器 | USB角色/供电→保护/电源→控制器或适用模拟控制→限流/LED | USB-C正反插与C到C供电、LED额定、实际下载协议 | 插电可靠、亮度/模式符合目标；不是必须加MCU |
| 手机看温湿度 | 电源→无线模组→传感器→本地页面或远程服务 | 模组发热影响读数、传感器气路、手机查看场景与配网 | 装壳后测量、连接恢复、数据新鲜度和多设备辨识 |
| 自定义MCU开发板 | 实际电源域/启动/复位/时钟→调试→所需接口 | 特殊供电脚、库映射、引脚与固件配置 | 下载/救援、每个必要接口和关键上电状态，不只亮灯 |
| 电池供电/充电电源 | 电芯→保护/电源路径→适用升降压→负载；充电如适用 | 化学体系/电压全范围、充电终止、热、反灌、轻载关断 | 全电压/负载与充电状态、首板温升与适用续航测量 |
| 低压远程开关 | 输入保护→逻辑电源→控制器→适用驱动/钳位→负载 | 真实铭牌、启动/堵转/感性释放、复位时误动作 | 实际负载开关、掉电/复位/断网行为及故障保护 |
| USB小键盘/控制器 | 数据接口/供电→USB能力与匹配固件→按键/编码器 | 裸芯片还是模组、时钟/存储、矩阵鬼键（无二极管矩阵三键同按会出幽灵键，见 [L6](common-hardware/l-hmi.md#l6-机械按键)）、ESD与电平 | 真实电脑枚举、组合按键、插拔/睡眠恢复 |
| RS485采集节点 | 现场电源→保护/转换→主控/采集→收发器/端接→总线 | A/B定义、端接/偏置位置、共模、线缆与隔离 | 多节点/实际线长、地址配置、异常帧/离线和恢复 |
| 双路直流电机小车 | 电池/母线→保护/驱动→电机；控制/传感另按需求 | 持续/堵转/回生、驱动额定、逻辑跌落、关断默认态 | 先安全空载/受控负载，再真实启动/刹车/温升 |

## 从骨架推进的方法

先推荐一条合适路线并说明为什么；只有存在实质差异时再比较原型验证、直接定制或分两步，不强迫新手在两个近似方案间做技术选择。数量、费用和等待时间取实际商品/订单条件，不填固定“几天”“多少钱”。

原型与自制板若采用不同芯片/模块/引脚，明确迁移差异，不把开发板跑通当定制板已验证。决定原型验证的风险边界：例如先验证通知可达，不代表电池续航、土壤检测或密封已验证。

引脚/接口/结构稳定后并行准备程序、测试和使用说明；改动后按项目关联记录复验。上面任一例子都不授予实际下单、烧录、账户或硬件访问能力，沿用用户授权和当前执行通道。

需要更完整的项目包时见 [完整项目样本](projects/README.md)；每个项目标明完成级别（资料分析/离线规划/实际 EDA/制造/样机/功能实测），不能把离线规划当成已验证实物。
